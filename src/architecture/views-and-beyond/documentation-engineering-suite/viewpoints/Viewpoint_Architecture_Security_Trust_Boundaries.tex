\DocProvenance
\section{Viewpoint purpose and applicability}
This is a reusable viewpoint specification, not a diagram or description of any specific system. Primary concerns: identity, data classification, least privilege and cross-zone flow. Principal stakeholders: security engineers, auditors, platform leads.

\section{Model kinds and relation vocabulary}
principals, resources, data classes, trust zones, authorized flow

\section{Conventions and notation}
data-flow overlay, permission register, policy links; assign identifiers to all significant elements and disclose legend, scope, environment and exclusions.

\section{Correspondence rules}
\begin{itemize}
\item each sensitive flow has principal, trust crossing, authorization control and verifiable policy
\item Cross-view references use stable IDs and never infer equality from similar names.
\item Stakeholder concerns and quality scenarios must link to this viewpoint when used.
\end{itemize}
\section{Analysis and verification}
\begin{itemize}
\item Validate complete definition of relation semantics and correct element typing.
\item Use reviewer questions from the scorecards appropriate to this viewpoint.
\item Compare every critical claim to source-controlled artifacts and/or runtime evidence; mark confidence and timestamps.
\end{itemize}
\section{Known limitations and failure modes}
invented security guarantees; undocumented administrative plane
