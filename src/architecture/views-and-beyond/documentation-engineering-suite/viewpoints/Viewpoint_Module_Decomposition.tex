\DocProvenance
\section{Viewpoint purpose and applicability}
This is a reusable viewpoint specification, not a diagram or description of any specific system. Primary concerns: implementation units, responsibilities, and containment. Principal stakeholders: architects, maintainers, team leads.

\section{Model kinds and relation vocabulary}
decomposition nodes, is-part-of edges and scoped responsibility descriptions

\section{Conventions and notation}
tree/graph with explicitly marked shared ownership; assign identifiers to all significant elements and disclose legend, scope, environment and exclusions.

\section{Correspondence rules}
\begin{itemize}
\item every module has a unique stable identifier, purpose and an explicit parent or root
\item Cross-view references use stable IDs and never infer equality from similar names.
\item Stakeholder concerns and quality scenarios must link to this viewpoint when used.
\end{itemize}
\section{Analysis and verification}
\begin{itemize}
\item Validate complete definition of relation semantics and correct element typing.
\item Use reviewer questions from the scorecards appropriate to this viewpoint.
\item Compare every critical claim to source-controlled artifacts and/or runtime evidence; mark confidence and timestamps.
\end{itemize}
\section{Known limitations and failure modes}
ambiguous module ownership; falsely implying runtime communication
