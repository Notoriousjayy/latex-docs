\DocProvenance
\section{Viewpoint purpose and applicability}
This is a reusable viewpoint specification, not a diagram or description of any specific system. Primary concerns: mapping software runtime elements onto execution infrastructure. Principal stakeholders: operators, platform engineers, security and finance.

\section{Model kinds and relation vocabulary}
software runtime IDs, account/network/compute/data resources, deployed-on relations

\section{Conventions and notation}
deployment topology, zone/account placement and mapping table; assign identifiers to all significant elements and disclose legend, scope, environment and exclusions.

\section{Correspondence rules}
\begin{itemize}
\item each runtime element is mapped to an environment/location with evidence
\item Cross-view references use stable IDs and never infer equality from similar names.
\item Stakeholder concerns and quality scenarios must link to this viewpoint when used.
\end{itemize}
\section{Analysis and verification}
\begin{itemize}
\item Validate complete definition of relation semantics and correct element typing.
\item Use reviewer questions from the scorecards appropriate to this viewpoint.
\item Compare every critical claim to source-controlled artifacts and/or runtime evidence; mark confidence and timestamps.
\end{itemize}
\section{Known limitations and failure modes}
mixing source modules with deployed instances; inaccurate tenancy
