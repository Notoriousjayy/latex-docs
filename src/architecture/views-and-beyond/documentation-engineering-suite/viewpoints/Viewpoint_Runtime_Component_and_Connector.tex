\DocProvenance
\section{Viewpoint purpose and applicability}
This is a reusable viewpoint specification, not a diagram or description of any specific system. Primary concerns: execution units, connectors, interfaces and failure propagation. Principal stakeholders: developers, SREs, security analysts.

\section{Model kinds and relation vocabulary}
component instances, ports, connectors, protocol and delivery semantics

\section{Conventions and notation}
runtime diagram, connector register and traces; assign identifiers to all significant elements and disclose legend, scope, environment and exclusions.

\section{Correspondence rules}
\begin{itemize}
\item every critical connector has protocol, authentication, retry, timeout, and observability expectations
\item Cross-view references use stable IDs and never infer equality from similar names.
\item Stakeholder concerns and quality scenarios must link to this viewpoint when used.
\end{itemize}
\section{Analysis and verification}
\begin{itemize}
\item Validate complete definition of relation semantics and correct element typing.
\item Use reviewer questions from the scorecards appropriate to this viewpoint.
\item Compare every critical claim to source-controlled artifacts and/or runtime evidence; mark confidence and timestamps.
\end{itemize}
\section{Known limitations and failure modes}
arrows without semantics; missing failure path; no external dependencies
