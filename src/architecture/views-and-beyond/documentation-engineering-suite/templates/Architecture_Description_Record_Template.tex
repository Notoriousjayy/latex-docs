\section{When to use this artifact}
Use this form to document one controlled unit of architectural evidence. The template contains instructional prompts. The companion blank is deliberately unfilled and suitable for printing or handwritten completion.

\section{Identity fields}
\small
\begin{tabularx}{\linewidth}{@{}YYYY@{}}
\toprule
\textbf{ID} & \textbf{Revision} & \textbf{Status} & \textbf{Owner} \\
\midrule
Example: ARCH-001 & 0.1 & Draft & Architecture lead \\
\bottomrule
\end{tabularx}
\normalsize
\section{Release history and change control}
Record ID, revision, status, responsible architect, current approved baseline, and review/approval authority.

\BlankLines{2}
\section{Purpose and readership}
Define which stakeholder questions this architecture description supports and what it intentionally excludes.

\BlankLines{2}
\section{System overview and context}
Explain system purpose, key actors, upstream/downstream dependencies, business and environmental constraints.

\BlankLines{2}
\section{Architecture drivers and significant requirements}
List requirement IDs, ranked quality attributes, assumptions, and major risks.

\BlankLines{2}
\section{Viewpoint and view registry}
List for each view the viewpoint ID, owner, intended stakeholders, scope, model types, and artifact links.

\BlankLines{2}
\section{Module structure}
Reference decomposition/uses/layered views and document selected change-impact paths.

\BlankLines{2}
\section{Runtime structure}
Reference C\&C views with connectors, protocols, errors, interfaces and selected traces.

\BlankLines{2}
\section{Allocation structure}
Reference runtime mappings to environments, deployment and ownership evidence.

\BlankLines{2}
\section{Cross-view correspondence}
Define mapping types and link each critical module, runtime element and deployment node.

\BlankLines{2}
\section{Rationale and decisions}
Link ADRs, decisions that affect several views, alternatives and accepted risks.

\BlankLines{2}
\section{Quality verification}
Link quality scenario IDs to architecture claims and independent verification evidence.

\BlankLines{2}
\section{Directory, glossary and release status}
Add searchable element identifiers, acronyms, historical versions, open findings and revision approvals.

\BlankLines{2}
\section{Template completion checklist}
\begin{itemize}
\item Identifiers are stable and references resolve.
\item Every materially important claim has a source, reviewer, or explicit assumption.
\item No uncontrolled secrets, internal credentials, or sensitive data are published.
\item Status and decision authority are recorded.
\end{itemize}
