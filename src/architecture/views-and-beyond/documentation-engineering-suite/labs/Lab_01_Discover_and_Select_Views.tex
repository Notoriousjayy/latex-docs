\ArchTitle{Laboratory 01: Select views from architecture questions}{Hands-on architecture engineering exercise with evidence-based grading}{Practical Laboratory}{ARCH-LAB-01}
\DocProvenance
\section{Engineering scenario}
Use a fictional multi-service order platform with frontend, API, message consumer, identity provider, relational database and external billing endpoint.

\section{Prerequisites}
Complete the relevant study guides and ensure you can distinguish module, component-and-connector, and allocation representations. Use a fictional environment or a sanitized, authorized system; never place secrets or sensitive topology into submitted artifacts.

\section{Procedure}
\begin{enumerate}
\item Identify at least six stakeholder roles and ten concrete questions.
\item Create candidate module, C\&C and allocation views; rank by risk and stakeholder utility.
\item Justify one view combination and one decision to keep views separate.
\item Declare a glossary of relations and a release order.
\end{enumerate}
\section{Deliverables}
\begin{itemize}
\item Stakeholder concern register
\item View selection matrix
\item Viewpoint selection rationale
\end{itemize}

\section{Reflection and critique}
\begin{itemize}
\item What stakeholder question was hardest to answer from the submitted architecture?
\item Which model assumption was most uncertain and how can it be verified?
\item What would need to change in the documentation after a significant runtime revision?
\end{itemize}
