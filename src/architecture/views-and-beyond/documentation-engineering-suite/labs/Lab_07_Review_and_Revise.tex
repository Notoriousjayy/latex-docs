\ArchTitle{Laboratory 07: Conduct a fitness-for-purpose documentation review}{Hands-on architecture engineering exercise with evidence-based grading}{Practical Laboratory}{ARCH-LAB-07}
\DocProvenance
\section{Engineering scenario}
A second team must perform a cloud deployment change without consulting the original architecture author.

\section{Prerequisites}
Complete the relevant study guides and ensure you can distinguish module, component-and-connector, and allocation representations. Use a fictional environment or a sanitized, authorized system; never place secrets or sensitive topology into submitted artifacts.

\section{Procedure}
\begin{enumerate}
\item Define review purpose and freeze artifact revisions.
\item Write ten purpose-specific review questions for developers, security and operations.
\item Have one reviewer attempt a change impact analysis using only the package.
\item Triage, assign, fix or accept findings and publish revision notes.
\end{enumerate}
\section{Deliverables}
\begin{itemize}
\item Review record
\item Finding workbook and scorecard
\item Revised documentation package
\end{itemize}
\section{Acceptance rubric}

\normalsize
\section{Reflection and critique}
\begin{itemize}
\item What stakeholder question was hardest to answer from the submitted architecture?
\item Which model assumption was most uncertain and how can it be verified?
\item What would need to change in the documentation after a significant runtime revision?
\end{itemize}
