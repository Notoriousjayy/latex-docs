\section{Conceptual focus}
Decomposition expresses is-part-of whereas uses is a dependency relation; avoid treating them as synonymous.

\section{Reading map}
Book location: Module Styles. Principal topics: decomposition, uses, generalization, layering, aspects, data model. Read the chapter discussion, then its summary checklist and selected discussion questions. Record terms precisely before adapting them to an implementation.

\section{Learning objectives}
\begin{itemize}
\item Explain decomposition, uses, generalization, layering, aspects, data model in terms of a stakeholder question.
\item Detect cycles and forbidden layer crossings; distinguish composition from use; record rules for inheritance.
\item Separate book-supported architectural concepts from optional implementation techniques such as Terraform, OpenAPI, and CI-generated evidence.
\end{itemize}
\section{Engineering interpretation}
Detect cycles and forbidden layer crossings; distinguish composition from use; record rules for inheritance.

\section{Worked laboratory assignment}
Create a dependency structure matrix and propose remediation for cyclic uses relations.

\section{Evidence to submit}
Uses matrix + layering rule

\section{Review prompts}
\begin{itemize}
\item Why does a layered diagram not prove absence of forbidden dependencies?
\item What relation types or behavior are intentionally outside the scope of this view?
\item Which system change would invalidate your claims, and how would you detect it?
\end{itemize}
