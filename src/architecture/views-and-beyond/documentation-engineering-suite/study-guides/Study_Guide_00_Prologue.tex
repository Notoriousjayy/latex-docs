\section{Conceptual focus}
The starting concern is not which diagram to draw but which decisions and users the document must support.

\section{Reading map}
Book location: Prologue. Principal topics: architecture, quality attributes, documentation purposes, seven documentation rules. Read the chapter discussion, then its summary checklist and selected discussion questions. Record terms precisely before adapting them to an implementation.

\section{Learning objectives}
\begin{itemize}
\item Explain architecture, quality attributes, documentation purposes, seven documentation rules in terms of a stakeholder question.
\item Identify readers and usage scenarios; distinguish architecture from implementation detail; define notation in a legend.
\item Separate book-supported architectural concepts from optional implementation techniques such as Terraform, OpenAPI, and CI-generated evidence.
\end{itemize}
\section{Engineering interpretation}
Identify readers and usage scenarios; distinguish architecture from implementation detail; define notation in a legend.

\section{Worked laboratory assignment}
Create a one-page architecture documentation charter for an existing service.

\section{Evidence to submit}
Charter + stakeholder purpose matrix

\section{Review prompts}
\begin{itemize}
\item How do architectural structure and quality scenarios constrain each other?
\item What relation types or behavior are intentionally outside the scope of this view?
\item Which system change would invalidate your claims, and how would you detect it?
\end{itemize}
