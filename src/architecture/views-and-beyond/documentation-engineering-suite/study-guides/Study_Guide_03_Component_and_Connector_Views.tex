\section{Conceptual focus}
Runtime interaction paths have their own structure, and connectors may need explicit protocol and failure semantics.

\section{Reading map}
Book location: Component-and-Connector Views. Principal topics: runtime elements, ports, connectors, instances, properties. Read the chapter discussion, then its summary checklist and selected discussion questions. Record terms precisely before adapting them to an implementation.

\section{Learning objectives}
\begin{itemize}
\item Explain runtime elements, ports, connectors, instances, properties in terms of a stakeholder question.
\item Model components as runtime execution units; specify connector type, semantics, direction and environmental assumptions.
\item Separate book-supported architectural concepts from optional implementation techniques such as Terraform, OpenAPI, and CI-generated evidence.
\end{itemize}
\section{Engineering interpretation}
Model components as runtime execution units; specify connector type, semantics, direction and environmental assumptions.

\section{Worked laboratory assignment}
Trace one successful and one failed request across API, worker, and datastore.

\section{Evidence to submit}
C\&C view + connector catalog

\section{Review prompts}
\begin{itemize}
\item How does a runtime element differ from the source module that implements it?
\item What relation types or behavior are intentionally outside the scope of this view?
\item Which system change would invalidate your claims, and how would you detect it?
\end{itemize}
