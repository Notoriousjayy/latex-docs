\section{Conceptual focus}
A view requires supporting explanation; combining views is useful only if relations remain unambiguous.

\section{Reading map}
Book location: Beyond the Basics. Principal topics: refinement, context, variability, decision rationale, combining views. Read the chapter discussion, then its summary checklist and selected discussion questions. Record terms precisely before adapting them to an implementation.

\section{Learning objectives}
\begin{itemize}
\item Explain refinement, context, variability, decision rationale, combining views in terms of a stakeholder question.
\item Document scope and context, variation constraints, alternative choices and correspondence rules.
\item Separate book-supported architectural concepts from optional implementation techniques such as Terraform, OpenAPI, and CI-generated evidence.
\end{itemize}
\section{Engineering interpretation}
Document scope and context, variation constraints, alternative choices and correspondence rules.

\section{Worked laboratory assignment}
Write a decision on queue vs synchronous call, then link to two affected views.

\section{Evidence to submit}
ADR + variability record

\section{Review prompts}
\begin{itemize}
\item When does hybrid notation hide rather than clarify an architectural concern?
\item What relation types or behavior are intentionally outside the scope of this view?
\item Which system change would invalidate your claims, and how would you detect it?
\end{itemize}
