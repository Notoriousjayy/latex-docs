\section{Conceptual focus}
Signatures alone do not sufficiently specify an interface.

\section{Reading map}
Book location: Documenting Software Interfaces. Principal topics: provided and required interfaces, syntax, semantics, error behavior. Read the chapter discussion, then its summary checklist and selected discussion questions. Record terms precisely before adapting them to an implementation.

\section{Learning objectives}
\begin{itemize}
\item Explain provided and required interfaces, syntax, semantics, error behavior in terms of a stakeholder question.
\item Specify inputs, outputs, preconditions, invariants, authorization, errors, compatibility, and version policy.
\item Separate book-supported architectural concepts from optional implementation techniques such as Terraform, OpenAPI, and CI-generated evidence.
\end{itemize}
\section{Engineering interpretation}
Specify inputs, outputs, preconditions, invariants, authorization, errors, compatibility, and version policy.

\section{Worked laboratory assignment}
Write an API contract for a resource read with 200, 401, 403, and 404 scenarios.

\section{Evidence to submit}
Interface contract + consumer tests

\section{Review prompts}
\begin{itemize}
\item Can two systems share a schema yet still be behaviorally incompatible?
\item What relation types or behavior are intentionally outside the scope of this view?
\item Which system change would invalidate your claims, and how would you detect it?
\end{itemize}
