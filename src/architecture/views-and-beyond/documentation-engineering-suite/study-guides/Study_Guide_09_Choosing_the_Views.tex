\section{Conceptual focus}
The minimum useful views are selected by stakeholder purpose, not a universal diagram count.

\section{Reading map}
Book location: Choosing the Views. Principal topics: stakeholder needs, candidate list, combining, prioritization. Read the chapter discussion, then its summary checklist and selected discussion questions. Record terms precisely before adapting them to an implementation.

\section{Learning objectives}
\begin{itemize}
\item Explain stakeholder needs, candidate list, combining, prioritization in terms of a stakeholder question.
\item Map concerns to candidates, combine compatible information, and prioritize depth and release order.
\item Separate book-supported architectural concepts from optional implementation techniques such as Terraform, OpenAPI, and CI-generated evidence.
\end{itemize}
\section{Engineering interpretation}
Map concerns to candidates, combine compatible information, and prioritize depth and release order.

\section{Worked laboratory assignment}
Conduct a view selection workshop for a multi-team platform and justify every selected view.

\section{Evidence to submit}
Stakeholder/view matrix + prioritization

\section{Review prompts}
\begin{itemize}
\item When should two related runtime views remain separate?
\item What relation types or behavior are intentionally outside the scope of this view?
\item Which system change would invalidate your claims, and how would you detect it?
\end{itemize}

\section{Chapter-specific analysis tasks}
\begin{itemize}
\item Identify and define each relevant element and relation before you choose a diagram notation.
\item Produce one counterexample showing how a plausible but incorrect model could mislead a stakeholder.
\item Identify the source and timestamp of at least one fact about the implementation; label inference separately.
\end{itemize}
