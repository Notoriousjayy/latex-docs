\DocStart{PRACTICAL LABORATORY}{Laboratory 09: Architecture package governance and review}{Reading alignment: Chapter 12 and Appendix}
\SourceNote{The lab setting, procedure and acceptance tests are new engineering exercises. They operationalize themes from Brown (2026) but are not extracted exercises.}
\section{Objective and fixture}
Prepare an acceptance-ready architecture documentation package.

Case study: Civic Permit Portal is a deliberately fictional system. It does not represent a production design, verified cloud configuration, security certification or operational deployment.


\section{Prerequisite reading}
Chapter 12 and Appendix. Review the corresponding study guides and relevant viewpoint specification before modeling.


\section{Procedure}
\begin{enumerate}
\item Register concerns, viewpoints, views and ADRs, execute scorecards and source lint, report unresolved blockers and approve/defer.
\item Identify the concern, choose the minimum useful diagram types, and write a one-sentence view purpose.
\item Implement or revise the diagram-as-code source using the repository C4 house style; avoid local style overrides.
\item Run the renderer and inspect the output; compare model relations against the latest available evidence.
\item Invite an independent reviewer and record findings, changes and remaining uncertainty.
\end{enumerate}

\section{Acceptance tests}
\begin{itemize}
\item Correct C4 scope and abstraction level; no unlabeled edges.
\item At least one explicit link to a stakeholder concern and one evidence reference.
\item A peer reviewer can explain the system model from the artifact alone.
\item No unsupported claim of software, deployment, standard or tool conformance.
\end{itemize}

\section{Expected deliverable}
A documented acceptance decision backed by traceable evidence.


\section{Known traps}
\begin{itemize}
\item Treating lint as semantic validation
\item Hiding known unknowns
\end{itemize}
