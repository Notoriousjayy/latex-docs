\textbf{What is a scaling feedback loop?} & A monitoring signal is compared against a policy threshold, and the controller requests additional or reduced capacity. Delay and noisy signals can cause oscillation.\\[3pt]\textcolor{petrol}{\emph{Practice:} Specify cool-down, minimum and maximum settings.}\\[8pt]\midrule
\textbf{What makes load balancing safe?} & Routing must account for target health, sticky state if needed and graceful removal. Even distribution cannot rescue a shared dependency outage.\\[3pt]\textcolor{petrol}{\emph{Practice:} Run a failing-instance routing test.}\\[8pt]\midrule
\textbf{How do SLA and pay-per-use monitors differ?} & SLA monitoring evaluates service quality against commitments; usage monitoring for charging records billable consumption units.\\[3pt]\textcolor{petrol}{\emph{Practice:} Design two distinct dashboards from the same workload.}\\[8pt]\midrule
\textbf{Why do audit monitors matter?} & Accountable operations require tamper-resistant event histories and consistent identity attribution.\\[3pt]\textcolor{petrol}{\emph{Practice:} Reconstruct a change from log events.}\\[8pt]\midrule
\textbf{What are failover and resource clustering?} & A failover system directs work toward an available alternative; clustering coordinates members so the service can tolerate selected disruptions.\\[3pt]\textcolor{petrol}{\emph{Practice:} Model a failed member and restoration sequence.}\\[8pt]\midrule
\textbf{Why is state management critical?} & Coordinated services may need stored state for replay, recovery, consistent sessions or workflow progress.\\[3pt]\textcolor{petrol}{\emph{Practice:} Explain what happens when one worker crashes after a state write.}\\[8pt]\midrule

\section{Synthesis and architecture connections}
Treat each mechanism as a deployable capability, not a complete architecture. Identify the infrastructure prerequisite, management-plane owner, dependent controls and the negative/failure evidence expected from an implementation.
\begin{workbox}[title={Applied deliverable}]
Explain control loops and failure paths under variable load.\\[4pt]Create a one-page architecture or operations artifact with: (1) assumptions, (2) a decision and alternatives, (3) control ownership, (4) observable acceptance criteria, and (5) a failed-case test.
\end{workbox}
