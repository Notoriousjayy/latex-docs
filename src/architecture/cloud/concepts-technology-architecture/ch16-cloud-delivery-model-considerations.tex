\textbf{How does the provider assess IaaS?} & An IaaS offering must supply capacity, virtualization, monitoring, availability and secure access as an operated service, not only installed servers.\\[3pt]\textcolor{petrol}{\emph{Practice:} Define provider acceptance evidence for an instance offering.}\\[8pt]\midrule
\textbf{What is different for PaaS?} & Platform offerings add application execution and deployment responsibilities; runtime interfaces, scaling and patch boundaries require clarity.\\[3pt]\textcolor{petrol}{\emph{Practice:} Create a runtime lifecycle responsibility chart.}\\[8pt]\midrule
\textbf{What changes for SaaS?} & A SaaS consumer primarily configures and uses an application while the provider maintains more of its stack; identity, data and contractual obligations still remain shared.\\[3pt]\textcolor{petrol}{\emph{Practice:} Specify offboarding and data export tests.}\\[8pt]\midrule
\textbf{How do consumer responsibilities vary?} & Consumers must establish governance and policy for whichever resource layers they control; the chosen service model changes tasks but never removes accountability for data usage.\\[3pt]\textcolor{petrol}{\emph{Practice:} Build a model-by-model control owner table.}\\[8pt]\midrule
\textbf{What makes procurement technical?} & Availability, portability, authentication integration and auditability should be contractually testable.\\[3pt]\textcolor{petrol}{\emph{Practice:} Write a service acceptance checklist with evidence links.}\\[8pt]\midrule
\end{longtable}\normalsize
\section{Synthesis and architecture connections}
Connect architecture selection to operating commitments. Attribute each obligation to a consumer or provider, describe its measurement source and produce traceable evidence for risk, cost and service quality.
\begin{workbox}[title={Applied deliverable}]
Create a delivery-model responsibility and acceptance checklist.\\[4pt]Create a one-page architecture or operations artifact with: (1) assumptions, (2) a decision and alternatives, (3) control ownership, (4) observable acceptance criteria, and (5) a failed-case test.
\end{workbox}
