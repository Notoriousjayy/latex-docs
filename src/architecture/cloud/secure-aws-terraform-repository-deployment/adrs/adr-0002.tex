{\LARGE\bfseries\color{Navy} ADR-0002: Multi-account workload and environment isolation }\\[4mm]
\textbf{Status: Proposed} \quad | \quad 29 October 2026 \quad | \quad Owner: Architecture Governance
\end{center}
\hrule
\section*{Context}
A repository or AWS IAM policy alone cannot fully separate service quotas, incident response, administrative control, and data sensitivity. AWS account separation provides a durable workload boundary.
\section*{Decision}
Independent production AWS accounts and account-scoped workload access.
\begin{enumerate}[leftmargin=*]
\item Production and nonproduction must be in distinct AWS accounts; isolate high-risk workloads further based on sensitivity.
\item Use AWS Organizations, OUs, SCP guardrails, centralized audit and a governed account-vending function.
\item Each application/environment has its own deployment role and explicitly mapped state.
\end{enumerate}
\section*{Alternatives considered}
\begin{itemize}[leftmargin=*]
\item One AWS account for all environments: rejected for baseline production.
\item Separate VPCs and IAM roles but one account: possible as an exception for lower-risk nonproduction, not an equivalent isolation guarantee.
\end{itemize}
\section*{Consequences}
\begin{itemize}[leftmargin=*]
\item Increases account administration, billing governance and network topology complexity.
\item Supports stronger organizational guardrails and incident containment.
\end{itemize}
\section*{Verification and review triggers}
\begin{enumerate}[leftmargin=*]
\item Verify account IDs and OU placement before apply.
\item Demonstrate developer role cannot modify prod workloads or prod state.
\end{enumerate}
\section*{Decision review}
Review at each quarterly architecture governance checkpoint or whenever organization, cloud, Terraform or GitHub platform constraints materially change. Exceptions require recorded owner, approval and expiration.
