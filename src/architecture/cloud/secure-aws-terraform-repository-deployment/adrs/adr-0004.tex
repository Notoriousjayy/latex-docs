{\LARGE\bfseries\color{Navy} ADR-0004: GitHub Actions OIDC authorization }\\[4mm]
\textbf{Status: Proposed} \quad | \quad 29 October 2026 \quad | \quad Owner: Architecture Governance
\end{center}
\hrule
\section*{Context}
Long-lived secrets and repo-wildcard trust policies let unrelated or lower-trust workflows gain production permissions. GitHub subject formats can differ depending on environment and immutable ID adoption.
\section*{Decision}
Exact GitHub OIDC subject and audience trust, with GitHub environment restrictions.
\begin{enumerate}[leftmargin=*]
\item Use exact audience and subject StringEquals conditions for each deployment IAM role.
\item Inspect the actual OIDC subject before provisioning trust; support immutable owner/repository IDs where emitted.
\item When a job uses a GitHub environment, restrict deployment branches and approval authority in that environment; do not assume its subject includes the branch.
\item Production accounts and roles must have distinct trust subjects and least-privilege permissions.
\end{enumerate}
\section*{Alternatives considered}
\begin{itemize}[leftmargin=*]
\item Static AWS access keys in repository secrets: rejected.
\item Wildcards across repository or environment OIDC subjects: rejected.
\item Using IAM Roles Anywhere for GitHub-hosted workflow identity: rejected for this use case.
\end{itemize}
\section*{Consequences}
\begin{itemize}[leftmargin=*]
\item No stored AWS deploy credentials; strong provenance in STS identity.
\item Misconfigured or moved GitHub environments can prevent assumption, intentionally failing closed.
\end{itemize}
\section*{Verification and review triggers}
\begin{enumerate}[leftmargin=*]
\item Confirm the real token and trust policy match.
\item Negative tests for wrong repository, environment, audience and dev-to-prod role assumption.
\end{enumerate}
\section*{Decision review}
Review at each quarterly architecture governance checkpoint or whenever organization, cloud, Terraform or GitHub platform constraints materially change. Exceptions require recorded owner, approval and expiration.
