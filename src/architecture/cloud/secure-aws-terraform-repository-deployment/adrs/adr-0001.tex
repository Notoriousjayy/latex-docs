\begin{center}
{\LARGE\bfseries\color{Navy} ADR-0001: Application-aligned repository ownership }\\[4mm]
\textbf{Status: Proposed} \quad | \quad 29 October 2026 \quad | \quad Owner: Architecture Governance
\end{center}
\hrule
\section*{Context}
Systems with unrelated application owners, approval groups and deployment lifecycles need clear source-code administration and audit histories. A single repository can provide good code sharing but not always independent GitHub permissions.
\section*{Decision}
Application-aligned repository boundaries with documented monorepo exceptions.
\begin{enumerate}[leftmargin=*]
\item Use a dedicated repository for each independently owned application or cohesive deployable product.
\item Permit a monorepo when the security review demonstrates enforceable path ownership, workflow isolation, release independence, and restricted credentials.
\item Store application-specific Terraform roots in the application repository unless a separation of duties or regulated change-control need warrants a dedicated IaC repository.
\end{enumerate}
\section*{Alternatives considered}
\begin{itemize}[leftmargin=*]
\item One repository for every microservice, irrespective of ownership and deployment: rejected due to operational sprawl.
\item One organization-wide monorepo: rejected as the default because repo-scoped permission and automation boundaries become harder to administer.
\item Split every application IaC repository: reserved for special cases needing distinct access/reviews.
\end{itemize}
\section*{Consequences}
\begin{itemize}[leftmargin=*]
\item Clear default application ownership; simple CI ownership; higher repository count; cross-service dependency management is explicit.
\item Repository isolation alone is insufficient: IAM permissions and state are enforced independently.
\end{itemize}
\section*{Verification and review triggers}
\begin{enumerate}[leftmargin=*]
\item Audit service catalog against repository ownership.
\item Confirm any monorepo exception has path, check, and privilege isolation tests.
\end{enumerate}
\section*{Decision review}
Review at each quarterly architecture governance checkpoint or whenever organization, cloud, Terraform or GitHub platform constraints materially change. Exceptions require recorded owner, approval and expiration.
