{\LARGE\bfseries\color{Navy} ADR-0005: Terraform module provenance and promotion }\\[4mm]
\textbf{Status: Proposed} \quad | \quad 29 October 2026 \quad | \quad Owner: Architecture Governance
\end{center}
\hrule
\section*{Context}
Upstream module changes can silently expand privileges or reduce security defaults. Reusable modules are infrastructure supply-chain artifacts.
\section*{Decision}
Versioned, reviewed infrastructure modules with immutable references.
\begin{enumerate}[leftmargin=*]
\item Modules must document ownership, tests, supported versions, API contracts, release and rollback procedures.
\item Production consumers must pin reviewed immutable module versions or commit refs and commit provider dependency lockfiles.
\item Module changes and required updates must pass policy-as-code checks and controlled promotion.
\end{enumerate}
\section*{Alternatives considered}
\begin{itemize}[leftmargin=*]
\item Following module default branches: rejected.
\item Copy/pasting shared module code into each application: discouraged except justified local specialization.
\item A repository per small module: not mandatory when a shared lifecycle and ownership make a grouped module repository appropriate.
\end{itemize}
\section*{Consequences}
\begin{itemize}[leftmargin=*]
\item Controlled promotion improves reproducibility but creates explicit upgrade work.
\item A centralized module maintenance team must provide compatibility and response SLAs.
\end{itemize}
\section*{Verification and review triggers}
\begin{enumerate}[leftmargin=*]
\item Attempt to update to an unapproved module ref; check must block.
\item Validate released module compatibility using pinned provider versions.
\end{enumerate}
\section*{Decision review}
Review at each quarterly architecture governance checkpoint or whenever organization, cloud, Terraform or GitHub platform constraints materially change. Exceptions require recorded owner, approval and expiration.
