{\LARGE\bfseries ADR-APPSEC-001 Isolate discovery from privileged enforcement}\par
\textbf{Status: PROPOSED (not approved)}\par
\textbf{Decision owner:} To be assigned by an adopting organization.\par
\textbf{Scope:} Enterprise GitHub code scanning companion to architecture discovery.
\section{Context}
Architecture Discovery captures configuration and inferred graph relationships; extending its token privileges would create a confused deputy and amplify exposure.
\section{Alternatives}
\begin{itemize}
\item Single collector/executor with write access: lower integration effort but broad trust boundary.
\item Independent read-only collector plus separately authorized GitHub App: stronger privilege separation.
\item Manual-only reviews: least automation but may preserve queue bottleneck.
\end{itemize}
\section{Proposed decision}
Adopt independent discovery and evaluator boundaries; never expose write-capable credentials to untrusted PR data or general catalog collectors.
\section{Consequences, validation and reversibility}
Additional integration interface and evidence reconciliation are required. Validate collector cannot call write endpoints and executor requires independently approved authorization.
\section{Authorization}
No deployment, API mutation or policy change is authorized by this draft ADR. Acceptance requires named independent security and platform reviewers, environment-specific API verification and controlled pilot evidence.
