{\LARGE\bfseries ADR-APPSEC-002 Start with deterministic offline policy}\par
\textbf{Status: PROPOSED (not approved)}\par
\textbf{Decision owner:} To be assigned by an adopting organization.\par
\textbf{Scope:} Enterprise GitHub code scanning companion to architecture discovery.
\section{Context}
Automated approvals depend on reproducible evaluation, exact exception scopes and denial on incomplete evidence. Arbitrary LLM output or untrusted rules are unsuitable as authorization.
\section{Alternatives}
\begin{itemize}
\item Python typed rule evaluation: transparent, low footprint and testable.
\item OPA/Rego: mature policy framework but deployment and governance overhead.
\item CEL: expressive and constrained but requires audited bindings.
\item LLM-based auto dismissal: non-deterministic and inappropriate as authority.
\end{itemize}
\section{Proposed decision}
Propose a typed, version-pinned offline evaluator initially; allow OPA/CEL reassessment only after acceptance criteria and ADR review.
\section{Consequences, validation and reversibility}
Keep logic small, deterministic and security-reviewed. Measure policy test coverage, reviewer agreement, false approval rate and exception expiry. No write API integration in this phase.
\section{Authorization}
No deployment, API mutation or policy change is authorized by this draft ADR. Acceptance requires named independent security and platform reviewers, environment-specific API verification and controlled pilot evidence.
