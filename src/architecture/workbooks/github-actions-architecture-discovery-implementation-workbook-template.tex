\noindent\textbf{Purpose:} A phase-gated project working instrument for building an organization-scoped GitHub Action and its read-only discovery engine, with explicit owners, checkpoints and acceptance evidence.

\noindent\textbf{Use:} Follow the guided prompts, record evidence locators, and create a separate project-controlled instance.

\noindent\textbf{Source reference:} GitHub Actions Architecture Discovery at Enterprise Scale, technical reference, October 2026.

\tableofcontents
\clearpage
\section{Phase 0 -- scope and control plane}
\Field{Organization, installation and pilot scope}{List authorized targets, exclusions, inventory denominator and intended owners.}
\Field{GitHub App permission assessment}{Record actual endpoint permissions, reviewer and least-privilege sign-off.}
\Field{Data classification and retention}{Document metadata sensitivity, export handling and access boundaries.}
\subsection{Control checklist}
\begin{itemize}
\item $\square$ Authorization boundary documented
\item $\square$ No write permissions or unsafe evaluation
\item $\square$ Baseline coverage denominator identified
\end{itemize}


\section{Phase 1 -- read-only pilot collector}
\Field{Action workflow contract}{Capture workflow\_dispatch input schema, authentication, concurrency and artifact publishing.}
\Field{GitHub API retrieval strategy}{Identify pagination, SHA pinning, selected file paths and conditional requests.}
\Field{Failure, cache and restart behavior}{Record retry rules, checkpoint design, error statuses and idempotency.}
\Field{Pilot sample and expected inventory}{Include diverse repos and an independently inspected baseline.}
\subsection{Control checklist}
\begin{itemize}
\item $\square$ No repository modifications
\item $\square$ Opaque workflow expressions retained
\item $\square$ Pilot output and warnings independently reviewed
\end{itemize}


\section{Phase 2 -- monorepo component discovery}
\Field{Manifest and workspace inputs}{Enumerate Maven, Gradle, npm/pnpm, Python, Go, Rust and container build clues.}
\Field{Glob expansion and component identity}{Document pinned tree resolution, excludes, collisions and durable identities.}
\Field{Job-to-component correlation}{Separate explicit build target evidence from broad path-filter inferences.}
\Field{Negative examples and unresolved candidates}{Note nested checkout, dynamic scripts, library-only packages and denied trees.}
\subsection{Control checklist}
\begin{itemize}
\item $\square$ Monorepos do not equal single applications
\item $\square$ Ambiguities are represented explicitly
\end{itemize}


\section{Phase 3 -- normalized graph and evidence}
\Field{Node and edge schema version}{Enumerate required entities, relationship types, stable IDs and provenance.}
\Field{Evidence class enforcement}{Require E1 observed, E2 inferred, E3 externally verified with promotion evidence.}
\Field{Storage and snapshot plan}{Specify schema migrations, repeatable imports, query model and history.}
\subsection{Control checklist}
\begin{itemize}
\item $\square$ Relationship source path and SHA retained
\item $\square$ Parser and rule versions retained
\item $\square$ No inferred edge silently promoted
\end{itemize}


\section{Phase 4 -- artifacts and environment correlation}
\Field{Publication and package signals}{Document how build output differs from a proven published artifact.}
\Field{Deployment verification sources}{Record registry digests, deployment APIs, IaC and environment evidence.}
\Field{Cross-repository relationship validation}{Specify acceptance checks and provenance for shared workflow calls.}
\subsection{Control checklist}
\begin{itemize}
\item $\square$ Deployment edges require corroboration
\item $\square$ Unverified runtime calls are not asserted as facts
\end{itemize}


\section{Phase 5 -- governance and architecture catalog}
\Field{Catalog audiences and access}{Identify enterprise architects, AppSec, component owners and approvers.}
\Field{Coverage and drift reporting}{Document change detection, timestamp, stale/denied reporting and notifications.}
\Field{Handoff and steady-state operations}{Specify job schedules, service ownership, escalation and risk review.}
\subsection{Control checklist}
\begin{itemize}
\item $\square$ Data classification reflected in outputs
\item $\square$ Evidence and uncertainty visible to readers
\item $\square$ Governance review and ownership recorded
\end{itemize}

\section{Completion and handover}
\Field{Pilot exit criteria}{Record reviewed results, error coverage, deterministic reruns and accuracy.}
\Field{Readiness for portfolio rollout}{Record reviewer, privacy/security decision and staged rollout plan.}
\Field{Operational action items}{Capture blockers, outstanding enrichment and owner follow-ups.}
\section{Record review and sign-off}
\Field{Prepared by, role, and revision}{Provide author, contact, version, and creation date.}
\Field{Reviewed by, date, and scope}{Record who reviewed which evidence and what remains open.}
\Field{Status and next action}{Distinguish unreviewed, draft, reviewed, approved, and superseded; attach approvals separately.}
