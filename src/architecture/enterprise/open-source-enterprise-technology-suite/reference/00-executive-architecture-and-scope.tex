\section{Architecture objectives}
\begin{itemize}
\item Supply a capability-centered reference, not a mandate to deploy every project.
\item Unify decisions on identity, security evidence, IT operations and governance while preserving the original documents.
\item Keep personal finance and customer data separate from sensitive security evidence; integrate only explicitly authorized aggregates.
\item Treat every proposed integration, license and product feature as conditional until tested against an exact release.
\end{itemize}
\section{System context}
The enterprise platform spans six bounded contexts: identity and access; engineering/AppSec; ITAM/ITSM; governance and risk; delivery/business applications; and segregated finance. A lightweight integration layer brokers authenticated changes without becoming an unbounded data lake.\par

\section{Architecture and trust zones}
\begin{itemize}
\item Zone A: public entry and approved browser applications via reverse proxy/VPN; default deny nonessential ports.
\item Zone B: private application tier and integration adapters; mutual service identity, least privilege and audited changes.
\item Zone C: restricted identity and secrets domain; authenticated access to IdP and vault services.
\item Zone D: restricted findings, risk and immutable evidence; separate audit policies and retention.
\item Zone E: isolated finance and personal data; no direct scanner-to-ledger or CRM-to-ledger access.
\item Zone F: backup and recovery domain; distinct keys and documented break-glass access.
\end{itemize}
\section{Decision boundaries}
Use one owner per canonical entity and field; references cross bounded contexts by stable identifiers. Link raw findings to remediation and approved risk decisions but do not copy full vulnerability payloads to every application. The enterprise reporting plane receives aggregates and signed evidence pointers, not raw private bank data.\par
\textbf{Decision / gate.} Architecture approval is conditional on authoritative-record assignment, license qualification, security review and tested restore.\par
\section{End-to-end security outcome}
\begin{enumerate}
\item CI and authorized QA scans produce immutable source observations and provenance.
\item Adapters validate versions, preserve raw evidence and normalize findings.
\item Asset resolver maps known resource aliases to the iTop service and GLPI asset; ambiguous links are quarantined.
\item Owner and risk triage produce a time-bound remediation target and Taiga story with points and sprint only when approved.
\item Eramba records control context, decision and exception expiry; closure requires retest and reviewer evidence.
\item Operational monitoring and periodic restore tests verify the system itself.
\end{enumerate}
