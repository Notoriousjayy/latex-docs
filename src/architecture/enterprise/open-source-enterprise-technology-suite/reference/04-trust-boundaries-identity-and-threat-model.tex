\section{Identity patterns}
\begin{itemize}
\item Use Authentik as a candidate centralized IdP; preserve externally mastered HR/directory identities where present.
\item Test each target app OIDC or SAML provider capability in the exact edition/version; proxy authentication is not a substitute for app authorization.
\item Separate service identities from interactive users; no shared universal administrator; require break-glass inventory.
\item Least-privilege user and service access with quarterly recertification for privileged roles.
\item Design for IdP unavailability: scoped emergency admin access, audited use and prompt credential rotation.
\end{itemize}
\section{Data protection requirements}
\begin{itemize}
\item Classify P0 public metadata, P1 internal operations, P2 sensitive findings and P3 financial/personal/identity secrets.
\item Minimize replicated data and redact P2/P3 in common logs and tickets.
\item Encrypt transport and storage; rotate credentials; evidence-store object integrity verified by SHA-256.
\item Use independent retention schedules for financial, training, security, and customer information.
\item Explicitly forbid consumer finance sync credentials in the CI pipeline.
\end{itemize}
\section{Abuse scenarios to test}
\begin{enumerate}
\item Attacker steals CI token, injects benign-looking finding with malicious external links.
\item Stale asset alias falsely associates vulnerability with protected critical service.
\item GRC approval webhook is replayed to extend a risk exception without signature.
\item Taiga story closes but scanner still detects exposure: status must reopen.
\item Finance reverse proxy incorrectly accepts general staff session: access denied and alerted.
\end{enumerate}
