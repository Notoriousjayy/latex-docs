\section{Recovery architecture}
\begin{itemize}
\item Encrypt at source with separately protected keys and recovery procedure.
\item Follow multi-copy backup design including off-site/offline or immutable copy as appropriate.
\item Define business-approved RPO/RTO per system; example numbers in runbooks are not service commitments.
\item Run restoration in a segregated environment; use sanitized test data when possible.
\item Test authenticated operation after restore, not merely file decompression or database startup.
\item Keep documented dependency order: secrets/identity, storage/db, core apps, adapters, evidence processing and reporting.
\end{itemize}
\section{Failure injections}
\begin{enumerate}
\item Delete a test finding and verify recovery from immutable evidence.
\item Rotate/expire a client credential and confirm monitoring and remediation.
\item Break one GLPI-iTop sync cycle and verify reconciliation alerts.
\item Revoke finance access and verify backups cannot be read via ordinary app credentials.
\item Simulate lost Taiga response and confirm replay does not create a second story.
\end{enumerate}
