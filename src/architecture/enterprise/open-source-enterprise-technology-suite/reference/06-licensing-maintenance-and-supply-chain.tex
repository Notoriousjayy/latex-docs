\section{Release qualification checklist}
\begin{enumerate}
\item Capture official repository URL, commit/release/tag, exact deployment image digest and software BOM.
\item Verify LICENSE/SPDX notices for application, container base, bundled rules, feeds, fonts, plugins and network-service obligations.
\item Review supported release cycle, security policy, CVE history and upgrade path.
\item Validate SSO/API/export functions in target edition, including user count or automation limits.
\item Demonstrate upgrade + rollback, encrypted backup + restore and minimal observability.
\item Record accepted residual risks, decision authority, review date and expiry.
\end{enumerate}
\section{GHAS and proprietary exception}
GitHub Advanced Security is not an open-source scanner. A strict OSS path can use Semgrep OSS plus Gitleaks, ZAP, Trivy and Syft, with functionality evaluated per tool. GHAS may be a commercially approved alternative when organizational GitHub licensing, coverage and workflow justify it; it must remain visibly flagged.\par
\section{Continuous supply-chain evidence}
\begin{itemize}
\item Publish signed/digested deploy artifacts where feasible; retain SBOM in SPDX/CycloneDX and verify supplied formats.
\item Use dependency age and known exploited vulnerability context as enrichment, not unproven exploitability.
\item Review plugin and feed licensing separately: green indicators for application code do not confer rights to proprietary datasets.
\item Set review cadence on new upstream releases, discontinued maintenance and dependency vulnerabilities.
\end{itemize}
