\textbf{Purpose and status.} Operator procedure; adapt scope, access and escalation to the production environment.\par
\textbf{Evidence status:} Proposed / requires local validation.\par
\section{Trigger and prerequisites}
\begin{itemize}
\item Approved person / service request, identity authority, ticket, role owner and data class known.
\item IdP primary and emergency authentication verified; notification contacts documented.
\end{itemize}
\section{Procedure}
\begin{enumerate}
\item Record principal and role in approved identity master; map Authentik to target provider after proof-of-concept.
\item Enforce MFA for privileged groups; use explicit target-app role mappings, not implicit superuser grants.
\item Confirm login allowed to intended role and denied to another role; retain test evidence.
\item On termination, disable external identity and application sessions/tokens; revoke API tokens independently.
\item Verify deprovisioning in each app and reconcile audit logs within agreed response window.
\end{enumerate}
\section{Recovery and rollback}
\begin{itemize}
\item For IdP failure, use vaulted, time-bound break-glass account and document the incident.
\item Rotate or disable break-glass credential after use; investigate unexpected authentications.
\end{itemize}
\section{Evidence and escalation}
\begin{itemize}
\item IdP policy revision, account lifecycle ticket, application permission review and denied access event.
\item Escalate failed revocation to security incident; avoid silent manual overrides.
\end{itemize}
