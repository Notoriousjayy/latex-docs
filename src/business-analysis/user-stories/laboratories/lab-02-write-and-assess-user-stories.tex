\section{Scenario and initial inputs}
The starting backlog contains: "Build request database"; "Users manage everything"; "As a requester I can see status"; and "Implement React grid".

\section{Procedure}
\begin{enumerate}[leftmargin=*,itemsep=3pt]
\item Reclassify technical tasks and identify the missing user goals.
\item Rewrite at least four user-valued stories without prescribing implementation.
\item Score each against INVEST and explain evidence for ratings.
\item Choose one story that is too large and prepare a small measurable acceptance example.
\end{enumerate}
\section{Submission checklist}
\begin{itemize}[leftmargin=*,itemsep=2pt]
\item Four revised stories
\item Four completed INVEST scorecards
\item A prioritized open-question list
\end{itemize}
\section{Verification criteria}
\begin{itemize}[leftmargin=*,itemsep=2pt]
\item Outputs describe user outcomes rather than only technical activity.
\item Evidence is sufficient for another practitioner to reproduce or challenge the work.
\item Security, negative behavior and assumptions are visible when relevant.
\item Explicit tradeoffs and decision rights appear in the results.
\end{itemize}
\begin{tcolorbox}[colback=amberback,colframe=navy,title={Instructor note / expected reasoning},breakable]
An infrastructure item may be legitimate enabling work, but it should not be mislabeled as customer-facing value.

\end{tcolorbox}
\section{Stretch exercise}
Exchange artifacts with another participant. Identify one unverifiable expectation, one dependency hidden by the initial plan, and one incomplete traceability link. Revise the record and document what changed.
