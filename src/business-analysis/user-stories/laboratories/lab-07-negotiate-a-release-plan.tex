\section{Scenario and initial inputs}
Use the backlog from Lab 06. The primary release objective is submit + own-status + reviewer approval. The team has two candidate iterations and observed velocity ranging from 10 to 13 points.

\section{Procedure}
\begin{enumerate}[leftmargin=*,itemsep=3pt]
\item Choose a minimum viable user journey and prioritize it ahead of secondary enhancements.
\item Prepare two release scope scenarios using the observed range.
\item Mark external dependencies and a technical risk reduction action.
\item Specify release acceptance, necessary controls and a review trigger.
\item Show the impact of a newly required five-point feature without falsely treating a forecast as a guarantee.
\end{enumerate}
\section{Submission checklist}
\begin{itemize}[leftmargin=*,itemsep=2pt]
\item A versioned release plan
\item Two scope / capacity scenarios
\item A recorded negotiation and fallback decision
\end{itemize}
\section{Verification criteria}
\begin{itemize}[leftmargin=*,itemsep=2pt]
\item Outputs describe user outcomes rather than only technical activity.
\item Evidence is sufficient for another practitioner to reproduce or challenge the work.
\item Security, negative behavior and assumptions are visible when relevant.
\item Explicit tradeoffs and decision rights appear in the results.
\end{itemize}
\begin{tcolorbox}[colback=amberback,colframe=navy,title={Instructor note / expected reasoning},breakable]
The core scope totals 16 points in the illustrative dataset; a forecast must discuss capacity uncertainty.

\end{tcolorbox}
\section{Stretch exercise}
Exchange artifacts with another participant. Identify one unverifiable expectation, one dependency hidden by the initial plan, and one incomplete traceability link. Revise the record and document what changed.
