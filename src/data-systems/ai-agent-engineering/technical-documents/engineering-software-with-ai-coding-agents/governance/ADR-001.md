# ADR-001: Extend native coding-agent harnesses through narrow adapters

Status: proposed; acceptance requires platform qualification.

Context: Engineering teams need bounded delegation and independently verifiable changes, while the coding platforms already implement inference and tool loops. Reimplementing those loops duplicates vendor capabilities and creates additional security and maintenance obligations.

Decision: keep provider invocation behind an execution port. Enforce task authorization, workspace isolation, egress, verification, approval and release externally. Store evidence by task and candidate digest. Use separate identities for worker, verifier and release. The prototype does not implement the production security boundary.

Alternatives: (1) native agent plus protected CI: simpler and appropriate for small tasks; (2) custom agent loop: greater flexibility but substantial verification and maintenance cost; (3) distributed orchestration: useful for concurrency but introduces durable-state and coordination risks. Prefer the simplest architecture satisfying the control requirements.

Consequences: provider changes require adapter contract testing; trusted verification must not be editable by workers; live deployment requires isolated process trees, protected logs and credential restrictions. Revisit if native capabilities eliminate a documented external requirement.
