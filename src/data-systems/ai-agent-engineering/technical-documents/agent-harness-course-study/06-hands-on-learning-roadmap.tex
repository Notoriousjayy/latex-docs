\section{Learning progression}
\textbf{Phase A: foundations (L01--L04).} Run existing L01/L02 verification, then build orchestration parity and durable checkpoint tests before introducing retrieval or external integration. Required artifacts: normalized traces, schema rejection tests, restart experiment log. Use deterministic fake clocks and model responses. Exit: bounded loop, no unapproved effects, recovery across processes.

\textbf{Phase B: capability and retrieval (L05--L08).} Refactor ports only after behavior is captured by tests. Add context assembly and tool discovery, MCP adapter and scoped GitHub reads. Build a versioned synthetic repository corpus. Midterm: show a traced request, explain all five layers, measure retrieval and prove denied mutation.

\textbf{Phase C: adversarial and multiagent (L09--L12).} Threat-model assets and trust boundaries; add injection fixtures, approval state machine and delegation limits. Design a frozen benchmark before optimization. Demonstrate that classifier false negatives cannot bypass policy. Report all negative cases, not just successful examples.

\textbf{Phase D: operations and capstone (L13--L16).} Add redacted telemetry and resource accounting, container/CI controls, CodeQL evidence investigation and independent review. A learned skill may select an existing read-only capability but cannot widen policy. No real write, alert dismissal or deployment. Capture artifacts for an independent assessment rather than self-certification.

These are proposed supplements to the 16 existing labs, not replacements or completed work. Preserve the existing acceptance criteria. All tests run offline by default; no real GitHub mutation, alert dismissal or AWS deployment. Source: uploaded course snapshot and target curriculum README/roadmap (2026-11-23).

Each lab produces code, tests, diagram, security notes and an evidence.json record with real source SHA, tool versions, sanitized run ID and independent reviewer. A proposed timebox of 10 hours per lab matches the existing Week 01 workload model, but adjust to the syllabus.

\subsection{Suggested acceptance suite}
\begin{longtable}{>{\raggedright\arraybackslash}p{.25\linewidth}>{\raggedright\arraybackslash}p{.66\linewidth}}\toprule
Test & Expected assertion \\\midrule\endhead
Contract & Malformed, oversized and unknown proposal variants deny; no adapter call. \\
Authorization & Wrong actor, cross-scope object and undeclared tool deny; no downstream effect. \\
Approval & Exact validated payload only; denied, expired, modified and consumed approvals cannot execute. \\
Durability & Restart at draft, approval, claim, external success and local commit; no blind retry after unknown result. \\
Memory & Malicious or rejected source never becomes executable instruction; revocation invalidates retrieval and cache. \\
Delegation & Child capability set subset of parent; global budget cannot be exceeded under concurrent calls. \\
Sandbox & Host mount and arbitrary network denied in actual runtime integration tests. \\
Audit & Every effect has linked policy, approval if needed and observed delivery; no secrets in trace. \\
Evaluation & Mandatory evidence present; frozen thresholds pass; independent reviewer records decision. \\
\bottomrule\end{longtable}
