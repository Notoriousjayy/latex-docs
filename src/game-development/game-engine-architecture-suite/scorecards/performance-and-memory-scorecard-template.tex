\section{Purpose and use}
This is the guided version of the form. For each numbered field, use the accompanying prompt to capture evidence. Leave no required criterion unsubstantiated; cite test IDs and measured data rather than subjective claims.

\subsection{Measurement reproducibility}
Guidance: Hardware, build, seed, timings and workload are recorded.

\WritingBox{1.05in}
\subsection{Frame budget}
Guidance: P50, p95 and p99 plus stalls are measured.

\WritingBox{1.05in}
\subsection{Memory peak}
Guidance: Tracked peak and live bytes under loading and gameplay.

\WritingBox{1.05in}
\subsection{Allocation discipline}
Guidance: Per-frame allocation counters and intentional lifetime classes.

\WritingBox{1.05in}
\subsection{Parallel efficiency}
Guidance: Sequential parity, job overhead and scalability curves.

\WritingBox{1.05in}
\subsection{Numerical stability}
Guidance: dt and complexity sweeps expose drift/penetration/overflow.

\WritingBox{1.05in}
\subsection{Release decision}
Guidance: Recorded evidence, owner and unresolved budget failures.

\WritingBox{1.05in}
\section{Scoring and disposition}
Rate each criterion from 0 to 4 (0 absent, 1 planned, 2 partially supported, 3 evidence verified, 4 tested under failure conditions). Mark any critical release blocker independently of total score.
