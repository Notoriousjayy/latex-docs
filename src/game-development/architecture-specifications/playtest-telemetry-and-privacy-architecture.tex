\section{Purpose and provenance}
Minimal, consent-aware, privacy-preserving instrumentation for playtesting decisions.

Book-aligned conceptual chapters: 9, 10, 28, 34. The architecture, contracts, constraints, and diagrams are original engineering proposals, not architectures claimed to be supplied by Schell.


\section{Stakeholder concerns and boundaries}
\begin{itemize}
\item Player: understandable, responsive, accessible experience.
\item Game designer: explicit rule changes and observable consequences.
\item Gameplay engineer: state ownership, testability, maintainability, debugging.
\item QA/research: reliable test evidence and reproducible findings.
\item Security/privacy owner: minimal data collection, abusive-input boundaries, safe operations.
\end{itemize}

\section{Architecture decisions}
\begin{enumerate}
\item Consent is established before telemetry is collected; withdrawal disables collection.
\item Event schema uses pseudonymous session identifiers and strictly selected non-sensitive fields.
\item Raw observations and derived metrics are stored with distinct retention and access policies.
\item Research notes keep subjective quotes separate from recorded behavior.
\item Deleting session data requires a documented retention/deletion workflow; no production identity service is assumed.
\end{enumerate}

\section{Quality attributes and verification}
\begin{itemize}
\item Disabled consent produces zero telemetry records.
\item Only allowlisted event keys reach storage.
\item Records have owner, purpose, retention, and deletion method.
\item A session note distinguishes observed from inferred experience.
\end{itemize}

\section{Threats, trade-offs, and alternatives}
\begin{enumerate}
\item For each exposed input and state owner, list abuse cases and assign prevention, detection, and recovery controls.
\item Compare two alternative decompositions using latency, coupling, observability, and test isolation.
\item Record who signs off on portability, security, privacy, and player-facing changes.
\item Do not infer that software correctness demonstrates an engaging player experience.
\end{enumerate}
