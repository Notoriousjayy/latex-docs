\section{Problem and conceptual crosswalk}
Create an event collector that only records opt-in, schema-validated, minimal observations.

Source alignment: Chapter 15: Players Play Games through an Interface, Chapter 28: Good Games Are Created through Playtesting. The source explains the design questions; the algorithm choices and reproducible implementation steps are supplementary engineering work.


\section{Preconditions and constraints}
\begin{itemize}
\item Basic Python 3 syntax, modern C++17 syntax, functions, assertions, and deterministic testing.
\item Use Python standard library and C++17 standard library only; no game engine is required.
\item The examples are didactic models rather than complete games; player experience must be tested separately.
\item Do not transmit telemetry or real player data. Use synthetic examples.
\end{itemize}

\section{Implementation procedure}
\begin{enumerate}
\item Read examples/python/privacy-aware-telemetry.py and examples/cpp/privacy-aware-telemetry.cpp.
\item Identify the state, legal operations, preconditions, invariants, and observable outputs.
\item Run the Python implementation and build/run the C++ implementation.
\item Add at least three boundary tests including an invalid input and a no-op or terminal state.
\item Record any differences between language implementations and why they do not imply identical PRNG outputs.
\item Write an actual playtest hypothesis that cannot be settled by functional unit tests alone.
\end{enumerate}
