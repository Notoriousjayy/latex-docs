\begin{tcolorbox}[colback=Teal!5,colframe=Teal,title=Essential question]How do row and column cycle decompositions determine an in-place permutation of all matrix positions?\end{tcolorbox}
\begin{tcolorbox}[colback=white,colframe=Mist,title=Learning objectives]\begin{itemize}\item Define the induced product permutation.\item Derive its cycles from a row-cycle and column-cycle pair.\item Apply tagged permutations to avoid visited storage.\item Trace a cyclic data move with one temporary value.\item Explain the alias case where row and column permutations coincide.\end{itemize}\textbf{Prerequisites:} permutation cycles, gcd/lcm, matrix indexing, in-place cyclic moves.\end{tcolorbox}
\section*{Cornell notes}
\begin{longtable}{@{}Q!{\color{Mist}\vrule width 1pt}A@{}}\cornellhead
\cue{What mapping is applied?}{Given row permutation $\sigma$ and column permutation $\tau$, matrix position $(i,j)$ moves according to
\[
\rho(i,j)=(\sigma(i),\tau(j)).
\]
Moving rows and columns separately would move every element twice; RENUMB follows the cycles of $\rho$ directly.}
\cue{What is the product-cycle theorem?}{Pair a row cycle of length $r$ with a column cycle of length $s$. Their Cartesian product decomposes into $\gcd(r,s)$ cycles of length $\operatorname{lcm}(r,s)$. These cycles together contain all $rs$ position pairs generated by that cycle pair.}
\cue{How is one cycle moved?}{Save one matrix entry in a temporary scalar. Repeatedly move the predecessor entry into the current vacancy while following $\rho$, and finally write the saved value into the last vacancy. Each matrix element in that cycle moves once.}
\cue{How are cycle pairs discovered?}{Tag $\sigma$ and $\tau$ using the cycle routine. Tagged entries identify one representative per cycle. RENUMB loops over tagged row cycles and tagged column cycles, then traverses all induced product cycles for each pair.}
\cue{How are gcd and lcm avoided?}{The routine uses a counter derived from the row-cycle length and observes returns of the row and column positions. Completion of one product cycle reduces the counter; after the required number of returns, all $\gcd(r,s)$ cycles for the pair have been processed, without explicitly calculating either gcd or lcm.}
\cue{Why is aliasing important?}{The same permutation array may serve as both $\sigma$ and $\tau$. Tagging one and checking the other's first entry detects this case, preventing a second tagging pass from corrupting shared state. Tags remain fixed during matrix movement and are removed at the end.}
\cue{Cost and storage}{Every matrix element is displaced once, plus cycle-control tests. The source bounds the operation count by $O(mn)$. Auxiliary data consists of the two permutation arrays, their tags, indices, and one saved matrix entry; no $m\times n$ visited array is needed.}
\cue{Cautions}{The direction convention must match the contract: old $a_{ij}$ becomes new $a_{\sigma(i),\tau(j)}$. Reversing that convention applies inverse permutations. Restore all negative tags even when the two permutation arrays are distinct.}
\cue{Retrieval practice}{\begin{enumerate}\item What is $\rho(i,j)$?\item How many product cycles arise from lengths $r,s$?\item Why is one temporary entry enough?\item How is aliasing detected?\item Which direction convention must be documented?\end{enumerate}}
\end{longtable}
\begin{tcolorbox}[colback=Ink!4,colframe=Ink,title=Cornell summary]
RENUMB avoids separate row and column passes by treating their combined effect as the product permutation $\rho(i,j)=(\sigma(i),\tau(j))$. A row cycle of length $r$ and column cycle of length $s$ generate $\gcd(r,s)$ position cycles, each of length $\operatorname{lcm}(r,s)$. Following each position cycle moves its entries in place with one temporary value, so every matrix element is displaced only once. Tagged row and column permutations supply cycle representatives without a visited matrix, including the special case in which both permutations share one array. The resulting work is proportional to the matrix size, provided the mapping direction and tag restoration are handled consistently.
\end{tcolorbox}
