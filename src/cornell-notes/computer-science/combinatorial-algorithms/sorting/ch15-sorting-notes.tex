\begin{tcolorbox}[colback=Teal!5,colframe=Teal,title=Essential question]How does one sift operation support both linear-time heap construction and an $O(n\log n)$ in-place sort?\end{tcolorbox}
\begin{tcolorbox}[colback=white,colframe=Mist,title=Learning objectives]\begin{itemize}\item State the array heap invariant.\item Trace downward vacancy movement in the sift operation.\item Separate TOHEAP and SORTHEAP.\item Derive the stated time and storage bounds.\item Explain EXHEAP's callback-like comparison/exchange protocol.\end{itemize}\textbf{Prerequisites:} arrays, binary trees, asymptotic summation, total order.\end{tcolorbox}
\section*{Cornell notes}
\begin{longtable}{@{}Q!{\color{Mist}\vrule width 1pt}A@{}}\cornellhead
\cue{What is a max heap?}{For one-based array $b_1,\ldots,b_n$, every parent dominates its children: $b_{\lfloor j/2\rfloor}\ge b_j$ for $2\le j\le n$. Node $i$ has children $2i$ and, when present, $2i+1$. Thus $b_1$ is a maximum.}
\cue{What does the sift operation assume?}{For a root position $\ell$, both child subtrees are already heaps. Save $b_\ell$ in a temporary location, move the larger child upward into the vacancy while it exceeds the saved value, and finally place the saved value in the remaining vacancy. The rooted subtree is then a heap.}
\cue{How is TOHEAP performed?}{Apply sift to $\ell=\lfloor n/2\rfloor,\lfloor n/2\rfloor-1,\ldots,1$. Leaves require no work. Reverse order ensures the two child subtrees satisfy the sift precondition before their parent is processed. The source bounds total heap-construction work by $O(n)$.}
\cue{How is the heap sorted?}{Exchange the maximum at position 1 with the last active position. Shrink the active heap by one and sift the new root through the remaining heap. Repeat until one item remains. The inactive suffix grows in nondecreasing final order.}
\cue{Why is the full cost $O(n\log n)$?}{A sift descends at most the height of the active binary tree, $O(\log n)$. Heap construction sums smaller subtree heights to $O(n)$. Up to $n-1$ extraction sifts cost $O(n\log n)$. Only one saved item and indices are needed beyond the array.}
\cue{Correctness invariant}{During construction, every subtree rooted below the current index is a heap. During extraction, the active prefix is a heap and the inactive suffix is sorted, contains the largest removed values, and is no smaller than the active prefix. Each exchange extends that suffix by one correct maximum.}
\cue{What is EXHEAP?}{EXHEAP separates heap control from data operations. A negative control value asks the caller to compare items $i$ and $j$ and return the sign; a positive value asks the caller to exchange them; zero announces completion. This supports records, matrix rows, or data stored outside the sorting routine.}
\cue{Tradeoffs}{Heapsort has deterministic $O(n\log n)$ comparisons, is in place, and is general. It is not stable and does not exploit existing order; the source notes particularly poor behavior on already sorted input relative to adaptive methods.}
\cue{Cautions}{Comparisons must define a consistent order. In EXHEAP, do not alter the requested indices or control state between the request and reentry. In zero-based implementations, child formulas change to $2i+1$ and $2i+2$.}
\cue{Retrieval practice}{\begin{enumerate}\item What is the heap property?\item Why choose the larger child?\item Why process parents in reverse order?\item What remains invariant during extraction?\item What does EXHEAP externalize?\end{enumerate}}
\end{longtable}
\begin{tcolorbox}[colback=Ink!4,colframe=Ink,title=Cornell summary]
Heapsort relies on one local repair: when both child subtrees are heaps, move the vacancy downward through larger children and insert the saved root where it dominates its children. Applying this sift from the last parent to the root constructs a heap in linear total work. Repeatedly moving the root maximum to the end, shrinking the heap, and sifting the replacement produces a sorted array in $O(n\log n)$ worst-case work with constant auxiliary storage. HPSORT operates directly on numeric data; EXHEAP exposes comparison and exchange requests so the same control algorithm can order arbitrary external items. The method is compact and predictable but neither stable nor adaptive to existing order.
\end{tcolorbox}
