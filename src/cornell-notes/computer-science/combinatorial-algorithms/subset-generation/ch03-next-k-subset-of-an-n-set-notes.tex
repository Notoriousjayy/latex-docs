\begin{tcolorbox}[colback=Teal!5,colframe=Teal,title=Essential question]How can every one of the $\binom nk$ fixed-cardinality subsets be generated either in dictionary order or by exchanging exactly one element at a time?\end{tcolorbox}
\begin{tcolorbox}[colback=white,colframe=Mist,title=Learning objectives]\begin{itemize}\item Maintain the increasing tuple representation.\item Compute a lexicographic successor and its active suffix length.\item Explain the revolving-door adjacency condition.\item Track insertions and deletions exposed by NXKSRD.\item Compare work and application behavior of the two orders.\end{itemize}\textbf{Prerequisites:} combinations, increasing sequences, lexicographic order, and symmetric difference.\end{tcolorbox}
\section*{Cornell notes}
\begin{longtable}{@{}Q!{\color{Mist}\vrule width 1pt}A@{}}\cornellhead
\cue{What family is generated?}{All $k$-element subsets of $\{1,\ldots,n\}$, represented by an increasing tuple $1\le a_1<\cdots<a_k\le n$. The family size is $\binom nk$, and fixed cardinality removes the bit-vector states of other sizes.}
\cue{What is lexicographic succession?}{Find the rightmost position that can increase while leaving room for its suffix. Increase that entry by one, then replace every later entry with consecutive integers. The first tuple is $(1,2,\ldots,k)$; the final tuple is $(n-k+1,\ldots,n)$.}
\cue{How does NEXKSB avoid a fresh search?}{It maintains $h$, the length of the suffix that must be rebuilt, together with a boundary value $m$. On most transitions, the state reveals whether $h$ resets or increases. The suffix is then filled by consecutive values ending at the advanced boundary. The source's counting argument shows fewer than two units of suffix work on average.}
\cue{What is revolving-door order?}{Consecutive $k$-subsets differ by deleting one member and inserting one different member. Their symmetric difference therefore has size two. This is analogous to moving through adjacent states while preserving cardinality and supports external calculations that can update from one removal and one insertion.}
\cue{What does NXKSRD expose?}{Besides the new sorted subset, the routine reports the element that left and the element that entered. That interface is the important application-level feature: a maintained quantity can undo the deleted element's contribution and apply the inserted element's contribution without recomputing from the full set.}
\cue{Correctness conditions}{For either order, the tuple must remain strictly increasing and within $[1,n]$. Lexicographic succession advances the greatest possible prefix position and resets the suffix to its least legal continuation, so no tuple lies between the old and new states. The revolving-door construction must preserve size $k$, change one-out/one-in, and terminate after $\binom nk$ unique states.}
\cue{State and edge cases}{Inputs satisfy $0\le k\le n$. The first-call flag initializes a new sequence; the more-to-come flag marks the final tuple. Check $k=0$, $k=n$, and $n=1$ explicitly in a modern wrapper. Do not sort after each call: sorted output is an invariant maintained by the generator.}
\cue{Which order should be used?}{Use lexicographic order when dictionary ranking, prefix grouping, or simple successor logic matters. Use revolving-door order when the external computation is incrementally updated from one deletion and one insertion. Neither order changes the number of outputs; it changes transition cost and useful locality.}
\cue{Historical or legacy context}{The routines preserve bookkeeping values in caller-owned arrays and flags across calls. A modern iterator can encapsulate this state and return a structured record containing the subset, completion status, inserted element, and deleted element.}
\cue{Retrieval practice}{\begin{enumerate}\item What is the final lexicographic $k$-subset?\item Which suffix is reset after an increment?\item What does symmetric difference size two mean?\item Why report inserted and deleted elements?\item Which invariants must hold after every call?\end{enumerate}}
\end{longtable}
\begin{tcolorbox}[colback=Ink!4,colframe=Ink,title=Cornell summary]
Fixed-cardinality subset generation has two useful notions of ``next.'' NEXKSB treats a subset as a strictly increasing tuple and advances it in lexicographic order by increasing the latest feasible coordinate and rebuilding the suffix with its smallest legal values. Its retained suffix state keeps average update work small. NXKSRD follows a revolving-door order: every transition removes one element and inserts one element while the cardinality remains $k$. Reporting those two elements lets a surrounding calculation update incrementally. Correct implementations preserve bounds, sortedness, uniqueness, and exact termination at $\binom nk$ states. The appropriate order is determined by whether the consumer values dictionary structure or minimum-change transitions.
\end{tcolorbox}
