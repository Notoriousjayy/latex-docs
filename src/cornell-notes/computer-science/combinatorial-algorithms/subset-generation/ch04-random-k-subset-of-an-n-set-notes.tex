\begin{tcolorbox}[colback=Paper,colframe=Ink]{\small\bfseries\color{Teal}CORNELL NOTES}\par{\LARGE\bfseries Chapter 4: Random $k$-Subset of an $n$-Set (RANKSB)}\par\medskip\textbf{Topic:} Uniform sampling without replacement\hfill\textbf{Date:} \today\par\textbf{Study purpose:} Understand the bin-based linear-storage sampler and its cost.\end{tcolorbox}
\begin{tcolorbox}[colback=Teal!5,colframe=Teal,title=Essential question]How can a uniformly random sorted $k$-subset be selected using only $k$ array positions and average work close to linear in $k$?\end{tcolorbox}
\begin{tcolorbox}[colback=white,colframe=Mist,title=Learning objectives]\begin{itemize}\item State the sampling and storage requirements.\item Explain the bin-count rejection phase.\item Reconstruct values within nonempty bins without duplicates.\item Relate expected repeated draws to the sampling fraction.\item Identify the complementary method suggested for large $k$.\end{itemize}\textbf{Prerequisites:} sampling without replacement, expectation, floor arithmetic, and sorted arrays.\end{tcolorbox}
\section*{Cornell notes}
\begin{longtable}{@{}Q!{\color{Mist}\vrule width 1pt}A@{}}\cornellhead
\cue{What contract is required?}{Input integers satisfy $0\le k\le n$. Output is an increasing tuple $(a_1,\ldots,a_k)$ chosen uniformly from the $\binom nk$ possibilities. The algorithm is designed to use the output array itself as workspace, with no array of length $n$.}
\cue{Why is naive rejection awkward?}{Repeatedly drawing from $[1,n]$ and checking all prior choices needs quadratic comparison work. A full membership bitmap gives fast duplicate tests but violates the $k$-word storage goal and does not directly produce sorted output. The expected number of raw draws also grows toward $n\log n$ when nearly every element is requested.}
\cue{What is the bin strategy?}{Partition $[1,n]$ into $k$ nearly equal consecutive ranges $R_1,\ldots,R_k$. First determine only how many selected elements belong to each range. The array holds counters disguised as range-boundary values. A trial landing in a bin with $m$ accepted positions out of $q$ possible positions is rejected with probability $m/q$, so exact accepted values need not yet be retained.}
\cue{How are bin counts compacted?}{After $k$ acceptances, scan the counter array, discard empty bins, and compact nonempty-bin descriptors leftward. Working from the right, reserve exactly $|B_i|$ positions for the selected values of each nonempty bin. This reuses the same $k$ locations for descriptors and final output.}
\cue{How are actual values chosen?}{Process each reserved bin. Draw a rank among the still-unchosen values in that bin; scan the already inserted sorted values and increment the candidate when it crosses an occupied value. Insert the adjusted value in order. The within-bin quadratic work is acceptable because bin occupancies are typically small.}
\cue{Why is the result uniform?}{The first phase reproduces the occupancy distribution produced by $k$ distinct uniform choices. Conditional on those occupancies, the second phase chooses each subset within every bin uniformly. Multiplying these conditional choices yields the same probability for every global $k$-subset.}
\cue{What cost is established?}{The expected number of raw draws is $n(H_n-H_{n-k})$. For $k$ bounded away from $n$, this is linear in $k$; in the worst sampling regime it is $O(k\log k)$. The chapter's occupancy calculation shows the expected sum of squared bin sizes is linear in $k$, making the second phase linear on average.}
\cue{What is RKS2 for?}{A second method is sketched for $k\ge n/2$, using $k$ storage words and $O(k)$ steps while retaining sorted output. It avoids the deterioration of repeated-draw rejection near $k=n$, but is not included in the supplied routine.}
\cue{Cautions}{Integer formulas that map values to bins must respect the source's one-based boundaries. Random integer generation must be unbiased. The output array changes roles several times, so premature reads or aliasing will corrupt descriptors. For $k=0$ or $k=n$, a modern implementation should use direct results.}
\cue{Retrieval practice}{\begin{enumerate}\item Why use $k$ bins?\item What does a counter represent before compaction?\item Why are within-bin quadratic scans acceptable?\item When does raw rejection become expensive?\item What does the storage bound exclude?\end{enumerate}}
\end{longtable}
\begin{tcolorbox}[colback=Ink!4,colframe=Ink,title=Cornell summary]
RANKSB meets three simultaneous requirements: uniform sampling without replacement, sorted output, and only $k$ storage locations. It divides the universe into $k$ consecutive bins, simulates accepted occupancy counts without storing individual trials, compacts the nonempty bins, and then chooses the actual values inside each bin. Small expected bin occupancy keeps the local duplicate-resolution work controlled. The expected number of preliminary drawings is linear when the sampling fraction is bounded away from one and grows to $O(k\log k)$ in the extreme regime. A complementary strategy is therefore appropriate for large $k$. The algorithm is a careful example of representation reuse: the output array successively stores boundary counters, compact bin descriptors, reserved regions, and finally the sorted sample.
\end{tcolorbox}
