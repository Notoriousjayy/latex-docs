\section*{Cornell notes}
\begin{longtable}{@{}Q!{\color{Mist}\vrule width 1pt}A@{}}\cornellhead
\cue{What is the target?}{For finite poset $P=\{1,\ldots,n\}$, find a permutation of labels such that $x<y$ implies the new label of $x$ is smaller than the new label of $y$. Applying this same permutation to rows and columns makes the zeta matrix upper triangular.}
\cue{Why does minimal-element removal work?}{Every nonempty finite poset has a minimal element. Assign it the next label, remove it conceptually, and repeat. No later element can be required to precede an already labeled minimal element, so the labels form a linear extension.}
\cue{What inefficiency is avoided?}{A naive method descends a relation chain to a minimal element, labels it, then restarts a global search. The predecessor of the newly labeled element is already near another minimal remaining element, so discarding that chain information repeats work.}
\cue{How is the label array reused?}{Before an element receives its final positive label, its array slot stores a predecessor pointer along the current descent chain. After reaching a minimal element, save its pointer, overwrite the slot with the next label, and resume from the saved predecessor when one exists.}
\cue{What input matrices are accepted?}{The full zeta matrix works, but the algorithm also accepts the covering-relation matrix or a more general nonzero relation matrix that generates the same partial order. It searches for an unlabeled predecessor below the current element.}
\cue{Correctness invariant}{Every permanently labeled element is minimal among the currently unlabeled elements reachable in the maintained search. Therefore if $x<y$, $y$ cannot receive a label before $x$. Temporary pointers refer only to unlabeled chain positions and are replaced before exit.}
\cue{Output and relationship}{SIG$(i)$ is the new label assigned to original element $i$. RENUMB can apply SIG to the rows and columns of the relation matrix. The next chapter uses this triangular form before performing specialized matrix inversions.}
\cue{Historical or legacy context}{The source notes that edge-list topological sorting is more efficient when ordered pairs are the natural input. TRIANG is designed for a square incidence-matrix interface, where scanning rows and columns is already part of the cost model.}
\cue{Retrieval practice}{\begin{enumerate}\item What property must new labels satisfy?\item Why does a minimal element always exist?\item What does an unlabeled SIG slot store temporarily?\item Which matrices may describe the order?\item How is triangularity used later?\end{enumerate}}
\end{longtable}
\begin{tcolorbox}[colback=Ink!4,colframe=Ink,title=Cornell summary]
TRIANG constructs a linear extension of a finite partial order so that its incidence matrix becomes upper triangular after consistent row and column renumbering. It repeatedly descends through unlabeled predecessors until reaching a minimal remaining element, assigns the next label, and then resumes from the saved chain rather than restarting. The output array doubles as temporary predecessor storage and final labels. This approach accepts a full zeta matrix, a cover matrix, or another matrix generating the same order. It is tailored to dense matrix input; an explicit-edge representation would normally favor a conventional topological sort.
\end{tcolorbox}
