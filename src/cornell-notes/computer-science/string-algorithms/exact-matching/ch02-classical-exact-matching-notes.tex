\begin{CornellOverviewBox}{Chapter overview}
\textbf{Purpose.} Compare three classical ways to reuse matched structure: right-to-left skipping, prefix-failure shifts, and bounded per-character processing.

\textbf{Learning objectives}
\begin{itemize}
  \item Apply the bad-character and strong good-suffix rules.
  \item Explain the Knuth-Morris-Pratt prefix invariant and failure shift.
  \item Separate preprocessing bounds from search bounds.
  \item Recognize when a real-time guarantee is stronger than linear total time.
\end{itemize}

\textbf{Prerequisites.} Chapter 1, borders of strings, and basic amortized analysis.
\end{CornellOverviewBox}

\begin{CornellNotesTable}
\CornellNoteRow{\S2.1: What is being compared?}{All methods report exact occurrences, but they expose different structure. Boyer-Moore scans an alignment from right to left and may jump far; Knuth-Morris-Pratt scans the text monotonically while maintaining a matched prefix; real-time matching limits the work charged to each arriving character.}
\CornellNoteRow{\S2.2: Why scan right to left?}{A mismatch near the pattern's right end reveals a character and a matched suffix simultaneously. Boyer-Moore chooses a shift that cannot skip a valid occurrence, taking the larger safe shift supplied by its two rules.}
\CornellNoteRow{What is the bad-character rule?}{Suppose text character $c$ mismatches pattern position $j$. Shift so $c$ aligns with its rightmost occurrence in $P[1..j-1]$; if no such occurrence exists, move the pattern beyond $c$. Preprocessing stores suitable occurrence positions for constant-time shift lookup.}
\CornellNoteRow{What is the strong good-suffix rule?}{After a suffix $P[j+1..m]$ matches, shift it to another occurrence whose preceding character differs from $P[j]$. If none exists, align the longest suffix of the matched suffix that is also a prefix of $P$. This stronger condition uses the known mismatch as well as the known match.}
\CornellNoteRow{How is Boyer-Moore used?}{\textbf{Input/output:} $P,T$ and all occurrence positions. \textbf{Preprocess:} bad-character positions plus good-suffix shifts. \textbf{Search:} compare right to left, report a full match, and shift safely. \textbf{Behavior:} often sublinear in inspected text characters; a proper full implementation also has a linear worst-case search bound.}
\CornellNoteRow{\S2.3: What invariant drives KMP?}{Before reading the next text character, $q$ is the length of the longest prefix of $P$ that is a suffix of the text prefix already read. On mismatch, replace $q$ by the next shorter border length until the character can extend the prefix or $q=0$. The text index never moves backward.}
\CornellNoteRow{What is KMP preprocessing?}{For every pattern prefix, record the length of its longest proper border, often called a failure or prefix function. The table can be derived in $O(m)$ time. A full match is reported when $q=m$, after which the border of the whole pattern permits overlapping matches.}
\CornellNoteRow{Why is KMP linear?}{Every successful comparison advances the text. Failure transitions strictly decrease the current matched-prefix length, and those decreases are charged against earlier increases. Search time is $O(n)$ after $O(m)$ preprocessing, with $O(m)$ auxiliary storage.}
\CornellNoteRow{\S2.4: What does real-time mean?}{Linear total time allows an occasional long failure-chain walk. Real-time matching strengthens the guarantee to $O(1)$ worst-case work per arriving text character. Precomputed transitions collapse the possible failure sequence into direct state changes; the tradeoff can be more preprocessing or alphabet-dependent storage.}
\CornellNoteRow{Which edge cases matter?}{Handle overlapping occurrences, a pattern longer than the text, repeated single-character patterns, and an empty pattern policy. Boyer-Moore tables must define shifts at the first pattern position; KMP must fall back after a full match rather than resetting blindly.}
\CornellNoteRow{\S2.5: What should practice emphasize?}{Construct preprocessing tables by hand, trace alignments, and prove that each shift preserves every possible occurrence. Compare total comparisons, not just asymptotic notation, on periodic and nonperiodic inputs.}
\end{CornellNotesTable}

\begin{CornellSummaryBox}{Chapter synthesis}
Classical exact matchers encode the same principle in different forms: preserve what a partial match has proved. Boyer-Moore uses right-to-left evidence to skip alignments, KMP maintains the longest viable prefix state while streaming left to right, and real-time variants remove long per-character fallback chains.
\end{CornellSummaryBox}

\begin{CornellSummaryBox}{Key takeaways}
\begin{CornellRecallList}
  \item Boyer-Moore combines two independently safe shift rules.
  \item The strong good-suffix rule uses both the matched suffix and mismatch context.
  \item KMP's state is the longest pattern prefix matching the processed-text suffix.
  \item KMP never rescans text characters.
  \item Linear total time and constant worst-case time per character are different guarantees.
  \item Overlapping matches require a post-match fallback state.
\end{CornellRecallList}
\end{CornellSummaryBox}

\begin{CornellOverviewBox}{Algorithm selection: when to use this}
\begin{CornellChecklist}
  \item Use Boyer-Moore when practical skipping on ordinary text is valuable.
  \item Use KMP for predictable linear scans, small memory, and streaming-friendly behavior.
  \item Use a real-time transition table when input arrival deadlines forbid variable work per character.
\end{CornellChecklist}
\end{CornellOverviewBox}

\begin{CornellExamBox}{Self-test questions}
\begin{CornellRecallList}
  \item Why is the maximum of the two Boyer-Moore shifts still safe?
  \item State the KMP invariant at the boundary between two text characters.
  \item How are overlapping matches preserved after a full KMP match?
  \item Give an input family on which naive matching repeats many comparisons.
  \item What extra promise does a real-time matcher provide?
\end{CornellRecallList}
\end{CornellExamBox}
