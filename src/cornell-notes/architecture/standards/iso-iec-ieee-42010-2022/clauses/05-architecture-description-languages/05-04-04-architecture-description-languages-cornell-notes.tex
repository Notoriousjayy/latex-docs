\begin{CornellNotesTable}
\CornellNoteRow{Purpose / key concept}{An ADL is a specified syntax and semantics intended for use in describing the architecture of an entity of interest.}
\CornellNoteRow{Core details}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item An ADL is a language for stakeholders, including those involved in the architecting effort that allows the expression of architecture considerations by means of AD elements pertaining to the entity of interest, and the architecting context.
\item An AD can use more than one ADL, even a different ADL for each viewpoint, or even distinct ADLs for each model kind specified by a single architecture viewpoint.
\item ADLs can be employed (or devised) to express specific architecture considerations which an architect needs to address.
\item An ADL provides a way to create and understand the view components that compose into architecture views.
\end{itemize}}
\CornellNoteRow{Study relationship / visual insight}{Study relationship: an ADL provides a way to create and understand AD elements, identifies model kinds, can refine viewpoint specifications, uses legends, and works with view methods that guide selection and transformation of information.}
\CornellNoteRow{Example / application}{UML profiles for architecture description are defined using stereotypes, tag definitions, and constraints applied to specific model elements (classes, attributes, operations, and activities) with a profile collection of such extensions collectively customized for a particular domain (e.g. aerospace, healthcare, financial) or platform (J2EE, .NET), and a modelling profile can define a particular model kind as part of its specification.}
\CornellNoteRow{Interpretive note}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item The use of more than one ADL in an AD requires great care to avoid confusion and misunderstanding.
\item ADLs identify one or more AD elements which are instances of the architectural constructs: stakeholder, concern, architecture viewpoint, model kind, legend, etc.
\end{itemize}}
