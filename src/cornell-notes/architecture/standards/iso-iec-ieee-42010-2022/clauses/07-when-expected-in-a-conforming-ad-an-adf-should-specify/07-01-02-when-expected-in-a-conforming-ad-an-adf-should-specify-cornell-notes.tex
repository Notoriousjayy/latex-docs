{\small\textbf{Learning objective:} Identify the mandatory, recommended, and permitted provisions governing when expected in a conforming ad, an adf should specify.}
\end{CornellOverviewBox}
\vspace{3pt}

\begin{CornellNotesTable}
\CornellNoteRow{Purpose}{Identifies additional framework content that should be specified when it is expected in a conforming architecture description.}
\CornellNoteRow{Recommendation}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item When expected in a conforming AD, an ADF should specify:
\item Recommended content: one or more stakeholder perspectives (per 6.3)
\item Recommended content: one or more aspects (per 6.5)
\item Recommended content: definition of one or more structuring formalisms to organize viewpoints (per 5.4.2)
\item Recommended content: one or more model kinds that apply to specified architecture viewpoints (per 8.2)
\item Recommended content: definition of one or more legends that apply to specified architecture viewpoints
\item Recommended content: identification of ADLs that can be used to create views with regards to the viewpoint specification (per 7.2)
\item Recommended content: correspondence methods (per 6.9.3)
\item Recommended content: view methods (per 8.3)
\item Recommended content: version identification as specified by the organization and/or project
\item The specification of an ADF should include conditions on applicability.
\item The specification of an ADF should indicate its consistency with the concepts in 5.2.
\end{itemize}}
\CornellNoteRow{Permission}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item A specification of an ADF may establish additional rules for adherence.
\item An ADF may have a structuring formalism with one or more structural categories to provide ways of representing relationships among various elements of the architecture and enhancing opportunities for analysis of interactions among those elements.
\end{itemize}}
