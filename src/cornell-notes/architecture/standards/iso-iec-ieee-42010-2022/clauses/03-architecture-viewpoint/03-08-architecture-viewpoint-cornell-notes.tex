\vspace{3pt}

\begin{CornellNotesTable}
\CornellNoteRow{Term}{\textbf{architecture viewpoint}}
\CornellNoteRow{Definition}{A set of conventions governing the creation, interpretation, and use of architecture views to frame one or more concerns.}
\CornellNoteRow{Key characteristics}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item Here, “to frame” concerns means “to shape, compose, give expression to” those concerns. It is used to distinguish the stages of framing concerns by a viewpoint from addressing those concerns in a resulting view. This is analogous to the distinction between “framing a problem” and “solving that problem”.
\item A viewpoint is a frame of reference for the concerns determined by the architect as relevant to the purpose of the architecture description (3.3).
\item The conventions of an architecture viewpoint are documented in a specification (3.16) of that viewpoint. In some communities and architecture description frameworks, “view specification” and viewpoint are synonyms.
\item The identification of a viewpoint is often the result of prior knowledge, experience and praxis in the domain(s) to which the viewpoint applies, indicating the information relevant to addressing the concern (3.10).
\end{itemize}}
\CornellNoteRow{Distinction}{A viewpoint frames concerns and governs views; a view addresses those concerns using the viewpoint’s conventions.}
\CornellNoteRow{Related sections}{3.7, 3.10, 3.3, 3.16}
\CornellNoteRow{Active recall}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item How would you explain architecture viewpoint in your own words?
\item Which neighboring concept is easiest to confuse with architecture viewpoint, and how is it different?
\end{itemize}}
\end{CornellNotesTable}


\begin{CornellSummaryBox}{Summary}
A set of conventions governing the creation, interpretation, and use of architecture views to frame one or more concerns. A viewpoint frames concerns and governs views; a view addresses those concerns using the viewpoint’s conventions.
\end{CornellSummaryBox}
