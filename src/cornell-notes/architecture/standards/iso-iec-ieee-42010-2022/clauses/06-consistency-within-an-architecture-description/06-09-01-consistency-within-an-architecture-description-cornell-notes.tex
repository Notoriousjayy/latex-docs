\begin{CornellOverviewBox}{Overview}
{\Large\bfseries\textcolor{CNavy}{Section 6.9.1: Consistency within an architecture description}}\\[3pt]
{\small\textbf{Classification:} Normative}\\
{\small\textbf{Learning objective:} Identify the mandatory, recommended, and permitted provisions governing consistency within an architecture description.}
\end{CornellOverviewBox}
\vspace{3pt}

\begin{CornellNotesTable}
\CornellNoteRow{Purpose}{Requires known inconsistencies to be recorded and recommends consistency analysis across views, view components, and other AD elements.}
\CornellNoteRow{Requirement}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item A conforming architecture description must record any known inconsistencies.
\end{itemize}}
\CornellNoteRow{Recommendation}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item An architecture description should include or reference an analysis of consistency of its architecture views, its view components and other AD elements.
\end{itemize}}
\CornellNoteRow{Permission}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item Correspondences and correspondence methods, as specified in 6.9.2 and 6.9.3, may be used to express, record, enforce and analyse consistency between views, their view components and other AD elements within and among ADs.
\end{itemize}}
\CornellNoteRow{Related sections}{6.9.2, 6.9.3}
\CornellNoteRow{Conformance check}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item A conforming architecture description must record any known inconsistencies
\end{itemize}}
\CornellNoteRow{Active recall}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item Which provisions in Consistency within an architecture description are mandatory for conformance?
\item Which provisions are recommendations or permissions rather than requirements?
\end{itemize}}
\end{CornellNotesTable}


\begin{CornellSummaryBox}{Summary}
Requires known inconsistencies to be recorded and recommends consistency analysis across views, view components, and other AD elements. For conformance, its mandatory provisions must be satisfied, including: A conforming architecture description must record any known inconsistencies. Recommended practice includes: An architecture description should include or reference an analysis of consistency of its architecture views, its view components and other AD elements. The section also explicitly permits: Correspondences and correspondence methods, as specified in 6.9.2 and 6.9.3, may be used to express, record, enforce and analyse consistency between views, their view components and other AD elements within and among ADs.
\end{CornellSummaryBox}
