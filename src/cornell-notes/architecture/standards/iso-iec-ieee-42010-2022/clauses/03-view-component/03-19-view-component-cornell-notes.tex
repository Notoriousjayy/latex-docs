\begin{CornellNotesTable}
\CornellNoteRow{Term}{\textbf{view component}}
\CornellNoteRow{Definition}{A separable portion of one or more architecture views governed by the applicable model kind or legend.}
\CornellNoteRow{Key characteristics}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item In the context of an architecture description (3.3), a legend is an informal documentation of conventions.
\end{itemize}}
\CornellNoteRow{Distinction}{A view component is part of one or more views; a model kind supplies conventions for model-based components, while a legend documents conventions where no model kind governs.}
\CornellNoteRow{Example / application}{An architecture view component describing access control mechanisms can be used in several views of an architecture description (3.3) to explain functional flows, behaviour and security features of an entity.}
\CornellNoteRow{Related sections}{3.7, 3.15, 3.3}
\CornellNoteRow{Active recall}{\begin{itemize}[leftmargin=*,nosep,topsep=1pt]
\item How would you explain view component in your own words?
\item Which neighboring concept is easiest to confuse with view component, and how is it different?
\end{itemize}}
\end{CornellNotesTable}


\begin{CornellSummaryBox}{Summary}
A separable portion of one or more architecture views governed by the applicable model kind or legend. A view component is part of one or more views; a model kind supplies conventions for model-based components, while a legend documents conventions where no model kind governs.
\end{CornellSummaryBox}
