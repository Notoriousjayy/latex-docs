\section*{Chapter Overview}
General-purpose algorithms rely on exact representations, explicit invariants, and disciplined validation. Their assumptions and failure modes must be visible before the code is trusted.

\section*{Learning Objectives}
\begin{itemize}
\item Identify the representation and invariant that controls an algorithm's correctness.
\item Compare time, memory, and implementation trade-offs.
\item Validate transformations with known vectors, boundary cases, and round trips.
\end{itemize}

\begin{exambox}{Numerical warning}
Bit-order disagreement, integer overflow, malformed streams, and noncanonical codes can make an apparently correct algorithm fail in production.
\end{exambox}

\section{22.0 Introduction}
\begin{cornell}
\noterow{What is the central idea?}{General-purpose algorithms require precise representations, invariants, complexity models, and tests, even when they are not numerical approximations.}
\noterow{How should it be used?}{Choose an exact representation, state encoding conventions, implement transformations with explicit bounds, and test round trips and known vectors.}
\noterow{Cost and reliability}{Analyze bit, memory, and execution costs separately. Retain checks that detect malformed inputs and violated invariants.}
\noterow{Implementation checklist}{\begin{itemize}
\item Define inputs, outputs, bounds, and ownership.
\item Guard invalid states, overflow, and malformed encodings.
\item Test simple, boundary, and corrupted inputs.
\end{itemize}}
\end{cornell}

\begin{summarybox}{Section summary}
A reliable general algorithm has a clear representation, an observable invariant, explicit bounds, and an independent verification path.
\end{summarybox}
