\section{Language-Lawyer and Library-Usage Pitfalls}
\begin{CornellReferencePitfallBox}\begin{itemize}[label=\textcolor{CornellReferenceAmber}{$\blacktriangleright$}]
\item Ranking conversions before constructing the complete candidate set.
\item Assuming the function with the fewest textual conversions wins.
\item Forgetting rewritten, synthesized, or built-in candidates.
\item Treating constrained-template ordering as ordinary conversion ranking.
\item Taking an overload set's address without a target type context.
\item Treating a note, example, or recommended practice as though it imposed a mandatory program rule.
\end{itemize}\end{CornellReferencePitfallBox}
\section{Programmer and Implementation Checklist}
\begin{CornellReferenceChecklistBox}\begin{itemize}[label=$\square$]
\item Determine the exact syntactic overload context.
\item Build the complete candidate set, including special candidates.
\item Remove non-viable candidates with recorded reasons.
\item Classify and rank each implicit conversion sequence.
\item Apply template and constraint tie-breakers only at the correct stage.
\item Require a unique best viable function.
\item For \CornellClauseRef{12.1}, verify preamble against the precise rule category and all cited dependencies.
