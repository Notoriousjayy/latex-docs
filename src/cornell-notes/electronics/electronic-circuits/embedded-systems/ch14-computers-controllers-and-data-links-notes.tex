\begin{CornellOverviewBox}{Concept}
Computing systems combine processors, memory, buses, peripherals, interrupts, DMA, and serial/parallel links. The central design task is to move commands and data with defined ownership, timing, ordering, encoding, error handling, and real-time behavior. Older and newer buses differ in speed and signaling, but the transferable reasoning concerns transactions, arbitration, synchronization, buffering, and physical-layer integrity.
\end{CornellOverviewBox}
\begin{CornellOverviewBox}{Concept}
\textbf{Prerequisites.} Digital logic and timing, number representations, programmable devices, logic interfacing, and basic programming concepts.

\textbf{After studying this chapter, you should be able to:}
\begin{itemize}
  \item Describe CPU, memory, I/O, bus, interrupt, and DMA roles.
  \item Trace programmed-I/O and interrupt-driven transactions through address, data, status, and control registers.
  \item Compare memory technologies and their volatility, timing, endurance, and interface needs.
  \item Select SPI, I$^2$C, UART/RS-485, CAN, USB, Ethernet, or other links from topology, rate, distance, determinism, and robustness.
\end{itemize}\textbf{Central design questions.}
\begin{itemize}
  \item Who owns the bus or buffer, and what event transfers ownership?
  \item What are ordering, atomicity, timeout, retry, and error-recovery semantics?
  \item Which layer defines electrical signaling, framing, transport, and application meaning?
\end{itemize}\end{CornellOverviewBox}
\section{Cornell Notes}
\begin{CornellNotesTable}
\CornellNoteRow{14.1: Architecture}{A CPU fetches and executes instructions using registers, an arithmetic/logic unit, control, and caches. Memory holds code/data; mass storage provides persistence; ports connect peripherals; real-time I/O interacts with deadlines. Buses carry address, data, control, and timing. Modern systems hide latency with caches and concurrency, so memory ordering and device-register semantics must be explicit.}
\CornellNoteRow{14.2: Instructions}{Machine instructions encode operations, operands, and addressing modes; assembly is a symbolic representation. A programming example should be traced through register/memory state and side effects. Width, signedness, endianness, alignment, flags, stack discipline, and privilege matter. For device I/O, compilers and CPUs may reorder ordinary memory operations unless the platform's I/O primitives and barriers are used.}
\CornellNoteRow{14.3: Bus interfacing}{A programmed output writes data to an addressed register; an input reads sampled state; status reports readiness/errors; command registers initiate operations. Interrupts notify the CPU asynchronously and require identification, acknowledgement, bounded service, and shared-state discipline. DMA moves blocks without per-word CPU service but introduces buffer ownership, cache coherence, alignment, and completion synchronization.}
\CornellNoteRow{14.4: Memory}{SRAM is fast and simple but area/power intensive; DRAM is dense and needs refresh/controllers; flash/EEPROM are nonvolatile with program/erase granularity, endurance, retention, and power-fail constraints. Memory selection includes latency, bandwidth, capacity, volatility, endurance, ECC, interface, temperature, lifecycle, and software update model. No nonvolatile write should assume power remains present indefinitely.}
\CornellNoteRow{14.5--14.6: Bus overview}{Parallel buses transfer multiple bits together but suffer skew, pin count, crosstalk, and termination challenges as speed/distance grows. Synchronous buses share a clock; asynchronous buses handshake. Arbitration chooses a master; ready/wait or credits handle variable latency. Bridge devices translate protocols but also buffering, ordering, width, and clock domains.}
\CornellNoteRow{14.7: Serial links}{SPI is simple, fast, and chip-select based but lacks a universal higher protocol. I$^2$C uses addressed open-drain lines with arbitration/acknowledgement and RC rise limits. UART links frame asynchronous characters; RS-485 provides differential multidrop electrical signaling. CAN adds prioritized arbitration and fault handling. USB and Ethernet are layered ecosystems with discovery, framing, and software stacks. Select and implement the complete applicable standard.}
\CornellNoteRow{14.7: Coding and clock recovery}{Manchester/biphase embed transitions for clock recovery at bandwidth cost. Run-length-limited and block codes constrain transition density and may provide dc balance and error detection. Serial receivers recover sampling phase from transitions; jitter tolerance, encoding, channel loss, equalization, termination, and reference clocks set link margin. Bit stuffing changes throughput and worst-case latency.}
\CornellNoteRow{14.8: Number formats}{Unsigned, two's-complement, fixed-point, floating-point, BCD, and character codes have different range, precision, overflow, and comparison rules. A wire protocol must define byte order, bit order, field width, scaling, units, invalid values, and versioning. Floating point represents many real values approximately and has NaN, infinity, rounding, and non-associativity concerns.}
\end{CornellNotesTable}
\begin{CornellSummaryBox}{Summary}
Computer interfaces are stateful transactions over physical links. Correct design defines registers, ownership, timing, ordering, buffering, interrupt/DMA behavior, memory persistence, numeric encoding, and recovery at each layer. Match the protocol and physical layer to rate, distance, topology, latency, noise, power, and ecosystem needs, then test failures as deliberately as normal transfers.
\end{CornellSummaryBox}
\section{Worked Examples}
\begin{CornellExamBox}{Interrupt load}
A device interrupts at $20\,\mathrm{kHz}$ and the complete handler costs $1.8\,\mu\mathrm{s}$. CPU utilization is $20{,}000(1.8\,\mu\mathrm{s})=3.6\%$, excluding cache disruption and bursts. DMA or batching may reduce overhead, but latency and buffer management change.
\end{CornellExamBox}
\begin{CornellExamBox}{I$^2$C rise-time estimate}
A bus has $C=180\,\mathrm{pF}$ and $R_P=2.2\,\mathrm{k\Omega}$. The rough $10$--$90\%$ rise is $2.2RC=0.871\,\mu\mathrm{s}$. Compare with the selected speed mode's threshold-based rise requirement and device sink-current limits.
\end{CornellExamBox}
\begin{CornellExamBox}{Fixed-point range}
A signed 16-bit value uses scale $0.01\,^{\circ}\mathrm{C}$/count. Representable range is approximately $-327.68$ to $327.67\,^{\circ}\mathrm{C}$. Define saturation/invalid codes and byte order; otherwise two implementations can interpret identical bytes differently.
\end{CornellExamBox}
\section{Design and Troubleshooting}
\begin{CornellExamBox}{Design and Troubleshooting}
\begin{enumerate}
  \item Define data producers/consumers, rate/burst, latency/deadline, topology, distance, environment, and failure behavior.
  \item Specify registers/messages, ownership, state machine, buffering, interrupt/DMA, ordering, timeouts, retries, and numeric formats.
  \item Choose protocol/physical layer; design clocks, level/termination, connectors, isolation, integrity checks, and update/security needs.
  \item Test normal load, burst, concurrency, reset, disconnect, corruption, timeout, power loss, buffer exhaustion, and long-duration recovery.
\end{enumerate}\end{CornellExamBox}
\begin{CornellExamBox}{Symptoms, likely causes, and checks}
\begin{itemize}
  \item Stale/wrong register data: caching/reordering, missing volatile/I/O accessor, endian/width mismatch, or ownership race.
  \item Interrupt storm/loss: uncleared source, wrong polarity, masking race, level/edge mismatch, or service overload.
  \item DMA corruption: cache incoherence, premature reuse, alignment/length error, or incomplete barrier.
  \item Serial errors: baud/clock mismatch, termination, common-mode, rise time, framing, cable topology, or ground shift.
  \item Works until reset/power fail: undefined startup protocol, partial nonvolatile write, stale peer state, or missing timeout recovery.
\end{itemize}\end{CornellExamBox}
\begin{CornellWarningBox}{Safety and Limitations}
External data links can import surge, ESD, ground potential, or hazardous isolation failures. Use appropriate transceivers, galvanic isolation, protection, shielding, and connector pin sequencing. Do not connect earth-referenced debug probes to floating or hazardous equipment without an approved isolated/differential method.
\end{CornellWarningBox}
\section{Key-Equation Sheet}
\begin{CornellExamBox}{Key Equations}
\begin{itemize}
  \item Service utilization estimate: $U=\lambda t_s$ for event rate $\lambda$ and service time $t_s$ under simplified non-overlap assumptions.
  \item Payload throughput equals symbol/bit rate times coding, framing, and idle efficiency.
  \item Open-drain rise estimate: $t_r\approx2.2R_PC_{bus}$ for $10$--$90\%$.
  \item Signed two's-complement $n$-bit range is $-2^{n-1}$ to $2^{n-1}-1$.
  \item Fixed-point real value equals stored integer times the documented scale.
  \item Buffer time margin $=\text{capacity}/\text{net fill rate}$ during a sustained producer-consumer mismatch.
\end{itemize}\end{CornellExamBox}
\section{Study and Review}
\subsection{Design checklist}
\begin{itemize}
  \item Register/message fields, widths, endian, units, and versions are documented.
  \item Ownership, ordering, atomicity, timeout, retry, and reset recovery are defined.
  \item Interrupt/DMA worst-case rates and cache/buffer synchronization are safe.
  \item Physical layer, termination, common mode, isolation, and connectors match the environment.
  \item Power-fail, disconnect, corruption, overflow, and peer-restart tests pass.
\end{itemize}\subsection{Common misconceptions}
\begin{itemize}
  \item A bus protocol is not only its connector or voltage levels.
  \item DMA is not free; it transfers CPU work into ownership/coherence management.
  \item Volatile in C/C++ is not a general inter-thread synchronization primitive.
  \item Floating point is not exact real arithmetic.
  \item A high headline link rate is not equal to usable application throughput.
\end{itemize}\subsection{Active-recall questions}
\begin{enumerate}
  \item What roles do address, data, strobe, and status play?
  \item How do interrupts differ from polling?
  \item What new problems does DMA introduce?
  \item How do SRAM, DRAM, and flash differ?
  \item Why did high-speed links move toward serial?
  \item What constrains I$^2$C rise time?
  \item How do RS-485 and a UART relate?
  \item Why use line coding?
  \item What must a numeric wire format define?
  \item Which failures should timeout/retry logic handle?
\end{enumerate}\subsection{Original practice problems}
\begin{enumerate}
  \item A $1\,\mathrm{MiB}$ DMA buffer receives $40\,\mathrm{MB/s}$ while software drains $32\,\mathrm{MB/s}$. Time to overflow from empty?
  \item A frame carries 256 payload bytes plus 20 overhead bytes at $2\,\mathrm{Mbit/s}$. Find ideal payload rate without idle gaps.
  \item Interpret bytes 0x34 0x12 as a 16-bit little-endian unsigned value.
\end{enumerate}\subsection{Answer key / solution outline}
\begin{enumerate}
  \item Net fill is $8\,\mathrm{MB/s}$; using binary $1\,\mathrm{MiB}$ and decimal rate gives about $0.131\,\mathrm{s}$ -- define units precisely.
  \item Efficiency $256/276=92.75\%$; payload rate $1.855\,\mathrm{Mbit/s}$.
  \item $0x1234=4660$ decimal.
\end{enumerate}\begin{CornellSummaryBox}{Summary}
Define data meaning and transaction state as rigorously as electrical signaling. Ownership, ordering, buffering, interrupts/DMA, numeric formats, timeout recovery, and physical-layer margins determine whether a link remains correct under concurrency and failure.
\end{CornellSummaryBox}
