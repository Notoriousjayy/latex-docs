\begin{CornellOverviewBox}{Review Orientation}
\textbf{Central problem.} Evaluate proxy, stateless, stateful, and inspection firewalls as protocol interpreters whose filtering decisions can fail through ambiguity, fragmentation, layering, spoofing, or resource exhaustion.
\textbf{Why it matters.} Security reviewers use this material to connect attacker-controlled conditions to violated invariants, consequential operations, and defensible remediation.
\textbf{Prerequisites.} IP, TCP, UDP, fragmentation, routing, application protocols, and trust zones.
\textbf{Assessment relationship.} It applies foundational protocol auditing to a security control that mediates traffic between trust domains.
\end{CornellOverviewBox}
\section{Learning Objectives}
\begin{itemize}
\item Explain the security significance of proxy versus packet filter.
\item Identify attacker influence and failed assumptions associated with attack surface.
\item Trace security-relevant data or state through proxy firewalls.
\item Evaluate whether controls addressing packet-filtering firewalls preserve the intended invariant.
\item Audit implementation and error paths related to tcp filtering.
\item Distinguish safe and unsafe uses of udp filtering.
\item Diagnose a failure involving ftp and dynamic protocols from concrete evidence.
\item Verify remediation and test coverage for fragmentation.
\end{itemize}

\term{Proxy versus packet filter}\\[-0.1em]{\small How do enforcement models differ?} & A proxy terminates and recreates communication with application awareness, while a packet filter decides using packet or flow metadata. Proxies can validate richer semantics but add code and state; filters are simpler but see less context.\par\smallskip\textbf{Audit move:} Document the layer, state, normalization, and policy data each rule actually uses. \\\hline
\term{Attack surface}\\[-0.1em]{\small Can the firewall itself be attacked?} & Management services, protocol parsers, logging, rule engines, dynamic helpers, and state tables are reachable software. High privilege and network position increase the impact of memory, parsing, or resource flaws.\par\smallskip\textbf{Audit move:} Inventory management and data-plane inputs and minimize enabled helpers. \\\hline
\term{Proxy firewalls}\\[-0.1em]{\small What must an application proxy validate?} & The proxy must parse a complete protocol grammar, enforce policy, and emit an unambiguous normalized representation. Differential interpretation between proxy and destination creates bypasses.\par\smallskip\textbf{Audit move:} Compare proxy acceptance and normalization with backend parsing behavior. \\\hline
\term{Packet-filtering firewalls}\\[-0.1em]{\small Which packet fields drive the decision?} & Address, protocol, port, direction, flags, interface, fragment state, and connection tracking may contribute. Rules that assume unavailable fields or trust spoofable addresses are fragile.\par\smallskip\textbf{Audit move:} Test every rule with fragments, unexpected flags, alternate directions, and spoofed sources. \\\hline
\end{longtable}
\begin{CornellSummaryBox}{Section Summary}
A firewall's assurance depends on which layer it interprets and whether its model matches endpoint behavior.
\end{CornellSummaryBox}

\term{TCP filtering}\\[-0.1em]{\small Can flags approximate connection state safely?} & Rules often infer established traffic from flag patterns, but crafted combinations and asymmetric routing can undermine simple tests. Stateless filters cannot validate sequence-space behavior.\par\smallskip\textbf{Audit move:} Enumerate accepted flag combinations in both directions and test malformed cases. \\\hline
\term{UDP filtering}\\[-0.1em]{\small What does a reply rule mean without state?} & UDP has no handshake, so broad reverse-direction rules can admit unsolicited packets. Source addresses and ports are not reliable identity.\par\smallskip\textbf{Audit move:} Narrow endpoints and use state, authentication, or application mediation where required. \\\hline
\term{FTP and dynamic protocols}\\[-0.1em]{\small Why do embedded addressing and dynamic ports matter?} & Protocols that negotiate data channels force filters to parse application payload or open broad ranges. Active helpers become security-sensitive parsers.\par\smallskip\textbf{Audit move:} Disable unused helpers and validate negotiated addresses, ports, direction, and lifetime. \\\hline
\term{Fragmentation}\\[-0.1em]{\small How can fragments evade packet rules?} & Later fragments may not contain transport headers, while overlapping reassembly can produce different data at the filter and endpoint. Fragment policy must be consistent and bounded.\par\smallskip\textbf{Audit move:} Normalize or reassemble before policy and compare overlap behavior with protected hosts. \\\hline
\end{longtable}
\begin{CornellSummaryBox}{Section Summary}
Stateless rules evaluate packets independently and therefore must handle protocol context conservatively.
\end{CornellSummaryBox}

\term{TCP and UDP state}\\[-0.1em]{\small What constitutes a valid flow?} & TCP tracking should respect transitions and sequence context; UDP tracking commonly uses observed request-response tuples and timers. Loose state can admit unrelated traffic, while tight state can break legitimate recovery.\par\smallskip\textbf{Audit move:} Test unsolicited, out-of-window, reordered, reused-tuple, and timeout-boundary traffic. \\\hline
\term{Directionality}\\[-0.1em]{\small How is initiator direction established?} & Interface, route, first packet, and policy define flow direction. Asymmetric paths or spoofed first packets can confuse rules that assume topology proves identity.\par\smallskip\textbf{Audit move:} Validate state behavior under asymmetric routing and source spoofing. \\\hline
\term{Stateful fragmentation}\\[-0.1em]{\small When is fragment state associated with a flow?} & Fragments may arrive before the first fragment or collide on identifiers. Reassembly caches consume memory and need strict keying, validation, and expiration.\par\smallskip\textbf{Audit move:} Stress fragment caches and verify association uses complete, nonspoofable context where possible. \\\hline
\end{longtable}
\begin{CornellSummaryBox}{Section Summary}
State narrows accepted traffic but creates new tables, timeouts, and protocol models that attackers can manipulate.
\end{CornellSummaryBox}

\subsection{Layering and Spoofing}

\rowcolor{Navy}\color{white}\textbf{Cue / Recall Prompt} & \color{white}\textbf{Technical Notes and Audit Reasoning} \\

\term{Layering issues}\\[-0.1em]{\small Where can two parsers see different traffic?} & Tunnels, encapsulation, normalization, retransmission, overlapping data, and application ambiguity can make the firewall authorize one interpretation while the endpoint processes another.\par\smallskip\textbf{Audit move:} Map every decoding layer and compare normalization and conflict-resolution policies. \\\hline
\term{Distance spoofing}\\[-0.1em]{\small What can forged network identity accomplish?} & Source addresses can often be forged when no response is needed or when routing position permits observation. Address-based trust should be treated as weak authentication.\par\smallskip\textbf{Audit move:} Require cryptographic or application identity for sensitive operations. \\\hline
\term{Local spoofing}\\[-0.1em]{\small Why is an adjacent attacker more capable?} & A nearby attacker may influence address resolution, observe replies, inject traffic, or position itself in the path. Network topology alone does not prove peer identity.\par\smallskip\textbf{Audit move:} Test from local segments and protect neighbor discovery and management planes. \\\hline
\term{Off-path inference}\\[-0.1em]{\small Can remote observations reveal firewall state?} & Timing, identifiers, error behavior, and side channels can let an attacker infer or influence state without direct visibility. Predictable state weakens filtering assumptions.\par\smallskip\textbf{Audit move:} Reduce observable differences and use robust, hard-to-guess state validation. \\\hline
\end{longtable}
\begin{CornellSummaryBox}{Section Summary}
Security controls fail when different layers or devices disagree about the packet, stream, identity, or state being authorized.
\end{CornellSummaryBox}
\begin{CornellLegacyBox}{Historical Context}
Firewall architectures and default normalization have evolved, but parser differential, helper exposure, state exhaustion, and misplaced address trust remain relevant review themes.
\end{CornellLegacyBox}

\section{Chapter Synthesis}
A firewall is a stateful parser and policy engine, not an absolute boundary. Its view must remain consistent with protected endpoints across fragments, streams, tunnels, and application grammar. Prioritize parser exposure, state-table exhaustion, rule paths that trust spoofable identity, and any differential interpretation that lets traffic acquire a safer classification than the endpoint gives it.

\subsection*{Answer Key}
\begin{enumerate}
\item A proxy terminates and recreates communication with application awareness, while a packet filter decides using packet or flow metadata. Proxies can validate richer semantics but add code and state; filters are simpler but see less context.
\item Management services, protocol parsers, logging, rule engines, dynamic helpers, and state tables are reachable software. High privilege and network position increase the impact of memory, parsing, or resource flaws.
\item The proxy must parse a complete protocol grammar, enforce policy, and emit an unambiguous normalized representation. Differential interpretation between proxy and destination creates bypasses.
\item Address, protocol, port, direction, flags, interface, fragment state, and connection tracking may contribute. Rules that assume unavailable fields or trust spoofable addresses are fragile.
\item Rules often infer established traffic from flag patterns, but crafted combinations and asymmetric routing can undermine simple tests. Stateless filters cannot validate sequence-space behavior.
\item UDP has no handshake, so broad reverse-direction rules can admit unsolicited packets. Source addresses and ports are not reliable identity.
\item An attacker may place disallowed transport data in a fragmented datagram that the endpoint reassembles. Normalize or reassemble consistently before policy and apply a conservative fragment rule.
\item The firewall and endpoint authorize different semantics, enabling parser-differential bypass. Reject ambiguity or normalize to one representation whose interpretation matches the backend.
\end{enumerate}
