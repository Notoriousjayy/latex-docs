\section{Objective and environment}
Compare static and dynamic memory-safety evidence using modern C and C++ techniques. All experiments are local and synthetic. Compile the safe companion with a supported compiler, warnings, and sanitizers where available; keep test data non-sensitive.
\section{Exercise C1: Buffer capacity invariant}
Given a destination buffer \(d\) of capacity \(c\), require \(0<c\), data length \(\ell<c\), and a terminator at \(d[\ell]\). A silent truncation contract must be explicit; do not assume \texttt{strncpy} always null-terminates.
\textbf{Risky construction for code-review discussion only:}
\begin{lstlisting}[language=C]
void copy_name(char *dst, const char *input) {
    strcpy(dst, input); /* length/capacity not established */
}
\end{lstlisting}
\textbf{Reference pattern:} \texttt{examples/c/safe\_copy.c} implements checked copying with an explicit capacity and error return. Unit tests cover null pointers, zero capacity, exact fit, oversized input and terminator correctness.
\section{Exercise C2: Integer arithmetic}
Before allocating \(n\times k\) bytes, require \(n\le SIZE\_MAX/k\) for \(k\ne 0\). Test \(n=0,1,SIZE\_MAX/k\), and one exceeding the boundary. Signed-to-unsigned conversion must be validated before calculation.
\begin{lstlisting}[language=C]
if (item_size != 0 && count > SIZE_MAX / item_size)
    return ERROR_OVERFLOW;
size_t bytes = count * item_size;
\end{lstlisting}
\section{Exercise C3: C++ lifetime and containers}
Refactor a manual heap buffer to \texttt{std::vector<std::byte>} or an owning value type; accept a \texttt{std::span} where the caller retains ownership. Explain why a view does not lengthen a resource's lifetime and why an iterator can become invalid after reallocation.
\section{Verification protocol}
\begin{lstlisting}[language=bash]
cc -std=c11 -Wall -Wextra -Wpedantic -Werror \
   -fsanitize=address,undefined -fno-omit-frame-pointer \
   examples/c/safe_copy.c -o safe_copy
./safe_copy
\end{lstlisting}
Compile without sanitizer options if unsupported; record the difference. Compare compiler warnings, a SAST query and sanitizer behavior. Do not claim that a sanitizer's success proves safety for every input or execution path.
\section{Required evidence}
Bounds table, tool/build details, test results, any reproduced diagnostic, a fix change and limitations. Passing requires zero unexpected test failures, documented allocation check and accurate distinction between static and dynamic evidence.
