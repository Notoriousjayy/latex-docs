\section{Objective and environment}
Implement and verify secure input handling, database parameterization, path controls and resource cleanup in Java 17 or later. Use an isolated directory and an ephemeral local database; do not connect examples to production systems. Tool selection: \texttt{javac}, a unit-test runner, and a currently supported SAST analyzer.
\section{Exercise J1: SQL injection as a source-to-sink flow}
\textbf{Anti-pattern for inspection only:}
\begin{lstlisting}[language=Java]
String sql = "SELECT id FROM users WHERE email = '" + email + "'";
// sink: database statement execution
\end{lstlisting}
\textbf{Required correction:}
\begin{lstlisting}[language=Java]
try (PreparedStatement ps = conn.prepareStatement(
         "SELECT id FROM users WHERE email = ?")) {
    ps.setString(1, email);
    try (ResultSet rs = ps.executeQuery()) {
        // consume values without generating SQL text from email
    }
}
\end{lstlisting}
\textbf{Assertions:} benign strings retain their literal meaning; apostrophes and SQL-shaped payloads never change the statement structure; resources close on success and exception paths. \textbf{Taint model:} HTTP user input \(\rightarrow\) controller \(\rightarrow\) SQL API. Parameter binding is the context-specific control.
\section{Exercise J2: Path confinement}
Use the companion \texttt{examples/java/PathGuard.java} as a starting point. Test relative paths, an absolute path, parent traversal, and paths that normalize outside a configured root. Record symbolic-link and race-related residual risks for a hostile filesystem. Do not claim prechecking a path prevents symlink swaps; for untrusted writers, use stronger OS-level or capability-oriented designs.
\section{Exercise J3: Review and scan}
\begin{enumerate}
\item Pin the scan revision. Record JDK, build tool and SAST version.
\item Confirm a vulnerable fixture is located and the proposed secure implementation is not inaccurately flagged.
\item Generate a report and record rule ID, source, sink, trace and confidence.
\item Fix in a separate revision; rerun negative tests and scan; link before/after commits.
\end{enumerate}
\section{Deliverables and pass criteria}
Lab evidence form; tests for ordinary and adversarial inputs; SAST results with at least one explained false-positive candidate; remediation traceability. Pass only when SQL structure is immutable, path checks have a documented filesystem threat model, and failure-path resources close correctly.
