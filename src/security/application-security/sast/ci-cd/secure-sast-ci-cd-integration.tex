\section{Architecture and responsibilities}
Developers receive local IDE/CLI feedback; a restricted pull-request scan checks proposed changes; a trusted default-branch scan runs comprehensive rules; findings are normalized and attributed to owners; exceptions have an expiration. A policy service evaluates reviewer-confirmed impact and historical baseline state. Maintain a separate SCA, secrets and IaC scanning inventory: product bundling does not imply one SAST control covers all categories.
\begin{focusbox}{Trust boundary}
Untrusted PR content, dependencies, build scripts, custom rules and scanner configuration may execute code. Use least privilege, isolated runner context, limited network, verified artifacts, pinned or maintained actions and explicit approval for exposure to secrets or write tokens. Never check out untrusted contributions under privileged \texttt{pull\_request\_target} solely to run a scanner.
\end{focusbox}
\section{Reference workflow designs}
\textbf{CodeQL}: The companion \texttt{examples/workflows/codeql-review.example.yml} illustrates a PR/push matrix for Java, Python and C/C++. It uses CodeQL Action v4 and language-aware build modes. C/C++ may need a project-specific build; \texttt{none} is a coverage trade-off, not equivalent to a complete compilation. Do not enable this illustrative workflow without reviewing repository license/feature eligibility, branch protection and action permissions. If CodeQL default setup is enabled, do not duplicate it unintentionally.

\textbf{Semgrep}: \texttt{examples/workflows/semgrep-review.example.yml} runs a read-only pattern scan, generates JSON/SARIF artifacts and never uploads PR results with write permissions. It intentionally does not rely on cloud-account credentials. Local and CI rule choices, versions, engine and licensing require verification. SARIF upload to GitHub requires a separately designed, appropriately authorized workflow with \texttt{security-events: write} where eligible.
\section{Policy-as-code gates}
\begin{enumerate}
\item Define eligible changes, required analyzers and known excluded modules.
\item Preserve immutable scan output and metadata; distinguish invalid/scanner-failed/no-analysis from a passed result.
\item Compare incoming result fingerprints with a reviewed baseline, then queue high-impact new hypotheses for confirmation.
\item Block according to approved policy (e.g., newly confirmed high impact), and support time-limited exception with approval and compensating controls.
\item Test gating logic using fixtures: new serious finding, inherited finding, false positive, expired exception, scanner outage and upload failure.
\end{enumerate}
\section{Implementation checklist}
\begin{itemize}
\item \checkbox\ Developer commands are documented and reproduce CI scans on a pinned commit.
\item \checkbox\ Tool/ruleset versions and runtime dependencies recorded and updated.
\item \checkbox\ No persistent secrets or elevated tokens granted to untrusted PR code.
\item \checkbox\ Branch protections require selected checks and review; bypass activity is audited.
\item \checkbox\ Findings retain file/rule evidence, assigned owner, classification, due date and closure verification.
\item \checkbox\ Baseline exclusions are narrowly scoped, justified and measurable.
\item \checkbox\ CodeQL default vs advanced setup decision documented; private code-scanning eligibility checked.
\item \checkbox\ Alert categories and SARIF version/limits validated before upload.
\end{itemize}
