\section{Trust-boundary inventory}
\begin{tabularx}{\linewidth}{@{}p{0.28\linewidth}Y@{}}\toprule
Boundary & Abuse scenario and minimal control\\\midrule
PR code to runner & Malicious build scripts steal runner data; sandbox + read-only token + short-lived runner\\
Third-party actions & Compromised release; review provenance, pin to trusted commit where feasible, maintenance policy\\
Scanner plugins/rules & Untrusted extensions execute code; allowlisted trusted rules, minimal network and separate identities\\
Runner to package feeds & Download and install scripts may execute; lockfiles, supported registries and constrained tokens\\
Scan output to dashboard & Crafted SARIF leaks paths or breaks ingestion; validate/redact and restrict access\\
Trusted reporting step & Write token misused through PR code; separate privileged upload from untrusted checkout\\
Policy exception path & Unbounded suppression hides regressions; named approver, justification, expiry and revalidation\\\bottomrule
\end{tabularx}
\section{Adversarial tabletop}
Scenario A: a fork PR changes a build script to print environment variables. Review whether scanner build-mode executes that script, whether credentials exist, and whether caches are shared with privileged workflows. Scenario B: a malicious rule pack modifies output. Review version pinning, artifact hashes and ingestion permissions. Scenario C: an expiring high-risk finding is suppressed by configuration drift. Review diff and independent policy controls.
\section{Required decisions}
Record workflow events, permission scopes, branch restrictions, network egress, language/build mode, source-trust classification, runner isolation, installed extension policy and recovery behavior on scanner failure. Do not define \emph{passed scan} as equivalent to \emph{zero findings}. Document approved risk acceptance explicitly.
