\section{API surface}
\begin{itemize}
\item GET code scanning alerts and alert instances; retain analysis\_key, ref, commit\_sha, tool, rule ID and classifications.
\item GET pull requests, reviews, checks, statuses, effective rulesets and review obligations where accessible.
\item GET delegated dismissal requests with pagination, explicit statuses and organization boundary.
\item PATCH direct code scanning alert requires Code scanning alerts write and authorization.
\item PATCH review of delegated code scanning dismissal requires organization dismissal-request permission and repository alert read plus reviewer eligibility.
\item Handle 403/404/422/429/5xx independently; do not interpret missing permissions as no alerts.
\end{itemize}

\section{Token boundaries}
A read-only collector uses the minimal GitHub App installation permissions needed for specific endpoints. The executor is a separate app/role, cannot run in a fork PR trust context, must not checkout untrusted code with write-capable tokens and must use short-lived installation tokens.

Repository permission alone may not establish organization-level eligibility to review delegated dismissal requests. Verify effective roles and endpoint requirements at deployment.


\section{Event strategy}
\begin{itemize}
\item pull\_request: untrusted contribution data; safe for isolated, low-privilege assessment only.
\item pull\_request\_target: privileged context; do not checkout or execute untrusted head, particularly when tokens are write-capable.
\item workflow\_run: previous workflow outputs are untrusted; re-validate artifact digests and no privileged execution of raw data.
\item workflow\_dispatch: manually initiated after authorization; validate all parameters, actor and head SHA.
\item schedule: read-only reconciliation, coverage and expiration monitoring; do not use as implicit blanket approval.
\end{itemize}

\section{Reliability and audit}
Use ETag/conditional requests, pagination Link headers, bounded retries, 429/secondary limit backoff, idempotency tokens, correlation IDs, optimistic checks against state and head SHA, and after-write observation. Maintain a durable outbox before enabling mutations.


\section{Enterprise variations}
Document GitHub.com versus Enterprise Server feature support and licensing. Delegated code scanning dismissal is available on GHES 3.17+ in current conceptual documentation, but API feature details and GitHub App behavior must be verified for each target release. No edition entitlement is assumed.


\section*{Document status and provenance}
This document is a proposed reference design. Actual GitHub feature availability, organization policies, approvals, and runtime performance must be independently verified before adoption. The architecture inventory is not proof of vulnerability exploitability or correctness of a dismissal.
