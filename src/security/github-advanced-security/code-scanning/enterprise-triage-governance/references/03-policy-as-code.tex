\section{Authority model}
Policy evaluation is advisory until independently approved and connected to GitHub enforcement. The evaluator cannot grant security authority by emitting ALLOW\_MERGE. GitHub remains the final arbiter of merge eligibility.

Policy bundles must be immutable at evaluation, protected from untrusted PR edits, code-reviewed by delegated policy owners and identified by version and digest.


\section{Canonical decisions}
\begin{itemize}
\item ALLOW\_MERGE: no security blocker according to evaluated inputs, subject to all other GitHub controls.
\item FIX\_REQUIRED: confirmed actionable finding or disallowed risk.
\item AUTO\_TRIAGE: safe classification or assignment only; no dismissal implied.
\item EXCEPTION\_CANDIDATE: preliminary matched approval, additional controls still required.
\item DISMISSAL\_REQUEST\_REQUIRED: requester must use delegated workflow.
\item APPSEC\_REVIEW\_REQUIRED: human security validation or delegated review.
\item RISK\_ACCEPTANCE\_REQUIRED: risk-owner signoff outside false-positive route.
\item INSUFFICIENT\_EVIDENCE: absent, conflicting, or stale necessary proof.
\item SCAN\_INCOMPLETE: missing, failed, stale or unfinished required scan.
\item POLICY\_ERROR: invalid/missing policy version or ambiguous evaluation.
\end{itemize}

\section{Rule order and failure behavior}
Process policy and scan integrity before exception scope. Evaluate required alerts and severity without treating medium/low as dismissed. If any required fact is absent, return a blocking abstention. No later lower-priority rule may override incomplete scan or invalid policy.

Evaluation output includes reasons, rule IDs, evidence links, inputs digest, policy digest, issuer, timestamp, and suggested next action. Never store credentials, sensitive source payloads or privileged tokens in public evidence.


\section{Exception comparison}
\begin{itemize}
\item Require exact repository identity, rule identifier, stable fingerprint or approved equivalent, and component.
\item Require approved identity distinct from requester, status approved, effective time and unexpired deadline.
\item Require policy version compatibility, validation evidence, committed source ref and material change checks.
\item Reject unknown, wildcard, stale, unsigned or revoked approvals.
\item Recheck scope and head SHA immediately before future privileged execution.
\end{itemize}

\section{Decision invariants}
\begin{itemize}
\item Severity never independently establishes false positive.
\item String-matching a comment does not establish compensating-control efficacy.
\item Source-code path is not proof of test-only execution.
\item Repeated alerts across repositories do not inherit exceptions.
\item Untrusted AI classification can suggest a review, not authorize a dismissal.
\item A read-only evaluator never calls PATCH endpoints.
\end{itemize}

\section{Policy engine evaluation}
Compare a typed configuration-driven Python evaluator with Rego/Open Policy Agent and CEL. Prefer simple deterministic policy initially to minimize supply-chain surface and keep reproducibility. Record promotion to OPA/CEL in a proposed ADR, including interpreter isolation, policy tests, traceability, and governance.


\section*{Document status and provenance}
This document is a proposed reference design. Actual GitHub feature availability, organization policies, approvals, and runtime performance must be independently verified before adoption. The architecture inventory is not proof of vulnerability exploitability or correctness of a dismissal.
