\section{Developer PR blocked}
Capture repository, PR number, base/head SHA, screenshot or API evidence of blocker, scanner run and relevant alert. Run diagnostic order (review, check, ruleset, queue, request), then remediate or file an evidence-linked request.

Do not ask an automation bot to dismiss a missing scan or failed workflow. Do not force-push or disable required checks as a workaround.


\section{Suspected false positive}
Reproduce rule path and impact, check whether source-to-sink is actually reachable, inspect relevant sanitizer/control and trusted build target, collect evidence from a pinned revision. Document clear alternative explanation and uncertainty.


\section{Request for exception}
Requester supplies technical justification, scope, business owner, compensating control verification where relevant, expiry and ticket. Reviewer validates identity and evidence independently; approve or deny by authorized method.


\section{AppSec queue operations}
Prioritize genuine PR blockers by severity, exposure and review SLA. Use missing/denied metadata bucket to identify coverage gaps rather than marking safe. Notify owner and record next action with deadline.


\section{Direct and delegated review}
When delegated dismissal is active, developers request and reviewers act; do not bypass via direct PATCH. Direct state changes require explicit operational policy and secured review. Save GitHub response and follow-up state evidence.


\section{Reopen and rollback}
If previously dismissed finding is newly exploitable or exception invalid, quarantine related automation, alert owners, and use authorized GitHub reopening procedures. Identify affected branches before claiming closure.


\section{Escalation runbook}
Incident or credential leakage: route to incident response immediately. Unexplained critical alert: AppSec on-call. Missing scanner: DevOps owner. Unknown ownership: governance steward. API authorization error: platform security. Record escalation status and reviewer.


\section{Evidence hygiene}
Avoid storing vulnerable code, real secrets, private source URLs or employee identifiers in public LaTeX. Include artifact identifiers and secure evidence-reference placeholders only.


\section*{Document status and provenance}
This document is a proposed reference design. Actual GitHub feature availability, organization policies, approvals, and runtime performance must be independently verified before adoption. The architecture inventory is not proof of vulnerability exploitability or correctness of a dismissal.
