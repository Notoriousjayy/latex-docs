\section{Scope and intent}
The companion is a policy decision and evidence framework, not a replacement for code scanning or its existing GitHub enforcement. Architecture discovery remains a separate read-only provider. The initial implementation is offline and synthetic; privileged execution is excluded.

\begin{itemize}
\item Business objective: reduce preventable PR delay while preserving independently controlled risk disposition.
\item Threat boundary: untrusted PR data and discovery inferences must never be promoted to approval authority.
\item The merge policy is authoritative at GitHub, not in a companion dashboard or status comment.
\end{itemize}

\section{Logical components}
\begin{itemize}
\item Inventory collector: reads repository inventory, CODEOWNERS, rulesets and scanner coverage with incomplete states.
\item Alert adapter: normalizes CodeQL and third-party SARIF fields, preserves tool versions and analysis refs.
\item Merge-blocker analyzer: distinguishes required reviews, checks, rulesets, queue and unconfigured analysis.
\item Risk enrichment: adds ownership and independently verified exposure with E1/E2/E3 provenance.
\item Policy evaluator: deterministic rule precedence, immutable input envelope and explicit abstentions.
\item Evidence validator and exception register: match independent approval, exact scope and expiry.
\item Delegated request processor and privileged executor: isolated execution and authorization verification.
\item Escalation router, audit ledger, metrics and drift monitor: complete the operational loop.
\end{itemize}

\section{Trust and authority boundaries}
The read-only discovery engine must not possess code-scanning write permissions. Policy definitions are protected assets; developer-submitted PR changes are inputs, never executable policy. A dedicated application boundary with separation of duties owns any future mutation.

Execution must compare current alert state, repository identity, policy version, exception authorization and PR head SHA immediately before a proposed write. A decision generated against an obsolete revision is invalid.


\section{Evidence contract}
\begin{itemize}
\item E1 observed: pinned path, commit, parsed workflow, branch or ruleset, extraction timestamp and tool version.
\item E2 inferred: versioned rule, confidence, unresolved alternatives and explicit non-authoritative status.
\item E3 externally verified: approved ownership, signed exception, deployment/registry attestation or change record.
\item Missing, stale, access-denied, truncated, parse-error and unverified are different states; none may silently become low risk.
\end{itemize}

\section{Failure modes}
\begin{itemize}
\item API rate-limit or access denial: record partial coverage, abstain and notify.
\item Scan missing/in progress: never assert merge readiness or suppress the check.
\item Policy signature mismatch: reject and create incident/operational alert.
\item Exception expiry or head SHA drift: fail the exception match and reevaluate.
\item Unrecognized monorepo component: route to owner reconciliation, not auto-disposition.
\end{itemize}

\section{Deployment options}
Prefer a minimal collector and offline evaluator in the existing Python testing environment. A future least-privileged GitHub App can be independently deployed if policy and security authority are granted; do not assume a serverless or microservice deployment is necessary.


\section{Stage gates}
\begin{itemize}
\item G0 read-only inventory and ownership reconciliation.
\item G1 reproducible offline policy evaluation with negative tests.
\item G2 security review of trust boundaries, roles, API editions and audit ledger.
\item G3 limited nonproduction delegated-request pilot with manual reviewer.
\item G4 controlled production enablement only after independent authorization and rollback drill.
\end{itemize}

\section{Enterprise source-to-decision correspondence contract}
The controlled governance overlay in the adjacent sufficiency folder defines requirement IDs, canonical document custody, integrated contract validation and operational readiness gates. It is not a new authorization service and never overrides the present read-only boundary.

The collector publishes a versioned record with repository stable identity, pinned commit and workflow source URI, extraction rule and collector version, UTC observation time, completeness status, evidence classification and integrity digest. Only E1 facts represent directly observed configuration. E2 records carry uncertainty and explicitly cannot establish runtime reachability or disposition authority. E3 requires external corroboration and a trusted authority record; a joined E2 graph path does not become independently verified merely because a second inference agrees.

A downstream alert adapter must bind the repository node identity, alert instance and rule identity, analysis key, PR head and base revisions, scan completion, effective merge-control categories and policy revision. Missing, stale, truncated, access-denied, parse-error and unsupported observations are distinct. Never equate absence of returned alerts with all scans being complete.

\section{Sufficiency and operating control boundaries}
Architecture review is complete only with a current organization/repository scope, accountable service ownership, approved viewpoint/decision records and independently checked evidence samples. A successful static build does not establish application ownership, API permissions, merge eligibility or a signed risk decision.

Pilot approval additionally requires tested read-only collection, measured baseline, tenant feature verification and reviewed negative cases. Production approval additionally requires a separately authorized privileged executor (if chosen), immutable review/audit trail, retention controls, containment/reopen drill, incident response and change authorization. The companion remains a reference design until those independent checks are evidenced.

The governed crosswalk is maintained as Markdown and CSV in the same suite; actual enterprise identities, API tokens and unredacted findings must remain in authorized private systems.

\section*{Document status and provenance}
This document is a proposed reference design. Actual GitHub feature availability, organization policies, approvals, and runtime performance must be independently verified before adoption. The architecture inventory is not proof of vulnerability exploitability or correctness of a dismissal.
