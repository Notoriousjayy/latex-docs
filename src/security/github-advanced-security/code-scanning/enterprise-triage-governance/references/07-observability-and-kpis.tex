\section{Unit of observation}
Use repository ID + PR number + head SHA + time window for merge blockers; alert ID + instance fingerprint + rule + analysis for findings; request ID for delegated approvals. Avoid double counting across retries.

Retain per-event source, capture timestamp, collection scope, API status, policy version and data completeness.


\section{KPIs}
\begin{itemize}
\item Blocked PR rate = distinct PRs with security blocker / all eligible PRs.
\item Review median and P95 = elapsed time from first actionable request until final security disposition; censor unresolved items separately.
\item Security merge delay = time where security-only controls blocked an otherwise merge-ready PR; report estimation bounds.
\item Auto-triage rate = eligible classifier decisions / total triaged decisions, excluding missing data.
\item Incorrect dismissal rate = validated erroneous automatic dismissals / independently sampled executed automatic dismissals.
\item Reopened rate = reopened code scanning alerts / dismissed alerts for the period.
\item Policy error rate = invalid or unavailable policy decisions / all evaluations.
\item Scanner coverage = repos with complete required analysis / in-scope repos, excluding access-denied separately.
\item Exception freshness = unexpired verified exceptions / all exception matches considered.
\end{itemize}

\section{Quality controls}
Track precision, recall and false-positive rate for both component inference and dismissal eligibility separately. Define human-reviewed adjudication sample and confidence intervals; self-graded automated labels do not establish accuracy.


\section{Experiment design}
Use a four-week baseline and representative pilot, or justify the chosen period with PR volume. Stratify by repository criticality, PR size, language, scanner, baseline severity and historical blocker type. Avoid claiming causality from raw before-after averages.


\section{Alerting}
Alert on unauthorized mutation, unusual dismissal volume, unexpected policy bundle hash, repeated 403/429/5xx, audit write failures, large missing-scan population, SLA breach and exception expiration. Do not alert solely on raw total findings.


\section{Reporting boundaries}
Publish aggregates and sanitized exemplars only. Reconcile counters with GitHub records and enumerate API omissions. Dashboards supplement, rather than replace, GitHub checks and security reviewer authority.


\section*{Document status and provenance}
This document is a proposed reference design. Actual GitHub feature availability, organization policies, approvals, and runtime performance must be independently verified before adoption. The architecture inventory is not proof of vulnerability exploitability or correctness of a dismissal.
