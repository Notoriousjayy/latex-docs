\section{Trust boundaries}
B1 untrusted PRs and CI artifacts; B2 read-only GitHub metadata collectors; B3 policy bundle and exception registry; B4 privileged app token executor; B5 audit/evidence store; B6 organization decision rights.

Protect approval provenance as strongly as the token itself: a valid signature on a bad or forged authorization is not adequate. Require binding between approved exception and current finding.


\section{STRIDE assessment}
\begin{itemize}
\item Spoofing: compromised reviewer identity; require protected identity, scoped role checks and separate approval.
\item Tampering: PR alters policy or evidence; pin policy digest outside PR ref, verify artifact signatures.
\item Repudiation: missing audit record; append-only events with correlation IDs and independently retained responses.
\item Information disclosure: raw code/snippets or org inventory in public log; minimize and redact.
\item Denial of service: API exhaustion, floods and retry storms; bounded concurrency, circuit breakers and queue quotas.
\item Elevation of privilege: untrusted workflow runs with privileged tokens; separate apps and execution boundaries.
\item Confused deputy: inherited permissions from another repository; bind immutable repo ID and installation scope.
\item Replay or TOCTOU: compare revision, exception validity, state and decision at execution time.
\end{itemize}

\section{Risk validation scenarios}
\begin{itemize}
\item Critical finding with valid-looking but forged ticket: must abstain and escalate.
\item Requester attempts self-approval: block regardless of reason.
\item Policy definition changed in PR: ignore untrusted version.
\item Scanner missing or late: no positive policy assertion.
\item Two concurrent reviewers: record conflict and do not double-execute.
\item Cross-branch dismissal impact: require explicit awareness and revalidation before action.
\end{itemize}

\section{Control families}
Map design controls contextually to NIST SP 800-218 SSDF (PW, PS, RV), NIST SP 800-53 (AC, AU, CM, SI families), OWASP SAMM verification/governance, ISO/IEC 27001:2022 Annex A and ISO/IEC 27002. Confirm applicability and exact requirement text with licensed official standards; these are engineering crosswalk suggestions, not certification assertions.


\section{Response and recovery}
Revoke compromised GitHub App credentials, disable privileged executor, preserve protected audit logs, inspect dismissed alerts and restore/reopen incorrect dismissals through authorized operators. Test rollback in a sandbox before production.


\section{Residual risks}
Static analysis is incomplete; discovery inference is not runtime evidence; policy mistakes can affect many repositories. Require sampling, change review, rollout canaries, revalidation and independent periodic assessment.


\section*{Document status and provenance}
This document is a proposed reference design. Actual GitHub feature availability, organization policies, approvals, and runtime performance must be independently verified before adoption. The architecture inventory is not proof of vulnerability exploitability or correctness of a dismissal.
