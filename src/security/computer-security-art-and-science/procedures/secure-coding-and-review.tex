\section{Review scope}
Select the applicable language standard and compiler/interpreter version. For C/C++, define buffer lengths, integer domains, ownership, error handling, lifetime and concurrency; for Python, define input grammar, object authorization, deserialization and subprocess trust.
\section{Security review checklist}
\begin{enumerate}
\item Map untrusted inputs and privileges to explicit sinks.
\item Check that authorization guards are performed server-side on every object/action, including error and cache paths.
\item For pointers and buffers, validate capacity before work, reject overflow, initialize outputs and use one consistent length unit.
\item For parsers, bound recursion, sizes and allocation; reject ambiguous or invalid encodings.
\item For cryptographic code, prefer established library APIs and verify modes, nonces, authenticators, key lifecycle and error handling.
\item Verify sensitive audit data is minimized and secrets are never embedded in logs/tests.
\item Require negative unit tests and independent review of critical branches; capture actual command and exit status.
\end{enumerate}
\section{Finding disposition}
Document rule/reference, exact code revision, attack precondition, failed property, proposed fix, tests, reviewer and accepted exceptions. Do not duplicate the repository's language secure coding documents; link to their normative rules for each language.
