\section{Objective and book anchors}
Read Bishop Chapters 19--22, 25 before execution. This laboratory is an independent application of least-privilege github actions security gate, not a reproduction of a book exercise.
\section{Prerequisites and environment}
Local workflow review. Use synthetic data and an isolated test environment. Never conduct intrusive tests without explicit authorization.
\section{Reproducible steps}
\begin{enumerate}
\item Record source revision, system boundary, test authorization and the specific security property.
\item Inspect \texttt{ci-cd/security-laboratories-github-actions.tex} and write a hypothesis prior to running the procedure.
\item Run the command from the suite root (\texttt{src/security/computer-security-art-and-science}); capture tool versions, exit code and results.
\item Exercise permitted, prohibited and boundary cases; compare expected and actual results.
\item Verify that a deliberate policy regression would be caught by an independent negative test.
\item Use the matching Template--Blank pair to document evidence, owner, reviewer, result and limitation.
\end{enumerate}
\section{Execution recipe}
\begin{viewbox}\raggedright\small\texttt{Review .github/workflows/bishop-security-labs.yml}\end{viewbox}
\section{Original engineering activity}
Review checkout trust, event triggers, permissions, test failure propagation and dependency pinning.
\section{Interpretation and limits}
Workflow execution applies only to repository events; do not expose write credentials or production targets in PR jobs.
\section{Acceptance gate}
The run is complete only when the property, inputs, negative-path result, immutable revision, observed output and residual limitations are independently reviewable. A green test or finite model is not a production assurance certificate.
