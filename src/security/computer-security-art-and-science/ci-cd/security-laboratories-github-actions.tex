\section{Repository-aware integration decision}
The existing \texttt{.github/workflows/latex-ci.yml} builds changed LaTeX roots and delegates to \texttt{\_build-latex.yml}. Do not duplicate compilation or edit the shared build pipeline for these training assets. This suite adds a narrow read-only workflow for executable example code; the existing LaTeX CI handles its \texttt{.tex} documents.
\section{Trust boundaries}
\begin{enumerate}
\item Trigger on pull requests and pushes affecting the suite or its workflow; restrict to read-only \texttt{contents: read}.
\item Use a pinned checkout action, avoid privileged \texttt{pull\_request\_target}, production secrets, credentials and AWS deployment.
\item Run only hermetic Python/C/C++ tests with no network target. Require exit status zero on each step.
\item Keep code scanning, secrets scanning and SCA as separate configured platform controls where available. A documentation sample does not enable commercial GHAS features.
\item Store no customer data or live tokens. When adding evidence artifacts, review retention, sanitization and potential PR code execution risks.
\end{enumerate}
\section{Release gate rule}
Proposed local gate: a failing negative security test blocks the lab change until corrected and reviewed. A pass proves only that the sampled tests completed on the stated runner. Repository-level required status checks and permissions must be configured independently by an authorized maintainer.
