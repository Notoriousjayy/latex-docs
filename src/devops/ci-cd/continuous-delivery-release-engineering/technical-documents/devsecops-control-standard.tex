\section{Purpose and normative status}
This document is an original engineering reference. Statements using "must" or "shall" define recommended controls for adoption after local risk review, not requirements imposed by the Humble--Farley text.


\section{Identity and trust}
\begin{itemize}
\item Use OIDC federation with restrictively scoped role trust, environment protection and minimal job permissions.
\item Build workflows from untrusted pull requests must not hold cloud deployment privilege.
\end{itemize}
\subsection{Verification}
\begin{itemize}
\item Name the accountable owner and expected evidence for each assertion.
\item Demonstrate a negative case or rollback condition, not only the happy path.
\item Record an explicit exception if a control cannot be met.
\end{itemize}


\section{Preventative controls}
\begin{itemize}
\item Required reviews and protected branches; action dependency pinning; IaC scanning; secrets scanning; dependency scanning; code analysis; immutable artifact promotion.
\item Pin third-party GitHub Actions to reviewed full commit SHA in production and maintain update policy.
\end{itemize}

\section{Detective and responsive controls}
\begin{itemize}
\item Security gates create actionable findings with ownership, due dates and documented exceptions.
\item Collect CloudTrail/AWS events, audit log, deployment history, runtime alerts and incident evidence.
\end{itemize}

\section{Exception management}
\begin{itemize}
\item Exception records include control ID, asset, risk, compensating controls, approver, expiration, and retest.
\item High severity findings require predefined ownership and risk tolerance, not silent bypass.
\end{itemize}

\section{Minimum evidence contract}
\begin{itemize}
\item Decision/requirement identifier and current version.
\item Executable configuration or code reference at an immutable revision.
\item Artifact digest or migration ID, pipeline run URL, environment and timestamp.
\item Gate outcome, reviewer identity, exception record if applicable.
\item Post-change observation and recovery evidence.
\end{itemize}

\section{Review prompts}
\begin{itemize}
\item What would invalidate this model under a concurrent deployment?
\item Which checks apply before publication versus at deployment time?
\item What data or side effects can survive rollback?
\item How would an auditor reproduce the decision six months later?
\end{itemize}
