\section{Purpose and normative status}
This document is an original engineering reference. Statements using "must" or "shall" define recommended controls for adoption after local risk review, not requirements imposed by the Humble--Farley text.


\section{Rollout strategies}
\begin{itemize}
\item Blue-green: prepare two environments and switch traffic; canary: shift a controlled fraction; rolling: replace instances incrementally.
\item Use business and technical signals, not only container liveness, to judge impact.
\end{itemize}
\subsection{Verification}
\begin{itemize}
\item Name the accountable owner and expected evidence for each assertion.
\item Demonstrate a negative case or rollback condition, not only the happy path.
\item Record an explicit exception if a control cannot be met.
\end{itemize}


\section{Abort thresholds}
\begin{itemize}
\item Define windows, minimum sample size, error-budget burn, p95/p99 regressions, saturation and incident triggers before rollout.
\item A successful HTTP 200 is necessary but not sufficient for service correctness.
\end{itemize}

\section{Rollback taxonomy}
\begin{itemize}
\item Application revision rollback; traffic shift reversal; feature flag disablement; infrastructure restoration; database forward repair.
\item Each has different prerequisites; runbooks must state dependencies and non-reversible side effects.
\end{itemize}

\section{Response and ownership}
\begin{itemize}
\item Declare release commander, approver, observers, incident lead and communication channels.
\item Freeze automatic promotion on alarm; verify rollback independently and retain evidence.
\end{itemize}

\section{Minimum evidence contract}
\begin{itemize}
\item Decision/requirement identifier and current version.
\item Executable configuration or code reference at an immutable revision.
\item Artifact digest or migration ID, pipeline run URL, environment and timestamp.
\item Gate outcome, reviewer identity, exception record if applicable.
\item Post-change observation and recovery evidence.
\end{itemize}

\section{Review prompts}
\begin{itemize}
\item What would invalidate this model under a concurrent deployment?
\item Which checks apply before publication versus at deployment time?
\item What data or side effects can survive rollback?
\item How would an auditor reproduce the decision six months later?
\end{itemize}
