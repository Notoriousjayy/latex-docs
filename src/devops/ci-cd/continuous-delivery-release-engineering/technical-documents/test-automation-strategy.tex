\section{Purpose and normative status}
This document is an original engineering reference. Statements using "must" or "shall" define recommended controls for adoption after local risk review, not requirements imposed by the Humble--Farley text.


\section{Risk-based partition}
\begin{itemize}
\item Unit tests: fast deterministic logic; contract tests: consumer/provider compatibility; integration: real boundaries; acceptance: externally observable behavior; performance: response budgets; exploratory: unknown risks.
\item Use a risk matrix crossing likelihood, consequence, detectability and environment fidelity.
\end{itemize}
\subsection{Verification}
\begin{itemize}
\item Name the accountable owner and expected evidence for each assertion.
\item Demonstrate a negative case or rollback condition, not only the happy path.
\item Record an explicit exception if a control cannot be met.
\end{itemize}


\section{Design for repeatability}
\begin{itemize}
\item Clock/time randomness are injected or controlled; test data is isolated; retries are diagnostic, not a replacement for root cause analysis.
\item Avoid using production secrets or unmasked user data in fixtures.
\end{itemize}

\section{Gate criteria}
\begin{itemize}
\item Commit gate should be quick; correctness and security are not traded for arbitrary speed.
\item Acceptance gate must report outcome, configuration, tested artifact digest, test data version and link to logs.
\end{itemize}

\section{Coverage beyond line metrics}
\begin{itemize}
\item Prioritize fault injection, boundary conditions, schema compatibility and genuine business scenarios over a single coverage percentage.
\item Quarantined flaky tests require ticket, owner, expiration and restore criteria.
\end{itemize}

\section{Minimum evidence contract}
\begin{itemize}
\item Decision/requirement identifier and current version.
\item Executable configuration or code reference at an immutable revision.
\item Artifact digest or migration ID, pipeline run URL, environment and timestamp.
\item Gate outcome, reviewer identity, exception record if applicable.
\item Post-change observation and recovery evidence.
\end{itemize}

\section{Review prompts}
\begin{itemize}
\item What would invalidate this model under a concurrent deployment?
\item Which checks apply before publication versus at deployment time?
\item What data or side effects can survive rollback?
\item How would an auditor reproduce the decision six months later?
\end{itemize}
