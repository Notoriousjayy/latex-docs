\section{Purpose and normative status}
This document is an original engineering reference. Statements using "must" or "shall" define recommended controls for adoption after local risk review, not requirements imposed by the Humble--Farley text.


\section{Reference stage ordering}
\begin{itemize}
\item source review and commit CI -> build immutable artifact -> verify digest -> acceptance/contract tests -> security and performance gates -> staging -> controlled production promotion -> post-deploy verification.
\item Environment promotion may reconfigure, but must not silently rebuild.
\end{itemize}
\subsection{Verification}
\begin{itemize}
\item Name the accountable owner and expected evidence for each assertion.
\item Demonstrate a negative case or rollback condition, not only the happy path.
\item Record an explicit exception if a control cannot be met.
\end{itemize}


\section{Promotion invariant}
\begin{itemize}
\item The same immutable artifact digest is deployed in each environment. A unique source commit alone does not guarantee artifact identity.
\item Every promotion captures who/what/when/where, policy outcome, image digest or package SHA256, and deployment ID.
\end{itemize}

\section{Gate semantics}
\begin{itemize}
\item Mandatory gates fail closed: invalid signature, absent required test evidence, unexpected severity, policy deny, unauthorized ref, failing health check.
\item Advisory checks may warn but must be classified and governed; skipped mandatory gate is an exception with expiry.
\end{itemize}

\section{Failure and concurrency}
\begin{itemize}
\item On upstream failure cancel or block descendants; do not let a previously green artifact be confused with a new candidate.
\item Serialize production mutation by environment, use scoped locks, and ensure reruns are idempotent.
\end{itemize}

\section{Minimum evidence contract}
\begin{itemize}
\item Decision/requirement identifier and current version.
\item Executable configuration or code reference at an immutable revision.
\item Artifact digest or migration ID, pipeline run URL, environment and timestamp.
\item Gate outcome, reviewer identity, exception record if applicable.
\item Post-change observation and recovery evidence.
\end{itemize}

\section{Review prompts}
\begin{itemize}
\item What would invalidate this model under a concurrent deployment?
\item Which checks apply before publication versus at deployment time?
\item What data or side effects can survive rollback?
\item How would an auditor reproduce the decision six months later?
\end{itemize}
