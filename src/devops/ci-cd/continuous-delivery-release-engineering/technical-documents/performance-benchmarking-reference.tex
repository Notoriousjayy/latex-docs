\section{Purpose and normative status}
This document is an original engineering reference. Statements using "must" or "shall" define recommended controls for adoption after local risk review, not requirements imposed by the Humble--Farley text.


\section{DORA-style delivery measures}
\begin{itemize}
\item Deployment frequency = successful production deployments per unit time; change lead time = elapsed time from committed change to production use.
\item Change failure rate = deployments causing production impairment / deployments; failed-deployment recovery time measured from incident to restoration.
\end{itemize}
\subsection{Verification}
\begin{itemize}
\item Name the accountable owner and expected evidence for each assertion.
\item Demonstrate a negative case or rollback condition, not only the happy path.
\item Record an explicit exception if a control cannot be met.
\end{itemize}


\section{Pipeline measures}
\begin{itemize}
\item Time to first actionable feedback, build duration p50/p95, acceptance stage p95, queue time, test flakiness, retry rate, promotion delay.
\item Use comparable populations and time windows; do not average incomparable services without segmentation.
\end{itemize}

\section{Capacity measures}
\begin{itemize}
\item Record throughput, concurrency, p50/p95/p99 latency, errors, CPU/memory, network, input mix and generator characteristics.
\item Compare baselines on equivalent hardware, dataset, warm-up and load profile; include confidence bands where possible.
\end{itemize}

\section{Governance and misuse}
\begin{itemize}
\item Metrics should expose system bottlenecks, not turn into individual developer performance rankings.
\item Record numerator, denominator, exclusions, source, sampling interval, SLO and data quality.
\end{itemize}

\section{Minimum evidence contract}
\begin{itemize}
\item Decision/requirement identifier and current version.
\item Executable configuration or code reference at an immutable revision.
\item Artifact digest or migration ID, pipeline run URL, environment and timestamp.
\item Gate outcome, reviewer identity, exception record if applicable.
\item Post-change observation and recovery evidence.
\end{itemize}

\section{Review prompts}
\begin{itemize}
\item What would invalidate this model under a concurrent deployment?
\item Which checks apply before publication versus at deployment time?
\item What data or side effects can survive rollback?
\item How would an auditor reproduce the decision six months later?
\end{itemize}
