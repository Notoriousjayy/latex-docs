\section{Purpose and normative status}
This document is an original engineering reference. Statements using "must" or "shall" define recommended controls for adoption after local risk review, not requirements imposed by the Humble--Farley text.


\section{Build once and promote}
\begin{itemize}
\item A build creates a content-addressed digest and metadata; subsequent environments consume the digest, not a mutable tag.
\item Record build inputs, dependency lockfile, compiler/runtime version and reproducibility assumptions.
\end{itemize}
\subsection{Verification}
\begin{itemize}
\item Name the accountable owner and expected evidence for each assertion.
\item Demonstrate a negative case or rollback condition, not only the happy path.
\item Record an explicit exception if a control cannot be met.
\end{itemize}


\section{Supply-chain evidence}
\begin{itemize}
\item Produce provenance or attestations using a trusted builder; generate an SBOM for transparency; perform dependency and container scanning based on the threat model.
\item Attestation is evidence of process, not proof that an artifact is vulnerability-free.
\end{itemize}

\section{Storage policies}
\begin{itemize}
\item Use immutable storage/versioning and narrow publication rights; prohibit mutating released objects in place.
\item Retention covers incident response, rollback horizon, legal requirements, and privacy constraints.
\end{itemize}

\section{Promotion manifest}
\begin{itemize}
\item Fields: source SHA, builder identity, artifact URI and SHA256, SBOM digest, gate results, approved environment, deployment record, and expiry.
\item Verify digest on retrieval and immediately before deployment.
\end{itemize}
\subsection{Verification}
\begin{itemize}
\item Name the accountable owner and expected evidence for each assertion.
\item Demonstrate a negative case or rollback condition, not only the happy path.
\item Record an explicit exception if a control cannot be met.
\end{itemize}


\section{Minimum evidence contract}
\begin{itemize}
\item Decision/requirement identifier and current version.
\item Executable configuration or code reference at an immutable revision.
\item Artifact digest or migration ID, pipeline run URL, environment and timestamp.
\item Gate outcome, reviewer identity, exception record if applicable.
\item Post-change observation and recovery evidence.
\end{itemize}

\section{Review prompts}
\begin{itemize}
\item What would invalidate this model under a concurrent deployment?
\item Which checks apply before publication versus at deployment time?
\item What data or side effects can survive rollback?
\item How would an auditor reproduce the decision six months later?
\end{itemize}
