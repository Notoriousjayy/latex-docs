\section{Scope}
These procedures are new engineering workbooks and metric definitions, not data or numerical thresholds supplied by the 2007 CI book.

\section{Hypothesis and controls}
Examples: cache optimization reduces dependency resolution but not test cost; parallelism reduces wall time while increasing job-minutes. Before measurement, freeze revision, runner image, allocated CPU, dependency set and instrumentation.

\section{Observations}
Record run ID, timestamp, git SHA, event, success state, cold/warm cache status, queue seconds, setup seconds, build seconds, test seconds, security seconds and total seconds. Do not derive elapsed wall time by summing parallel jobs.

\section{Sample size and statistics}
Capture at least ten baseline and ten candidate runs per meaningful environment class as an exercise starting point, not a universal significance guarantee. Report median, p95, dispersion, failure count and uncertainty. Explain whether groups are paired.

\section{Experimental confounders}
Network availability, hosted runner variability, artifact cache eviction, dependency registry latency, system clock, non-deterministic tests, background tasks and CI provider queue policy may dominate differences.

\section{Decision policy}
Accept an optimization only if required checks and their quality are unchanged, failures are not hidden, trust boundaries remain intact and representative percentile gains exceed meaningful noise.

\section{Required evidence}
\begin{itemize}
\item Raw immutable input data and schema
\item Baseline/candidate revision identity and toolchain
\item Summary statistics with declared formulae
\item Risk and confounder narrative
\item Optimization disposition and owner
\end{itemize}
