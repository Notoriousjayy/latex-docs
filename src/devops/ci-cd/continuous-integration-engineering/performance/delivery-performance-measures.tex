\section{Scope}
These procedures are new engineering workbooks and metric definitions, not data or numerical thresholds supplied by the 2007 CI book.

\section{Latency measures}
Pipeline duration p50/p95 is measured from execution start to terminal status; queue time is separately measured from scheduling to execution start. Change lead time is from code commit to production release, not simply CI completion.

\section{Stability measures}
CI first-run pass rate counts first completed attempts for configured scope; flaky-test incidence counts failures attributable to nondeterminism with an evidence policy. Mainline repair time spans first confirmed red required build to verified green.

\section{Deployment measures}
Deployment frequency counts successful production deployments over a reporting period. Change failure rate uses production deployments requiring remediation, rollback or hotfix divided by total production deployments; it must not be conflated with failed PR tests.

\section{Restoration}
Time to restore measures duration from service-impacting incident recognition to recovered service using a stated organizational definition; pipeline red-to-green is a distinct measure.

\section{Governance}
Disclose exclusions, failed/cancelled runs, control group, denominator and observation window. Never optimize a dashboard by skipping slow or security-critical gates.

\section{Required evidence}
\begin{itemize}
\item Raw immutable input data and schema
\item Baseline/candidate revision identity and toolchain
\item Summary statistics with declared formulae
\item Risk and confounder narrative
\item Optimization disposition and owner
\end{itemize}
