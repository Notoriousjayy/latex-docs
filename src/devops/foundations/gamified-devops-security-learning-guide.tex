\section{Executive route map}
\textbf{Objective.} Replace passive tutorial consumption with short challenge loops: attempt, observe, diagnose, fix, test, and document. The original list identifies useful sites but mixes prerequisites and specializations; this guide resolves the ordering.

\begin{notebox}
\textbf{Dependency spine}\\[2pt]
\sffamily\small
Linux + Bash $\longrightarrow$ Git + coding + networking $\longrightarrow$ containers $\longrightarrow$ CI/CD $\longrightarrow$ Kubernetes + IaC $\longrightarrow$ SRE and secure delivery.\\[4pt]
After the spine, pursue in parallel: (a) cloud provider lab; (b) CTF/web/AppSec; (c) SQL/ML/AI safety, using the module prerequisites listed below.
\end{notebox}
\begin{tabularx}{\linewidth}{@{}p{.2\linewidth}p{.23\linewidth}X@{}}
\toprule
\textbf{Stage} & \textbf{Modules} & \textbf{Exit gate}\\\midrule
\textbf{A. Foundations} & M01--M06 & Bash, Git, API, network and query tasks demonstrated.\\
\textbf{B. Delivery} & M07--M11 & Tested containerized service deploys; incident diagnosed using telemetry.\\
\textbf{C. Cloud + flow} & M12--M15 & One provider lab and a documented architecture/strategy decision.\\
\textbf{D. Security} & M16--M20 & Five authorized challenges, reproduced fixes, defended tool use.\\
\textbf{E. Data + synthesis} & M21--M23 & Controlled ML experiments and complete secure-delivery capstone.\\\bottomrule
\end{tabularx}
\textbf{Difficulty:} B = beginner (guided and reproducible); I = intermediate (several services or tools); A = advanced (ambiguous faults, security trade-offs or cross-system failure). These are curriculum ratings, not vendors' difficulty designations.

\textbf{Suggested cadence:} 6--10 focused hours per week; an initial survey of the core sequence fits approximately 20 weeks. Advanced mastery, cloud electives and the capstone may require extra weeks. Modules are gates, not promises of completion by a fixed date.
\section{How the links were audited}
Every original URL was requested individually on 9 October 2026. \textbf{LIVE} means a recognizable destination returned content; \textbf{REDIRECT} means an old address resolved to a different canonical address; \textbf{MOVED} means the prior organization explicitly announced its replacement; \textbf{UNVERIFIED} means access was blocked or timed out. For JavaScript-rendered pages, a successful HTTP response does \emph{not} establish that the full game ran or that a login can be completed. Commercial pricing and quotas may change.

\section{Skill modules and evidence gates}
Each module contains objectives, a challenge and an observable acceptance artifact. A completed website level without engineering evidence counts as \emph{practice}, not module completion.
\Needspace{15\baselineskip}
\begin{skillbox}[title={M01 \quad Linux and shell fundamentals}]
\textbf{Level:} B \quad \textbf{Time:} 6--9 h \quad \textbf{Prerequisites:} None\\
\textbf{Platforms:} \texttt{O01, O02, A01}\par
\textbf{Learning objectives}
\begin{itemize}
\item Navigate the Linux file system and reason about permissions.
\item Search, filter and transform text using pipes and exit codes.
\end{itemize}
\textbf{Applied challenge.} Complete Bandit beginner levels; build a Bash script that diagnoses file ownership, disk use and a missing configuration file.\par
\textbf{Completion evidence.} Versioned script, sample output and six correct checks.\par
\end{skillbox}
\vspace{2.5pt}
\Needspace{15\baselineskip}
\begin{skillbox}[title={M02 \quad Bash automation and Vim editing}]
\textbf{Level:} B-I \quad \textbf{Time:} 4--6 h \quad \textbf{Prerequisites:} M01\\
\textbf{Platforms:} \texttt{O02, O03, A20}\par
\textbf{Learning objectives}
\begin{itemize}
\item Write robust shell functions with quoting and error handling.
\item Edit files quickly with motions, substitutions and undo.
\end{itemize}
\textbf{Applied challenge.} Write a parameterized log parser; test empty input and filenames containing spaces, then repair it using Vim.\par
\textbf{Completion evidence.} Executable script; two failure-mode tests; command cheat sheet.\par
\end{skillbox}
\vspace{2.5pt}
\Needspace{15\baselineskip}
\begin{skillbox}[title={M03 \quad Git collaboration and branching}]
\textbf{Level:} B-I \quad \textbf{Time:} 5--7 h \quad \textbf{Prerequisites:} M01\\
\textbf{Platforms:} \texttt{O04, O05, A04}\par
\textbf{Learning objectives}
\begin{itemize}
\item Distinguish commit, branch, merge, rebase and remote.
\item Use reviews and clean history to ship a change safely.
\end{itemize}
\textbf{Applied challenge.} Solve Git Branching exercises; open a pull request with deliberate merge conflict and resolve it.\par
\textbf{Completion evidence.} Merged pull request, conflict notes and visual branch graph.\par
\end{skillbox}
\vspace{2.5pt}
\Needspace{15\baselineskip}
\begin{skillbox}[title={M04 \quad Programming with Python and JavaScript}]
\textbf{Level:} B-I \quad \textbf{Time:} 8--12 h \quad \textbf{Prerequisites:} M02, M03\\
\textbf{Platforms:} \texttt{O16, O17, A20, A21, A22}\par
\textbf{Learning objectives}
\begin{itemize}
\item Write tests around data parsing and API requests.
\item Use functions, exceptions and dependency pinning effectively.
\end{itemize}
\textbf{Applied challenge.} Implement the same event-filtering tool in Python and JavaScript; validate malformed and oversized events.\par
\textbf{Completion evidence.} Two implementations, automated tests, dependency manifest.\par
\end{skillbox}
\vspace{2.5pt}
\Needspace{15\baselineskip}
\begin{skillbox}[title={M05 \quad Networking, DNS and HTTP}]
\textbf{Level:} B-I \quad \textbf{Time:} 5--7 h \quad \textbf{Prerequisites:} M01, M04\\
\textbf{Platforms:} \texttt{A01, A03}\par
\textbf{Learning objectives}
\begin{itemize}
\item Explain DNS, TCP, TLS, HTTP methods and status codes.
\item Troubleshoot network failures using evidence rather than guesses.
\end{itemize}
\textbf{Applied challenge.} Break name resolution or an HTTP endpoint in an isolated sandbox; restore service and explain root cause.\par
\textbf{Completion evidence.} Troubleshooting timeline; DNS/TLS/HTTP evidence.\par
\end{skillbox}
\vspace{2.5pt}
\Needspace{15\baselineskip}
\begin{skillbox}[title={M06 \quad SQL and relational data}]
\textbf{Level:} B-I \quad \textbf{Time:} 5--8 h \quad \textbf{Prerequisites:} M04\\
\textbf{Platforms:} \texttt{O18, O19, A15, A16, A17}\par
\textbf{Learning objectives}
\begin{itemize}
\item Use SELECT, JOIN, GROUP BY and parameterized queries.
\item Explain why untrusted strings must not be concatenated into SQL.
\end{itemize}
\textbf{Applied challenge.} Finish SQLBolt and a mystery scenario; write five analytical queries and a parameterized lookup.\par
\textbf{Completion evidence.} Queries, expected outputs, schema diagram and injection test.\par
\end{skillbox}
\vspace{2.5pt}
\Needspace{15\baselineskip}
\begin{skillbox}[title={M07 \quad Docker and container fundamentals}]
\textbf{Level:} I \quad \textbf{Time:} 7--10 h \quad \textbf{Prerequisites:} M04, M05\\
\textbf{Platforms:} \texttt{O07, A02, A01}\par
\textbf{Learning objectives}
\begin{itemize}
\item Build small reproducible container images.
\item Manage ports, volumes, runtime identity and image updates.
\end{itemize}
\textbf{Applied challenge.} Containerize the API and its database; run as non-root and use a healthcheck.\par
\textbf{Completion evidence.} Dockerfile, compose configuration, image build and tests.\par
\end{skillbox}
\vspace{2.5pt}

\section{Capstone blueprint and acceptance criteria}
\begin{notebox}
\textbf{Reference scenario:} An intentionally small ``Incident Ledger'' API accepts synthetic events, stores records in PostgreSQL, and offers authenticated read/write endpoints. All records are invented; use disposable credentials and a personal sandbox. The secure delivery system is more important than the application features.
\end{notebox}
\subsection{Implementation milestones}
\begin{enumerate}
\item \textbf{Repository:} README, architecture context diagram, threat model, licensing and pinned dependencies.
\item \textbf{API and tests:} Request validation, parameterized persistence and 80\%+ branch coverage on security-critical code (curriculum target, not industry threshold).
\item \textbf{Build pipeline:} Tests, dependency checks, CodeQL where applicable, secret scanning, artifact provenance, and no hardcoded credentials.
\item \textbf{Containers and deployment:} Non-root runtime, minimal base image, immutable image reference, readiness/liveness probes, resource limits and basic NetworkPolicy.
\item \textbf{Environment lifecycle:} Plan/review/apply/destroy, least-privilege cloud access, budget alerts, and an emergency teardown procedure.
\item \textbf{Observability:} Request metrics, correlated logs, trace propagation, one explicit SLI, and an alert verified to fire and clear.
\item \textbf{Security validation:} Reproduce one safe vulnerability in a disposable branch, write a failing regression test, fix it, rerun the scan, and document disposition.
\item \textbf{Failure exercise:} Trigger service degradation, identify contributing signals, restore service, and publish a concise blameless postmortem.
\end{enumerate}

\section{Practice safety, licensing and cost controls}
\begin{itemize}
\item Perform offensive exercises \textbf{only} in vendor-provided labs, intentionally vulnerable local workloads, or infrastructure for which you have explicit authorization. Never scan production applications just to complete a game.
\item Treat untrusted prompts, files, websites and tool outputs as adversarial during AI-security exercises. Use synthetic data; restrict agent permissions; require approval before external writes.
\item Scope cloud labs to disposable accounts/projects, configure spending alerts, avoid public exposure, and destroy resources at the end. ``Free training'' does not necessarily mean free cloud infrastructure.
\item Use personal training repositories, not proprietary source code. Never commit working tokens, cloud keys, customer information or sensitive logs.
\item Some platforms require an account, JavaScript, a download, a paid license, or extra compute. Verify access and current pricing immediately before beginning a module.
\end{itemize}
