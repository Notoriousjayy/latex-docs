\section{Experimental question}
Record a falsifiable claim: for example, naive CYK recognition on a fixed CNF grammar should exhibit growth consistent with cubic work in a chosen family of valid inputs. It is not enough to assert a theoretical complexity based on noisy wall-clock observations. Different grammars and implementation techniques can change coefficients and practical crossover points.\PTSource{Chapters 3--4, 7--9, 14; reproducible engineering procedure is independent of the book.}
\section{Workload design}
Freeze grammar and tokenization rules; generate accepted and rejected cases independently; capture the PRNG seed, distributions, input sizes, and whether results include AST or forest construction. Include deeply nested, ambiguous, repetitive, random and boundary inputs. One input shape is not representative of all distributions.
\section{Environment and correctness gate}
Record CPU, memory, OS, interpreter/compiler, flags, available cores and load. Run the correctness suite before timing, include a baseline implementation, and record failures separately. When comparing C++ and Python, separate language/runtime overhead from algorithmic performance claims.
\section{Collection and summaries}
Use a monotonic high-resolution timer, a nontrivial warmup, repeat independent measurements, save unaggregated timings and peak RSS where available. Prefer median and dispersion (e.g. IQR); preserve outliers with reasoned annotations. Record timeout or memory-capped runs as censored failures, not zero timings.
\section{Complexity and scaling analysis}
For fixed grammar $G$, calculate the ratio $T(2n)/T(n)$ under matched work; interpret $\log_2$ of the ratio cautiously. Cubic behavior can show ratios approaching 8 when the cubic term dominates. The fitted slope is not a complexity proof, particularly on small or caching-dominated data.
\section{Reproducibility bundle}
Publish input generator with seed, raw CSV, grammar version, code SHA, environment manifest, warmup/repeats, test command, analysis and explicit limitations. Never invent sample measurements.\section{Review gates}
Correctness before performance; no silently dropped failures; no cross-parser comparisons with different structural output obligations; full data provenance and no unsupported asymptotic claims.
