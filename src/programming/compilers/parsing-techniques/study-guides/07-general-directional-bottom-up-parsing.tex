\section{Chapter orientation}
This guide follows Chapter 7 of Grune and Jacobs, \emph{Parsing Techniques: A Practical Guide}, second edition. Printed pages 199--234. The focus is on reconstructing the chapter's reasoning, verifying explicit assumptions, and translating its central idea into a controlled engineering experiment. This is an independently authored learning guide, not a substitute for the book.

\section{Learning objectives}
\begin{enumerate}
\item Define and differentiate backtracking shift/reduce using a small grammar and its accepted language.
\item Define and differentiate earley prediction, scanning, completion using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating nullable productions.
\item Evaluate the operational constraints of chart parsing and agendas and retain reproducible evidence.
\end{enumerate}
\section{Core topics and review questions}
\subsection{Backtracking shift/reduce}
Write the exact input domain, grammar assumptions, data structures and observable outputs. Distinguish a mathematical language property from the behavior of one implementation.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Earley prediction, scanning, completion}
Construct two contrasting examples. Give a complete trace of states or sentential forms and indicate the condition under which the process halts.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?

Identify a counterexample, ambiguity, cycle or boundary condition; explain whether it is a grammar property, an algorithm limitation, or an implementation bug.

State the cost model, failure modes and evidence needed for a defensible design choice. Do not extrapolate results beyond the grammar family studied.

\section{Technical deep dive: Earley chart invariants}
Represent an item as $[A\to\alpha\bullet\beta,i]$ in chart $j$. Its meaning is that the grammar can derive the input slice $w[i:j]$ from $\alpha$ while $\beta$ remains expected. Prediction expands the next nonterminal at position $j$, scanning consumes a matching terminal, and completion advances a waiting item from the completed rule's origin. Deduplicate items at each position. Nullable symbols require care when a completion and its waiting item appear in either processing order; tests must cover both.
\section{Worked reasoning prompt}
Trace Earley items for $S\to aSb\mid\epsilon$ and input $aabb$. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Implement an Earley recognizer and compare its acceptance results with CYK for a compatible grammar. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
Deduplicate items and terminate closure correctly for nullable cycles. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
