This guide follows Chapter 12 of Grune and Jacobs, \emph{Parsing Techniques: A Practical Guide}, second edition. Printed pages 401--424. The focus is on reconstructing the chapter's reasoning, verifying explicit assumptions, and translating its central idea into a controlled engineering experiment. This is an independently authored learning guide, not a substitute for the book.

\section{Learning objectives}
\begin{enumerate}
\item Define and differentiate suffix grammars using a small grammar and its accepted language.
\item Define and differentiate general substring methods using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating linear-time ll/lr suffix methods.
\item Evaluate the operational constraints of substring recognition constraints and retain reproducible evidence.
\end{enumerate}

\section{Technical deep dive: substrings with syntax context}
Ordinary substring matching answers whether bytes or tokens occur contiguously. Grammar-aware substring parsing asks whether an observed fragment is embeddable in a valid sentence, which may require possible left and right contexts. Compare full sentence membership, prefix membership and interior substring membership for a grammar that imposes delimiters. An implementation must specify whether token boundaries are fixed and whether a substring may start within a token.
\section{Worked reasoning prompt}
Contrast full-input recognition with recognizing whether a fragment occurs inside a valid sentence. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Specify a substring query API and construct fixtures for full matches, prefixes, suffixes and true interior fragments. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
A generic substring search on raw bytes does not establish grammatical context. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
