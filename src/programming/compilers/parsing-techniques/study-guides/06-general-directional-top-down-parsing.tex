\section{Chapter orientation}
This guide follows Chapter 6 of Grune and Jacobs, \emph{Parsing Techniques: A Practical Guide}, second edition. Printed pages 165--198. The focus is on reconstructing the chapter's reasoning, verifying explicit assumptions, and translating its central idea into a controlled engineering experiment. This is an independently authored learning guide, not a substitute for the book.

\section{Learning objectives}
\begin{enumerate}
\item Define and differentiate pushdown automata using a small grammar and its accepted language.
\item Define and differentiate breadth/depth-first search using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating left recursion and its elimination.
\item Evaluate the operational constraints of recursive descent and definite clause grammars and retain reproducible evidence.
\end{enumerate}
\section{Core topics and review questions}
\subsection{Pushdown automata}
Write the exact input domain, grammar assumptions, data structures and observable outputs. Distinguish a mathematical language property from the behavior of one implementation.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Breadth/depth-first search}
Construct two contrasting examples. Give a complete trace of states or sentential forms and indicate the condition under which the process halts.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Left recursion and its elimination}
Identify a counterexample, ambiguity, cycle or boundary condition; explain whether it is a grammar property, an algorithm limitation, or an implementation bug.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?

\section{Technical deep dive: top-down recursion}
A naive recursive-descent procedure for $E\to E+t\mid t$ calls itself before consuming input and may fail to terminate. Replace immediate left recursion with $E\to tE'$, $E'\to +tE'\mid\epsilon$ for an equivalent language. To preserve left-associative AST construction, accumulate the repeated additions in an iterative fold rather than mechanically reproducing the new right-branching grammar shape. A parse method must make progress or advance a bounded explicit state.
\section{Worked reasoning prompt}
Rewrite $E\to E+t\mid t$ as $E\to tE\prime$, $E\prime\to +tE\prime\mid\epsilon$. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Implement a recursive-descent expression recognizer and demonstrate its behavior on a left-recursive grammar. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
Elimination preserves the language but may change tree shape and semantic action placement. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
