\section{Chapter orientation}
This guide follows Chapter 17 of Grune and Jacobs, \emph{Parsing Techniques: A Practical Guide}, second edition. Printed pages 545--574. The focus is on reconstructing the chapter's reasoning, verifying explicit assumptions, and translating its central idea into a controlled engineering experiment. This is an independently authored learning guide, not a substitute for the book.

\section{Learning objectives}
\begin{enumerate}
\item Define and differentiate parser selection using a small grammar and its accepted language.
\item Define and differentiate table-driven versus compiled designs using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating general context-free parser construction.
\item Evaluate the operational constraints of compression, code-generation and logic applications and retain reproducible evidence.
\end{enumerate}
\section{Core topics and review questions}
\subsection{Parser selection}
Write the exact input domain, grammar assumptions, data structures and observable outputs. Distinguish a mathematical language property from the behavior of one implementation.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Table-driven versus compiled designs}
Construct two contrasting examples. Give a complete trace of states or sentential forms and indicate the condition under which the process halts.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{General context-free parser construction}
Identify a counterexample, ambiguity, cycle or boundary condition; explain whether it is a grammar property, an algorithm limitation, or an implementation bug.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Compression, code-generation and logic applications}
State the cost model, failure modes and evidence needed for a defensible design choice. Do not extrapolate results beyond the grammar family studied.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\section{Technical deep dive: end-to-end compiler seams}
The lexer classifies bytes or decoded characters into located tokens; the parser builds syntax and AST structure; semantic passes bind names and validate contextual rules; IR/code generation operates only on validated structures. Tests at each boundary must confirm that source offsets and error categories survive transformations. Compare interpreter-based and table-driven recognition only on equivalent work. Avoid evaluating or compiling untrusted source as a side effect of parsing it.
\section{Worked reasoning prompt}
Compare a recursive-descent implementation with a table-driven recognizer for the same token grammar. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Produce a parser-engineering specification with APIs, error contracts, AST ownership, tests and performance targets. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
The book surveys parser-writing methods; modern library recommendations are an independent extension. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
