\section{Chapter orientation}
This guide follows Chapter 3 of Grune and Jacobs, \emph{Parsing Techniques: A Practical Guide}, second edition. Printed pages 61--102. The focus is on reconstructing the chapter's reasoning, verifying explicit assumptions, and translating its central idea into a controlled engineering experiment. This is an independently authored learning guide, not a substitute for the book.

\section{Learning objectives}
\begin{enumerate}
\item Define and differentiate parse trees and ambiguity using a small grammar and its accepted language.
\item Define and differentiate top-down versus bottom-up using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating nondeterministic automata.
\item Evaluate the operational constraints of parse forests and transitive closure and retain reproducible evidence.
\end{enumerate}
\section{Core topics and review questions}
\subsection{Parse trees and ambiguity}
Write the exact input domain, grammar assumptions, data structures and observable outputs. Distinguish a mathematical language property from the behavior of one implementation.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Top-down versus bottom-up}
Construct two contrasting examples. Give a complete trace of states or sentential forms and indicate the condition under which the process halts.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Nondeterministic automata}
Identify a counterexample, ambiguity, cycle or boundary condition; explain whether it is a grammar property, an algorithm limitation, or an implementation bug.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Parse forests and transitive closure}
State the cost model, failure modes and evidence needed for a defensible design choice. Do not extrapolate results beyond the grammar family studied.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\section{Technical deep dive: parse ambiguity and representations}
For $E\to E+E\mid E*E\mid n$, $n+n*n$ has an addition-at-root tree and a multiplication-at-root tree. Two different expansion orders for the same tree do not establish ambiguity. A shared packed parse forest factors repeated subtrees and records alternative derivations with explicit choice nodes. Recognition complexity must not be confused with the potentially exponential number of full trees obtained by enumerating the forest.
\section{Worked reasoning prompt}
For $E\to E+E\mid E*E\mid n$, compare two parses of $n+n*n$. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Draw two parse trees; design a shared parse-forest representation and acceptance criterion. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
Show a string accepted by the grammar with more than one tree, not merely two derivation orders. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
