\section{Chapter orientation}
This guide follows Chapter 11 of Grune and Jacobs, \emph{Parsing Techniques: A Practical Guide}, second edition. Printed pages 381--400. The focus is on reconstructing the chapter's reasoning, verifying explicit assumptions, and translating its central idea into a controlled engineering experiment. This is an independently authored learning guide, not a substitute for the book.

\section{Learning objectives}
\begin{enumerate}
\item Define and differentiate generalized lr using a small grammar and its accepted language.
\item Define and differentiate graph-structured stacks using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating generalized ll.
\item Evaluate the operational constraints of ambiguity and shared parse forests and retain reproducible evidence.
\end{enumerate}
\section{Core topics and review questions}
\subsection{Generalized LR}
Write the exact input domain, grammar assumptions, data structures and observable outputs. Distinguish a mathematical language property from the behavior of one implementation.

\subsection{Graph-structured stacks}

\section{Technical deep dive: retaining nondeterministic alternatives}
Generalized LR may fork on a table conflict and later merge compatible configurations in a graph-structured stack, avoiding needless replication of common prefixes. Generalized LL likewise records continuations and manages recursion without a single fixed deterministic prediction. Recognizing a word, building a packed forest, and enumerating every derivation have different output-size obligations. Include a deliberately ambiguous input and count alternative structures separately from distinct chart states.
\section{Worked reasoning prompt}
Analyze two branches created by a conflict in an ambiguous expression grammar. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Design branch-merging and shared-forest invariants; implement a bounded demonstration or compare an existing tool. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
Grammar size, degree of ambiguity, forest construction and worst-case behavior all matter. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
