The focus is on reconstructing the chapter's reasoning, verifying explicit assumptions, and translating its central idea into a controlled engineering experiment. \section{Learning objectives}
\begin{enumerate}
\item Define and differentiate languages as infinite sets using a small grammar and its accepted language.
\item Define and differentiate formal grammars and derivations using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating chomsky hierarchy.
\item Evaluate the operational constraints of grammar hygiene and semantics and retain reproducible evidence.
\end{enumerate}

\section{Technical deep dive: fixed points and grammar sanitation}
Productivity is computed by monotone iteration. Start with nonterminals having a terminal-only or empty right-hand side; repeatedly add $A$ when some $A\to\alpha$ uses only terminals and known productive nonterminals. Reachability is a separate traversal from $S$ through referenced nonterminals. A rule can be reachable but nonproductive, or productive but unreachable. Nullability similarly forms a least fixed point. State and prove termination from finiteness of the nonterminal universe.
\section{Worked reasoning prompt}
For $S\to aSb\mid\epsilon$, derive $aabb$ and justify the language $\{a^nb^n:n\geq0\}$. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Implement a reachability and productivity pass over nonterminals; report unused productions. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
Distinguish generating a sentence from deciding membership; include a nonproductive or unreachable symbol. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
