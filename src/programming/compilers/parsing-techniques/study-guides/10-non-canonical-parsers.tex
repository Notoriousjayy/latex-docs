\section{Chapter orientation}
This guide follows Chapter 10 of Grune and Jacobs, \emph{Parsing Techniques: A Practical Guide}, second edition. Printed pages 343--380. The focus is on reconstructing the chapter's reasoning, verifying explicit assumptions, and translating its central idea into a controlled engineering experiment. This is an independently authored learning guide, not a substitute for the book.

\section{Learning objectives}
\begin{enumerate}
\item Define and differentiate left-corner parsing using a small grammar and its accepted language.
\item Define and differentiate deterministic cancellation using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating total precedence and nslr.
\item Evaluate the operational constraints of partitioned and noncanonical derivation orders and retain reproducible evidence.
\end{enumerate}
\section{Core topics and review questions}
\subsection{Left-corner parsing}
Write the exact input domain, grammar assumptions, data structures and observable outputs. Distinguish a mathematical language property from the behavior of one implementation.

\section{Technical deep dive: what noncanonical changes}
Canonical derivation restrictions constrain when a constituent is committed. Left-corner methods use evidence from an observed left corner while retaining top-down expectations, and partitioning or cancellation changes the order and scope of decisions. Compare the parser's permitted intermediate structures to those of strict leftmost or rightmost derivations. Avoid conflating noncanonical order with acceptance of languages outside the supported grammar family.
\section{Worked reasoning prompt}
Compare a left-corner recognition trace to a conventional top-down trace for a tiny grammar. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Write a comparison report identifying which derivation restrictions are relaxed and what is recovered. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
Noncanonical derivation order is not interchangeable with nondeterminism or error recovery. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
