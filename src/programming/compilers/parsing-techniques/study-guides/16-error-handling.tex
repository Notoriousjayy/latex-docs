\section{Learning objectives}
\begin{enumerate}
\item Define and differentiate detection versus recovery versus correction using a small grammar and its accepted language.
\item Define and differentiate global, regional and local methods using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating panic-mode and follow recovery.
\item Evaluate the operational constraints of minimum-cost correction and diagnostics and retain reproducible evidence.
\end{enumerate}

\section{Technical deep dive: recovery is a policy choice}
A syntax error can be detected at the first point where no valid parser transition exists, but that point need not be the true location of the original mistake. Panic-mode recovery skips tokens until a synchronization set; FOLLOW-based synchronization may be appropriate at selected nonterminal boundaries. A proposed insertion is correction, not merely recovery. Define maximum skipped tokens and error count, retain the original invalid source, and prohibit code execution from a recovered tree without explicit authorization.
\section{Worked reasoning prompt}
For a missing closing parenthesis, distinguish detection, synchronization, and a proposed insertion. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Define diagnostic quality metrics and regression tests for three syntactic fault classes. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
Recovered output is not necessarily safe to execute or compile; errors should remain explicit. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
