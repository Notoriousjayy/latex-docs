\section{Chapter orientation}
This guide follows Chapter 5 of Grune and Jacobs, \emph{Parsing Techniques: A Practical Guide}, second edition. Printed pages 137--164. The focus is on reconstructing the chapter's reasoning, verifying explicit assumptions, and translating its central idea into a controlled engineering experiment. This is an independently authored learning guide, not a substitute for the book.

\section{Learning objectives}
\begin{enumerate}
\item Define and differentiate regular language applications using a small grammar and its accepted language.
\item Define and differentiate finite-state recognizers using a small grammar and its accepted language.
\item Construct an example or counterexample illustrating regular-expression conversions.
\item Evaluate the operational constraints of automaton minimization and retain reproducible evidence.
\end{enumerate}
\section{Core topics and review questions}
\subsection{Regular language applications}
Write the exact input domain, grammar assumptions, data structures and observable outputs. Distinguish a mathematical language property from the behavior of one implementation.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Finite-state recognizers}
Construct two contrasting examples. Give a complete trace of states or sentential forms and indicate the condition under which the process halts.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Regular-expression conversions}
Identify a counterexample, ambiguity, cycle or boundary condition; explain whether it is a grammar property, an algorithm limitation, or an implementation bug.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\subsection{Automaton minimization}
State the cost model, failure modes and evidence needed for a defensible design choice. Do not extrapolate results beyond the grammar family studied.
\textbf{Self-test:} Which invariant or decision criterion makes this topic precise, and what input would falsify an incorrect implementation?
\section{Technical deep dive: determinization}
For NFA state set $Q$ with epsilon moves, DFA subset states are epsilon closures of reachable NFA subsets. The DFA start state is the closure of the NFA start state; a subset is accepting if it intersects the NFA final-state set. For a single input symbol $a$, transition to the closure of all NFA $a$-successors. Constructing only reachable subsets avoids enumerating all $2^{|Q|}$ theoretical subsets in many practical instances, but worst-case exponential subset growth remains possible.
\section{Worked reasoning prompt}
Construct a DFA for decimal integers with an optional leading sign. Derive each intermediate state by hand; write the invariant that justifies advancing to the next state. Identify the accepted result and one structurally similar rejected result.
\section{Implementation and laboratory assignment}
Produce state transition tables and acceptance tests including empty and truncated prefixes. Record the grammar, input corpus, expected outputs, maximum input size and a regression test for the principal failure mode. For each test, independently justify the expected result rather than reading it from the program.
\section{Failure analysis and technical discussion}
Do not use a regular expression to model arbitrarily nested parentheses. Explain how your implementation would detect the failure and which diagnostics can distinguish grammar invalidity from resource exhaustion.
\section{Evidence checklist}
\begin{itemize}
\item Grammar and accepted-language specification with version and fixtures.
\item Hand-executed trace and implementation trace for the same accepted and rejected cases.
\item At least one adversarial or boundary input and an explanation of the expected behavior.
\item Correctness argument, complexity claim with assumptions, and unit-test output.
\item Cross-reference to a related chapter and one explicit unresolved question.
\end{itemize}
\section{Independent examination}
\begin{enumerate}
\item Explain the algorithm without using implementation-language details.
\item Give a proof sketch or invariant for acceptance and termination on the specified grammar class.
\item Change one grammar rule and predict which tests must change before running them.
\item Compare behavior on malformed input, ambiguous input, and input beyond configured resource limits.
\end{enumerate}
