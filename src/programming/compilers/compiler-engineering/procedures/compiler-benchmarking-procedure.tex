\section{Purpose and entry criteria}
Performance measurements are comparative experiments, not performance claims.
	extbf{Entry:} immutable revision, defined compiler semantics, reproducible test command, reviewer.

\section{Controlled procedure}
\begin{enumerate}
\item \textbf{Measurement question}: Define compilation speed, emitted-code runtime, peak RSS, binary size or throughput; do not mix metrics.
\item \textbf{Workloads and equivalence}: Fix input sizes, seed, semantic oracle, optimization flags, architecture and toolchain.
\item \textbf{Environment}: Capture CPU model, OS, thermal/frequency policy, scheduler load, compiler versions.
\item \textbf{Sampling}: Warm appropriately; collect >= 10 repetitions, report distribution and outliers; randomize or alternate experiment order.
\item \textbf{Analysis}: Compute median, variability, speedup baseline/new, confidence caveats; compare equivalent workloads only.
\item \textbf{Regression gate}: Require functional success; define threshold, rerun criteria and rollback owner.
\end{enumerate}

\section{Failure handling}
On an unexpected crash, semantic mismatch, excessive memory or missed test gate: stop release eligibility, capture a minimized reproducer, isolate tooling, and review the root cause. Never classify a speedup as acceptable if the transformation is incorrect.
