\section{Laboratory execution contract}
Every laboratory follows: input specification $\rightarrow$ correctness hypothesis $\rightarrow$ independent implementation $\rightarrow$ tests $\rightarrow$ cost derivation $\rightarrow$ benchmark $\rightarrow$ review. Run tests before any timing measurement. A sample implementation is supplied under the package's \texttt{code/} directory to serve as an oracle for small inputs; learners should implement their own solution before consulting it.
\section{Language-specific conventions}

Use Python 3.11+ type hints, deterministic \texttt{random.Random(seed)} only where an experiment requires simulation, clear mutation boundaries and \texttt{unittest} for regression. Distinguish algorithm cost from Python object allocation overhead and interpreter startup. Do not use wall-clock time for extremely short single invocations; time batches and report median nanoseconds per operation.
\section{Laboratory 01: Container and invariant engineering}
\SourceNote{Vol. 1, Ch. 2.}
\subsection{Goal and specification}
Implement a fixed-capacity ring buffer. Make full and empty explicit; do not rely on default overwriting.
\subsection{Required experiment}
\begin{enumerate}
\item Define input domain, output, three preconditions and a state invariant or canonical witness checker.
\item Write an implementation without adopting the other language's data representation by default.
\item Produce adversarial input families and one independent small-instance oracle.
\item Capture a resource model and a representative benchmark trace with raw samples.
\end{enumerate}
\subsection{Mandatory test cases}
Empty, singleton, wraparound, capacity-one, alternating enqueue/dequeue.
\subsection{Measurement focus}
Operations, allocations, max occupancy and failure handling.
\subsection{Exit gate}
Provide a reproducible invocation, version identifiers, passing automated tests, analytical complexity and an explicit explanation for any divergence between measured and predicted behavior.
