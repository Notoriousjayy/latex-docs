\section{How to use the registry}
\Provenance
\begin{groundedbox}The exact \textbf{107 pattern identifiers and names} in groups A--M below follow the Pearson/InformIT second-edition contents [B1]. The one-sentence interpretations and tests under each title are \textbf{new guidance}, not abstracts or quotations from the patterns' text.\end{groundedbox}
\begin{modernbox}Use each row as a starting hypothesis. Before implementation, validate its user context, business purpose, accessibility, attack surface, system dependencies and measurable success criteria.\end{modernbox}
\textbf{Record format:} source pattern identifier/title $\rightarrow$ modern engineering application $\rightarrow$ proposed test.\par

\section{Registry governance}

\begin{enumerate}
\item Assign an owning team and a versioned component or service for each adopted pattern.
\item Track the original pattern ID without claiming the original text endorses a contemporary framework.
\item Maintain a decision status: Adopt, Adapt, Replace or Retire. Document the reason and a measurable replacement behavior.
\item Include a negative test and an accessibility test for each implemented user journey.
\item Review the pattern after meaningful changes to its business context or technology assumptions.
\end{enumerate}
