\chapter{Lab environment and evidence standard}
Use a disposable unprivileged Linux environment. Never run experimental setuid helpers or intentional resource-exhaustion exercises against production machines. Where a lab would ordinarily require privileged operations, inspect configuration or use a tightly controlled temporary namespace rather than granting root to the entire training environment.

\section{Required evidence per lab}
\begin{itemize}
\item Brief contract and API classification (POSIX versus Linux-specific).
\item Hypothesis and expected output for both success and failure paths.
\item Build command, compiler version, sanitizer settings, and host kernel.
\item Test transcript including errno/pthread/EAI distinctions.
\item Leak/cleanup evidence, and one architectural improvement proposed after review.
\end{itemize}

\section{Lab 01: Interface and error semantics}
\textbf{Reading prerequisites:} textbook chapters 1--3\quad \textbf{Timebox:} 60--100 minutes.

\subsection{Build assignment}
Write a fault catalog for open, read, pthread\_create, and getaddrinfo.

\subsection{Fault-injection and negative cases}
Create absent and inaccessible fixture paths; verify errno differs from pthread and EAI return values.

\subsection{Acceptance tests and deliverables}
All four interfaces classified correctly; no ignored failure branches. Deliver source changes, automated checks, short trace commentary and a cleanup log.

\chapter{Assessment rubric}
\begin{longtable}{p{.24\linewidth}p{.11\linewidth}p{.51\linewidth}}\toprule
Category & Weight & Passing evidence\\\midrule\endhead
Behavior and tests & 30\% & Positive and adversarial checks reproduce expected outcomes\\
Error handling & 20\% & Partial progress, EINTR, EAGAIN and cleanup documented\\
Security and trust & 20\% & Input bounds, privilege and path assumptions made explicit\\
Concurrency / lifecycle & 15\% & No leaks, zombie processes, deadlock or uncontrolled queues\\
Portability & 10\% & Linux-only decisions and fallbacks recorded\\
Clarity & 5\% & Reproducible commands and concise engineering notes\\
\bottomrule\end{longtable}\section{Minimum pass rules}
Target at least 80 percent overall and no critical safety defect in the capstone. A single confirmed uncontrolled shell execution, unauthorized file access, indefinite worker leak or unrestricted resource growth constitutes an automatic remediation requirement before sign-off.

\textbf{Foundational source:} Michael Kerrisk, \emph{The Linux Programming Interface: A Linux and UNIX System Programming Handbook}, No Starch Press, 2010, ISBN 978-1-59327-220-3. The textbook's chapter titles and start pages organize the study guide; explanations, tasks, and code in this suite are independently authored educational material, not reproductions of the original text or its example programs.

\textbf{Current reference baseline:} The Open Group / IEEE, \emph{POSIX.1-2024, Issue 8}, \url{https://pubs.opengroup.org/onlinepubs/9799919799/}; Linux man-pages project, \url{https://man7.org/linux/man-pages/}; Linux kernel documentation, \url{https://docs.kernel.org/}. For Linux-only extensions consult the relevant per-interface manual pages and kernel documentation for the target kernel, architecture and libc; availability can differ materially.

\textbf{Scope:} This is an engineering study and implementation companion. It does not claim to restate a normative standard or guarantee a specific Linux kernel's behavior. System calls, libc wrappers and higher-level library functions are explicitly distinguished where material.
