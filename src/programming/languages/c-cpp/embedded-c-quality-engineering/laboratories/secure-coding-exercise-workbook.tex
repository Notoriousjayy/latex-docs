\section{Threat model}
Treat UART, BLE, network and file input as untrusted. Attackers may control lengths, payload bytes, packet ordering and timing. Security objectives are memory safety, bounded CPU time, recoverable errors, and no unintended state mutation.
\section{Original vulnerability exercises}
\begin{enumerate}
\item CWE-120/CWE-787 style boundary error: show that a payload length cannot exceed output capacity before any copy.
\item CWE-190 style arithmetic fault: demonstrate overflow detection before adding header and payload lengths.
\item CWE-457 style uninitialized read: ensure output is unchanged on rejected input and internal temporary storage is initialized.
\item CWE-362 style shared-state race: specify target-appropriate synchronization and test interleavings.
\item CWE-835 style unbounded loop: define max iterations, recovery and watchdog integration constraints.
\item CWE-676 style dangerous interface: review raw string and memory routines for size provenance and substitute checked APIs.
\end{enumerate}

\section{Verification requirements}
\begin{itemize}
\item Create a minimal negative test for each exercised defect class.
\item Use static analysis findings as hypotheses, not automatic proof.
\item Test malformed input, zero length, maximum length and unexpected transitions.
\item Distinguish native-host sanitizer results from target behavior.
\end{itemize}

\section{Severity and remediation decisions}
Record reachable input, exploit/hazard impact, probability, mitigation, owner and test evidence. Do not include genuine credentials or vulnerable production payloads.
