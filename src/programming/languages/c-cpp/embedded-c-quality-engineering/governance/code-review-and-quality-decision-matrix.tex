\section{Inspection sequence}
\begin{enumerate}
\item Read change intent and safety constraints.
\item Walk untrusted data entry points and ranges.
\item Examine numeric conversion, pointer lifetime and undefined behavior.
\item Check module and state ownership, concurrency and device-specific timing.
\item Inspect clean build, negative tests and SAST triage.
\item Review exceptions, source references and the release recommendation.
\end{enumerate}

\section{Severity rubric}
\begin{itemize}
\item Critical: credible catastrophic safety outcome or exploitable memory corruption with reachable inputs.
\item High: serious integrity/availability defect with credible trigger.
\item Medium: restricted scenario or defense-in-depth gap.
\item Low: style or documentation concern with low direct impact.
\end{itemize}

\section{Disposition codes}
OPEN: confirmed not remediated; FIXED: re-tested remediation; FALSE-POSITIVE: supported rationale; ACCEPTED: time-bounded authorized deviation; NOT-ASSESSED: missing evidence.
