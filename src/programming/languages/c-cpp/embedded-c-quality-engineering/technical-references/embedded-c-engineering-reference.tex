\section{Scope and control hierarchy}
\begin{enumerate}
\item Product-specific safety, security and legal obligations.
\item Target architecture, system hazards and runtime requirements.
\item Licensed MISRA guidance if applicable, with formal scope and deviations.
\item Project-adopted BARR-C:2018 style and defect-prevention rules.
\item Testing, automated checks, review and release governance.
\end{enumerate}

\section{Baseline toolchain}
\begin{itemize}
\item Record compiler/linker and target versions, ABI, endianness and optimization.
\item Prefer -std=c99, -Wall, -Wextra, -Wpedantic, -Wconversion and -Wsign-conversion where available.
\item Use host sanitizers only with supported toolchains; do not infer MCU-specific safety.
\item Review target interrupt timing, hardware access and synchronization separately.
\end{itemize}

\section{Original project control IDs}
EC-Q01 build provenance, EC-Q02 checked lengths, EC-Q03 controlled conversion, EC-Q04 interface encapsulation, EC-Q05 explicit bounded flow, EC-Q06 concurrency safety, EC-Q07 analyzer triage, EC-Q08 release evidence.
\section{Evidence chain}
\begin{verbatim}
Hazard -> Project control -> Source revision
       -> Test / Analyzer / Manual review
       -> Finding disposition -> Release decision
\end{verbatim}
\section{Interpretation boundary}
Clean compilers, formatters and analyzers are evidence of their own checks only and do not certify a device.
