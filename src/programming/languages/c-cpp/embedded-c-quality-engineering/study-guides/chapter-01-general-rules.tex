\section{Learning outcomes}
\begin{itemize}
\item Explain and verify c99 language mode, target abi and compiler diagnostics.
\item Explain and verify visible control-flow grouping and cast invariants.
\item Explain and verify internal linkage, const and volatile.
\end{itemize}

\section{Engineering concepts}
\subsection{C99 language mode, target ABI and compiler diagnostics}
Record implementation-defined assumptions before evaluating portability. Reproducibility requires compiler version, ABI, optimization and target information.

\subsection{Visible control-flow grouping and cast invariants}
Code structure should make decisions visible. Narrowing casts are claims about value ranges that must be proven by tests or invariants.

\subsection{Internal linkage, const and volatile}
Internal linkage limits coupling; volatile does not establish atomicity or thread synchronization.

\section{Practice laboratory}
Build a 12-bit ADC scale helper with a checked input range and separate register adapter.

Provide C99 source, two negative tests, two positive tests, toolchain data and a reviewer record.
\section{Failure investigation}
An interrupt and foreground task read a volatile multi-byte counter without synchronization. Reconstruct the failure, locate the broken invariant, design a reproducing test and document a mitigation.
\section{Assessment questions}
\begin{enumerate}
\item Which assumptions are compiler- or target-specific?
\item Which defects can an analyzer detect, and which require manual or HIL review?
\item What objective evidence is sufficient for an independent reviewer?
\end{enumerate}
