\section{Source locator}
BARR-C:2018, Chapter 4: Module Rules. This guide borrows the chapter topic only; explanations, questions and exercises are original.
\section{Learning outcomes}
\begin{itemize}
\item Explain and verify module cohesion.
\item Explain and verify headers, interfaces and linkage.
\item Explain and verify portable test doubles.
\end{itemize}

\section{Engineering concepts}
\subsection{Module cohesion}
Assign one coherent responsibility to a translation unit and minimize externally visible state.

\subsection{Headers, interfaces and linkage}
Each public header should be self-contained, with explicit include boundaries and required prototypes.

\subsection{Portable test doubles}
Protocol logic can be compiled on a host when hardware register access is behind a narrow adapter.

\section{Practice laboratory}
Separate framing logic from a UART transport and write a host-only test.

Provide C99 source, two negative tests, two positive tests, toolchain data and a reviewer record.
\section{Failure investigation}
A public mutable buffer couples drivers and permits out-of-band writes. Reconstruct the failure, locate the broken invariant, design a reproducing test and document a mitigation.
\section{Assessment questions}
\begin{enumerate}
\item Which assumptions are compiler- or target-specific?
\item Which defects can an analyzer detect, and which require manual or HIL review?
\item What objective evidence is sufficient for an independent reviewer?
\end{enumerate}

\section{Completion gate}
\begin{itemize}
\item Test evidence links to the source revision.
\item No unresolved critical defect or unapproved deviation.
\item At least one residual limitation is explicitly documented.
\end{itemize}
