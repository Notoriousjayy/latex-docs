\section{Source locator}
BARR-C:2018, Chapter 3: White Space Rules. This guide borrows the chapter topic only; explanations, questions and exercises are original.
\section{Learning outcomes}
\begin{itemize}
\item Explain and verify consistent formatting.
\item Explain and verify source hygiene.
\item Explain and verify separation of cosmetic and functional changes.
\end{itemize}

\section{Engineering concepts}
\subsection{Consistent formatting}
Use one versioned formatter configuration; never equate formatting success with program correctness.

\subsection{Source hygiene}
Audit tab characters, excessive lines and line endings; avoid modifying literal string semantics.

\subsection{Separation of cosmetic and functional changes}
Keep code reformatting separate from logic changes to preserve meaningful review diffs.

\section{Practice laboratory}
Implement a format-diff check and a separate C source text hygiene check.

Provide C99 source, two negative tests, two positive tests, toolchain data and a reviewer record.
\section{Failure investigation}
A large style-only patch conceals a one-character bounds fix. Reconstruct the failure, locate the broken invariant, design a reproducing test and document a mitigation.
\section{Assessment questions}
\begin{enumerate}
\item Which assumptions are compiler- or target-specific?
\item Which defects can an analyzer detect, and which require manual or HIL review?
\item What objective evidence is sufficient for an independent reviewer?
\end{enumerate}

\section{Completion gate}
\begin{itemize}
\item Test evidence links to the source revision.
\item No unresolved critical defect or unapproved deviation.
\item At least one residual limitation is explicitly documented.
\end{itemize}
