\section{Source locator}
BARR-C:2018, Chapter 2: Comment Rules. This guide borrows the chapter topic only; explanations, questions and exercises are original.
\section{Learning outcomes}
\begin{itemize}
\item Explain and verify intent and preconditions.
\item Explain and verify design references and api contracts.
\item Explain and verify documentation drift and dead code.
\end{itemize}

\section{Engineering concepts}
\subsection{Intent and preconditions}
Useful comments explain units, ownership, constraints and why a non-obvious design choice exists.

\subsection{Design references and API contracts}
Link hardware errata to versioned external references; describe pointer lifetime and error signaling at public interfaces.

\subsection{Documentation drift and dead code}
Outdated prose is a maintenance defect. Treat assumptions as candidates for assertions or explicit tests.

\section{Practice laboratory}
Document a bounded ring buffer with an overflow policy, error codes and producer/consumer ownership.

Provide C99 source, two negative tests, two positive tests, toolchain data and a reviewer record.
\section{Failure investigation}
Documentation claims unlimited input length while the implementation truncates a length counter. Reconstruct the failure, locate the broken invariant, design a reproducing test and document a mitigation.
\section{Assessment questions}
\begin{enumerate}
\item Which assumptions are compiler- or target-specific?
\item Which defects can an analyzer detect, and which require manual or HIL review?
\item What objective evidence is sufficient for an independent reviewer?
\end{enumerate}

\section{Completion gate}
\begin{itemize}
\item Test evidence links to the source revision.
\item No unresolved critical defect or unapproved deviation.
\item At least one residual limitation is explicitly documented.
\end{itemize}
