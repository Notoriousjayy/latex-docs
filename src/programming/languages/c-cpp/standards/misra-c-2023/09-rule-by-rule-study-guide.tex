\section{How to use this guide}
This guide provides a unique review focus for every directive and rule in the uploaded revision, plus a suggested verification approach. It does not reprint MISRA normative headlines, amplification or exceptions. Use the licensed source (PDF page reference below) to check the exact requirement before classifying any case. The questions are learning prompts, \emph{not} a replacement for a rule checker.
\section{Coverage strategy}
For each entry, learners should: (1) read the corresponding licensed rule/directive; (2) explain the prohibited or preferred behavior in original words; (3) design one negative case and one positive case; (4) specify the evidence needed to determine conformance; and (5) decide if a formal deviation could ever be permissible. Some inherently system-level checks cannot be established by isolated examples.

\section{Mastery and self-assessment}
For each entry, record four states: \emph{not studied}, \emph{explained}, \emph{demonstrated in code}, and \emph{verified in project evidence}. A memorized one-sentence summary is not evidence of mastery. For Mandatory rules, verify that the learner can distinguish impossible deviations from permissible exception cases explicitly present in the original text.
\section{Study order}
A productive order is language environment $\rightarrow$ lexical/build controls $\rightarrow$ essential types $\rightarrow$ pointers and side effects $\rightarrow$ control flow $\rightarrow$ libraries/concurrency $\rightarrow$ compliance process. Follow the separate curriculum for planned lab progression.
