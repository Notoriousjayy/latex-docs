\section{Learning outcomes and prerequisites}
Audience: experienced C developers, firmware engineers, verification engineers, and AppSec reviewers. Entry prerequisites are C compilation, function prototypes, integer and pointer semantics, ordinary testing, Git and basic CI. Learners should also recognize undefined behavior and be able to use a debugger. The program intentionally separates \emph{understanding C semantics} from \emph{applying MISRA process controls}.
\section{Dependency graph}
\begin{center}\fbox{C semantics $\rightarrow$ type model $\rightarrow$ pointer/flow analysis $\rightarrow$ verification $\rightarrow$ compliance evidence}\end{center}
Training units are cumulative; a later module's labs assume mastery of prior checkpoints.
\section{Twelve-week technical curriculum}
\subsection{Week 1: Project scope and predictable C}
\textbf{Instruction.} Select C edition, inspect 2023 guideline architecture, mandatory/required/advisory; compare compiler modes.

\textbf{Laboratory.} Scope manifest and baseline project.

\textbf{Exit evidence.} Scope and edition quiz (80\%); compile demo.

\subsection{Week 2: Lexical rules, identifiers and build hygiene}
\textbf{Instruction.} Tokens, macros, external names, unused entities, portable headers; Rule families 1--5 and 20.

\textbf{Laboratory.} Code review of symbol collisions and header guards.

\textbf{Exit evidence.} Identify 10 inserted source violations.

\subsection{Week 3: Types and integer arithmetic}
\textbf{Instruction.} Widths, promotions, essential type categories, literals and enum semantics; families 6,7,10.

\textbf{Laboratory.} Repair integer sensor conversions.

\textbf{Exit evidence.} Explain 6 conversion hazards and boundary cases.

\subsection{Week 4: Declarations, linkage and initialization}
\textbf{Instruction.} Translation units, declarations, scope, static linkage, automatic and atomic state; families 8,9.

\textbf{Laboratory.} Build two-module state management interface.

\textbf{Exit evidence.} Cross-TU declaration consistency check.

\subsection{Week 5: Expressions and side effects}
\textbf{Instruction.} Arithmetic boundaries, shifts, sequencing, evaluation order; families 12,13.

\textbf{Laboratory.} Create negative and corrected expression corpus.

\textbf{Exit evidence.} Static audit with explanation of false positives.

\subsection{Week 6: Control flow and functions}
\textbf{Instruction.} Loops, Boolean conditions, switch and error results; families 14--17.

\textbf{Laboratory.} Harden dispatcher and error propagation.

\textbf{Exit evidence.} Boundary, default and failure path test suite.

\subsection{Week 7: Pointer provenance and storage}
\textbf{Instruction.} Conversions, lifetime, arrays, overlap and type punning; families 11,18,19.

\textbf{Laboratory.} Bounds-safe packet validator with explicit extent.

\textbf{Exit evidence.} Review pointer paths and lifetime arguments.

\subsection{Week 8: Libraries, resources and concurrency}
\textbf{Instruction.} Prohibited library usage, resource ownership, C11 atomics and threads; families 21--23, Dir 5.

\textbf{Laboratory.} Compare resource and concurrency designs.

\textbf{Exit evidence.} Lifecycle state diagrams and concurrency hazard review.

\subsection{Week 9: Static analysis and tool validation}
\textbf{Instruction.} GEP coverage mapping, tool selection, checker tests, undecidable/system scope.

\textbf{Laboratory.} Configure reproducible scans and negative checker tests.

\textbf{Exit evidence.} Submit analyzer coverage matrix and limitations.

\subsection{Week 10: Project compliance and deviations}
\textbf{Instruction.} MISRA Compliance:2020, GEP, GRP, deviation permits/records, GCS.

\textbf{Laboratory.} Document a justified Required-rule deviation.

\textbf{Exit evidence.} Independent approval simulation.

\subsection{Week 11: GitHub Actions and reporting}
\textbf{Instruction.} Build matrices, artifact integrity, SARIF, branch protection and risk-based gates.

\textbf{Laboratory.} Integrate adapter with workflow, produce SARIF.

\textbf{Exit evidence.} Show fail-closed invalid run and maintained diagnostics.

\subsection{Week 12: Capstone assurance review}
\textbf{Instruction.} Complete evidence package, traceability, supplier limitations and final review.

\textbf{Laboratory.} Review embedded controller capstone and release dossier.

\textbf{Exit evidence.} Oral defense and final artifact checklist.


\section{Practical assessment scheme}
\begin{tabularx}{\linewidth}{@{}p{.31\linewidth}p{.14\linewidth}X@{}}\toprule
Competency & Weight & Minimum evidence\\\midrule
C semantics and rule reasoning & 25\% & Explain subtle integer, alias, lifetime and evaluation-order behavior.\\
Code transformation and tests & 25\% & Repair code while preserving requirements and demonstrating boundary tests.\\
Analyzer coverage and triage & 20\% & Reproduce a finding, explain limitations and choose a defensible disposition.\\
Compliance and deviation record & 20\% & Complete GEP/GCS sample entries and a risk-reviewed deviation.\\
Release and communication & 10\% & Deliver traceable artifacts and present residual risks.\\\bottomrule\end{tabularx}
\begin{keybox}\textbf{Training completion standard (course policy, not MISRA):} at least 80\% on semantic quizzes, no unresolved Mandatory violations in the capstone, all new Required findings resolved or correctly approved, and an independently reviewed compliance evidence packet.\end{keybox}
\section{Instructors' evaluation prompts}
Ask learners: (1) Can a rule be decidable but a tool miss violations? (2) What proves a pointer remains in one array? (3) Why may an Advisory guideline need a record? (4) Why is an analyzer result not a compliance claim? (5) How do compiler dialect changes alter applicability? (6) When do suppliers affect a whole-program review?
\section{Capstone specification}
Develop a bounded sensor message validator and state controller. It shall reject malformed message lengths, avoid heap use, expose explicit status returns, use function-local or controlled module state, document hardware behavior assumptions, and include unit tests and CI results. Deliver a 10-item guideline review sample with metadata, a checker coverage map, zero untriaged diagnostics and a release decision.
