\addcontentsline{toc}{chapter}{Sources and interpretation key}
\textbf{Primary source:} ISO/IEC 9899:2024(en), \emph{Information technology --- Programming languages --- C}, fifth edition (2024). Clause and annex identifiers refer to the supplied licensed standard. This handbook contains original explanations, designs and examples; it does not reproduce the standard. The licensed standard remains the authoritative source for exact wording and conformance decisions.\par
\textbf{Secondary engineering sources:} \url{https://gcc.gnu.org/onlinedocs/gcc/Standards.html}; \url{https://clang.llvm.org/c_status.html}; \url{https://cmake.org/cmake/help/latest/prop_tgt/C_STANDARD.html}. Compiler support and diagnostics are release-specific: verify the installed compiler, target and library before relying on a feature.\par
\begin{keybox}\textbf{Interpretation categories.} \textbf{[STANDARD]} summarizes a requirement, constraint, semantic rule or defined facility and cites the applicable clause. \textbf{[OPTIONAL]} describes conditional or implementation-dependent support. \textbf{[GUIDANCE]} records an engineering recommendation, not an ISO mandate. \textbf{[TEST]} is an original check or exercise; a passing test is evidence but is not proof of full conformity.\end{keybox}

\chapter{Migration contract}
A migration is complete only when build conformance mode, interfaces, tests, dependency versions, portability contracts and deployed runtime behavior are validated. Merely adding \texttt{-std=c23} is not sufficient. \refcl{Annex M.2}. This guide uses Annex M as an informative change index and the operative clauses as the authority for behavior.
\begin{keybox}\textbf{Required project outputs [GUIDANCE]:} inventory; baseline compiler matrix; dependency compatibility report; code-change decisions; automated regression suite; security regression suite; ABI comparison; waiver register; release gates; rollback plan.\end{keybox}

\chapter{Feature-by-feature engineering decisions}
\subsection{New spellings and keywords}
\standard\ Identify identifiers/macros that collide with bool, true, false, static\_assert, thread\_local and other newly reserved spellings. \refcl{6.4.2, 6.7.2; M.2}.\par\guidance\ Search entire source and dependencies; rename conflicting macros before mode switch.

\subsection{Empty parameter lists}
\standard\ C23 treats an empty parameter list as no parameters. \refcl{6.7.7, 6.9.1; M.2}.\par\guidance\ Replace legacy ambiguous declarations with explicit (void); test API compatibility.

\subsection{Identifier-list function definitions}
\standard\ Old-style definitions removed. \refcl{6.9.1; M.2}.\par\guidance\ Modernize prototypes and all call sites.

\subsection{Zero-size realloc}
\standard\ Requesting a zero-sized realloc is undefined behavior in C23. \refcl{7.24.4; M.2}.\par\guidance\ Handle size == 0 before calling realloc; define ownership outcome.

\subsection{Signed integer representations}
\standard\ Old sign representations removed; C23 narrows representation freedom. \refcl{6.2.6; M.2}.\par\guidance\ Remove sign-magnitude/ones-complement compatibility branches only after target review.

\subsection{Binary integer constants}
\standard\ 0b digits and digit separators are standard facilities. \refcl{6.4.5; M.2}.\par\guidance\ Retain fallback numeric spellings for older compilers.

\subsection{Compile-time assertions}
\standard\ static\_assert may omit a message. \refcl{6.7.12; M.2}.\par\guidance\ Use actionable messages in shared headers when maintaining pre-C23 builds.

\subsection{Type deduction}
\standard\ auto, typeof and typeof\_unqual provide inference. \refcl{6.7.10; M.2}.\par\guidance\ Prefer explicit types at ABI boundaries; feature-probe.

\subsection{constexpr object declarations}
\standard\ constexpr supports designated compile-time object definitions. \refcl{6.7.2, 6.6; M.2}.\par\guidance\ Probe semantics and distinguish C23 from C++ constexpr.

\subsection{Attributes}
\standard\ Attributes such as nodiscard, deprecated, maybe\_unused, fallthrough, noreturn, reproducible and unsequenced are specified, with optional implementation support. \refcl{6.7.13; M.1--M.2}.\par\guidance\ Guard with \_\_has\_c\_attribute; verify effect and location.

\subsection{Null pointer spelling}
\standard\ nullptr and nullptr\_t added. \refcl{6.5, 7.21.3; M.2}.\par\guidance\ Do not rely on spelling in shared C17 code or C++ interoperability without testing.

\subsection{Bit-precise integers}
\standard\ \_BitInt(N) and unsigned \_BitInt(N). \refcl{6.7.3; M.2}.\par\guidance\ Check width support, layout and conversion behavior on every target.

\subsection{Fixed underlying enum types}
\standard\ A colon may specify an enum underlying type. \refcl{6.7.3; M.2}.\par\guidance\ Treat layouts as ABI-sensitive; verify against consumers.

\subsection{Empty initialization}
\standard\ Empty braces can initialize objects. \refcl{6.7.11; M.2}.\par\guidance\ Test in mixed-standard codebases; use documented initialization policy.

\subsection{Unicode literal and identifier changes}
\standard\ Encoding semantics and Unicode identifier rules change. \refcl{6.2.9, 6.4.3, 6.4.6; M.2}.\par\guidance\ Run encoding/normalization tests and review source processing.

\subsection{New preprocessor tests}
\standard\ \_\_has\_include, \#elifdef and \#elifndef. \refcl{6.10.2; M.2}.\par\guidance\ Gate platform-specific includes by both availability and API capability.

\subsection{Binary embedding}
\standard\ \#embed permits resource inclusion. \refcl{6.10.4; M.2}.\par\guidance\ Maintain alternative generated-asset path; test artifacts and sizes.

\subsection{Variadic macro expansion}
\standard\ \_\_VA\_OPT\_\_ support. \refcl{6.10.5; M.2}.\par\guidance\ Replace nonportable comma tricks; test zero and multiple arguments.

\subsection{Diagnostics directive}
\standard\ \#warning added. \refcl{6.10.7; M.2}.\par\guidance\ Use to signal intentional platform fallback, not as a release policy.

\subsection{New bit utilities}
\standard\ <stdbit.h> bit and byte operations. \refcl{7.18; M.2}.\par\guidance\ Check header existence and required facilities with compile probes.

\subsection{Checked integer operations}
\standard\ <stdckdint.h> provides checked arithmetic macros. \refcl{7.20; M.2}.\par\guidance\ Prefer checked API where available; preserve proven fallback.

\subsection{Explicit erasure}
\standard\ memset\_explicit added. \refcl{7.26; M.2}.\par\guidance\ Use for secret erasure only with a threat model and tested availability.

\subsection{New allocation utilities}
\standard\ free\_sized, free\_aligned\_sized and memalignment. \refcl{7.24.4; M.2}.\par\guidance\ Require exact size/alignment invariants and test libc support.

\subsection{String and POSIX alignment}
\standard\ Functions including strdup, strndup, memccpy, gmtime\_r and localtime\_r are integrated. \refcl{7.24, 7.26, 7.29; M.2}.\par\guidance\ Check headers, feature-test macros and versioned libc.

\subsection{Time facilities}
\standard\ timegm and time-base additions appear in C23. \refcl{7.29; M.2}.\par\guidance\ Test platform runtime, range handling and timezone policy.

\subsection{Other standard-library updates}
\standard\ Integer formatting, qualifier-preserving generic functions and UTF conversions revised. \refcl{7.23, 7.26, 7.30; M.2}.\par\guidance\ Audit format strings, generic selection and ABI assumptions.

\subsection{Language removals/obsolescence}
\standard\ Removed and obsolescent features have different status. \refcl{6.11, 7.33; M.2}.\par\guidance\ Separate hard errors from policy deprecations in migration log.

\chapter{Worked migration patches}
\section{Legacy function declarations}
\begin{lstlisting}
/* Legacy C: declaration conveys incomplete argument information. */
int open_connection();
/* Portable explicit replacement. */
int open_connection(void);
\end{lstlisting}
\guidance\ Search declarations in external headers and generated code; do not modify only function definitions.
\section{Zero-sized reallocations}
\begin{lstlisting}
#include <stdlib.h>
#include <stdbool.h>
/* On success, output owns allocated bytes; on failure prior buffer remains. */
bool resize_buffer(void **p, size_t new_size) {
    if (new_size == 0) { free(*p); *p = NULL; return true; }
    void *tmp = realloc(*p, new_size);
    if (tmp == NULL) return false;
    *p = tmp;
    return true;
}
\end{lstlisting}
\standard\ Treating a zero-sized request as a special case avoids the C23 zero-size rule. \refcl{7.24.4}.\guidance\ Define whether the API regards resizing to zero as freeing storage; there is no single required application policy.
\section{Header gating and checked addition}
\begin{lstlisting}
#include <limits.h>
#include <stdbool.h>
#if defined(__has_include)
# if __has_include(<stdckdint.h>)
#  include <stdckdint.h>
#  define PROJECT_HAVE_CKD 1
# endif
#endif
bool add_nonnegative(int a, int b, int *out) {
    if (a < 0 || b < 0) return false;
#if defined(PROJECT_HAVE_CKD)
    return !ckd_add(out, a, b);
#else
    if (a > INT_MAX - b) return false;
    *out = a + b;
    return true;
#endif
}
\end{lstlisting}
\optional\ A header probe alone is insufficient on some partial implementations; the CMake configure step should compile a semantic probe that actually invokes the requested facility.
\section{Avoiding an ABI surprise}
\begin{lstlisting}
/* Fix the external representation; do not serialize enum object bytes. */
#include <stdint.h>
enum state : unsigned char { READY = 1, BUSY = 2 };
uint8_t encode_state(enum state s) { return (uint8_t)s; }
\end{lstlisting}
\guidance\ C23 supports fixed enum underlying types, but serialized protocol compatibility should be described independently of compiler internal representation.
\chapter{Toolchain strategy}
\section{Release-aware feature detection}
GCC documents \texttt{-std=c23} and \texttt{-std=gnu23}; Clang documents \texttt{-std=c23}. Standard-mode acceptance is not a guarantee of a complete C23 library. Verify compiler release, compiler runtime and each target. \url{https://gcc.gnu.org/onlinedocs/gcc/Standards.html}; \url{https://clang.llvm.org/c_status.html}.
\section{CMake configuration}
\begin{lstlisting}[language=]
cmake_minimum_required(VERSION 3.21)
project(c23_probe C)
add_executable(c23_probe main.c)
set_target_properties(c23_probe PROPERTIES
    C_STANDARD 23 C_STANDARD_REQUIRED YES C_EXTENSIONS NO)
\end{lstlisting}
\guidance\ \texttt{C\_STANDARD\_REQUIRED} avoids silent decay to older dialect modes when CMake can determine a standard flag. It does not validate all facilities. \url{https://cmake.org/cmake/help/latest/prop_tgt/C_STANDARD.html}.
\section{Staged rollout}
\begin{enumerate}
\item \textbf{Stage 0, evidence:} snapshot C17 build, exported symbols, diagnostics and tests.
\item \textbf{Stage 1, hygiene:} remove identifier conflicts, old-style definitions, unsafe \texttt{realloc(p,0)} calls, implicit ABI assumptions.
\item \textbf{Stage 2, dual-mode:} compile C17 and C23 in parallel; record intentional differences.
\item \textbf{Stage 3, opt-in features:} introduce type inference, new headers, bit-precise types and attributes only behind demonstrated support.
\item \textbf{Stage 4, security:} run sanitizers, fuzz tests, static analysis, negative tests and external-library integration.
\item \textbf{Stage 5, rollout:} ship target-scoped binaries, watch regressions and preserve the older branch as a rollback option.
\end{enumerate}
\chapter{Migration review checklist}
\begin{itemize}
\item Have all function declarations and K\&R definitions been audited? \refcl{6.7.7, 6.9.1}.
\item Have zero-length allocations, lifetime bugs and signed overflow been investigated? \refcl{6.5, 7.24.4}.
\item Does every C23-only API have a build-time check and fallback or minimum toolchain version? \refcl{6.10.2, 7}.
\item Are compiler-specific behavior, platform encoding, filesystem and locale assumptions documented? \refcl{Annex J}.
\item Were changes traced from Annex M to the normative clause and a regression test? \refcl{Annex M}.
\end{itemize}
